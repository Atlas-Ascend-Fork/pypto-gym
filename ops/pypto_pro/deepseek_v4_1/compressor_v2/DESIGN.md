# CompressorV2 设计说明

## 计算阶段划分

FP16 和 BF16 共用计算流程，矩阵乘以 FP32 累加，按输入类型转换输出。入口先检查输入并分配输出，再选择通用路径或片上路径；总 token 数为 `0` 时直接返回输出。

| 路径与阶段 | 主要工作 | 中间结果 |
| :--- | :--- | :--- |
| 通用路径，`Stage=0` | Cube 计算 KV 和分数投影；Vector 读取首组需要的调用前历史状态。 | FP32 投影工作区和历史快照。 |
| 通用路径，`Stage=1` | 合并 H 分区的部分和，拼接历史前缀，按组执行 softmax 加权，写出输出并更新缓存。 | 与输入同类型的输出及更新后的 FP32 缓存。 |
| 片上路径，`Stage=2` | Cube 将两路投影直接交给两个 Vector 子核，完成压缩与缓存写回。 | 投影无需独立的全局内存工作区。 |

两路投影分别为 `K = X @ wkv.T`、`G = X @ wgate.T`。每个长度为 `r = cmp_ratio` 的完整组，先求各通道的最大分数，再计算 `exp(G - max(G))`、加权和与归一化。计算加权分子前将 KV 乘以 `1 / r`，归一化后乘回 `r`。这些向量运算均使用 FP32，最后按最近值、中点取偶数转换为输入类型。

通用路径中的历史快照在缓存写回前完成，首组只从快照读取调用前的历史，避免长序列环形写回覆盖仍需使用的槽位。仅完整压缩组产生有效输出；缓存写回独立保留本次输入最后 `min(L_b, block_size)` 个 token 的投影。

## 核间切分策略

通用投影按“投影种类、H 分区、token 行块、输出通道块”分配工作项，Cube 核以核号为起点、核数为步长领取任务。若共享激活后工作项仍足以覆盖 Cube 核，则同一激活块先后用于 KV 和分数投影。

工作项较少且 H 足够大时，可沿 H 切为 `2` 至 `4` 个分区，每个分区的边界按装入面板宽度对齐。各分区分别写出 FP32 部分和，Vector 按分区顺序相加后再用于输出或缓存，不使用原子加法。分区选择依据工作轮数与搬运量估算，只有估算代价低于原路径的 `80%` 才启用。

历史快照按序列和 `64` 个缓存通道切分。分组压缩按压缩组与 `64` 个输出通道切分；固定长度布局且 `S <= 128` 时，先按序列和通道分配。缓存写回按投影种类和通道分配；工作项及核数满足条件时，使用压缩任务之外的 Vector 核。

片上路径按“token 行块、输出通道块”切分。每个 Cube 的 KV、分数累加结果经 `DualModeSplitM` 分成互不重叠的两个行半块，分别交给两个 Vector 子核。每个子核对其行半块独立完成压缩与缓存写回。

## 核内切分策略、基本块选择与核内 Buffer 划分

通用投影的列块宽度在总 token 数 `T <= 128` 时取 `64`，否则取 `128`；行块容量从 `16、32、64、96、128` 中按 Cube 核数及列块数选择。H 分区路径固定使用 `256 × 64` 输出块，并共享两路投影的激活。每次装入的 H 宽度为 `256` 或 `512`，矩阵乘的 H 方向步长为 `64` 或 `128`。

片上路径仅用于单序列且未显式提供 `seqused` 和 `start_pos` 的输入，从 `(行数, 列数) = (256, 128)、(128, 128)、(64, 64)、(32, 64)` 中选择。`T` 必须是行块大小的整数倍，每个行半块至少包含一个完整压缩组。行数为 `256` 时，缓存块大小还须为 `128` 的整数倍；其他候选可处理未对齐的缓存写回。

下表列出源码显式申请的片上 Buffer。`M`、`N` 为行、列块容量，`F` 表示是否共享两路投影的激活，取 `0` 或 `1`；`P` 为装入的 H 面板宽度，`Q` 为矩阵乘的 H 方向步长，`Parts` 为 H 分区数。Mat、Left、Right、Acc、Vec 分别对应 L1、L0A、L0B、L0C 和向量缓冲区 UB，各存储空间分别计量。Vec 容量按单个 Vector 核列出；两槽表示两块相同大小的 Buffer 交替使用，`1 KiB = 1024` 字节。

| 阶段 | Buffer 形状、类型及槽数 | 显式容量 |
| :--- | :--- | :--- |
| `Stage=0` 投影 | Mat：激活 `M × P`，权重共 `1 + F` 份 `N × P`，FP16 或 BF16，两槽 | `4P[M + (1 + F)N]` 字节 |
| `Stage=0` 投影 | Left：`M × Q`；Right：`Q × N`；均与输入同类型、两槽 | 依次为 `4MQ`、`4QN` 字节 |
| `Stage=0` 投影 | Acc：`M × N`，FP32，两槽 | `8MN` 字节 |
| `Stage=0` 历史快照 | Vec：`r × 64`，FP32，单槽 | `256r` 字节 |
| `Stage=1` 压缩与缓存更新 | Vec：KV、分数、临时块各 `128 × 64`，FP32；另有 `max(1, Parts - 1)` 个同形状部分和槽；输出 `(128 / r) × 64`，与输入同类型 | `98304 + 32768 × max(1, Parts - 1) + 16384 / r` 字节 |
| `Stage=2` 投影 | Mat：激活 `M × 256`、两路权重各 `N × 256`，与输入同类型，两槽 | `1024(M + 2N)` 字节 |
| `Stage=2` 投影 | Left：`M × Q`；Right：`Q × N`；均与输入同类型、两槽；Acc：`M × N`，FP32，两槽 | 依次为 `4MQ`、`4QN`、`8MN` 字节 |
| `Stage=2` 压缩，每个 Vector 子核 | Vec：两路投影各 `(M / 2) × N`，FP32；输出 `(M / (2r)) × N`，与输入同类型 | `4MN + MN / r` 字节 |
| `Stage=2` 非直接缓存写回 | Vec：额外两块 `(M / 2) × N`，FP32，单槽 | 在上一行基础上增加 `4MN` 字节 |

`Stage=0` 的 `P` 在共享激活或 `M=256` 时取 `256`，其他情况取 `512`；`Q` 在 `M=256` 时取 `64`，其他情况取 `128`。`Stage=2` 同样按 `M` 选择 `Q`。`M=256` 的片上路径满足缓存对齐条件，使用直接写回，无需额外缓存临时块。

通用路径另分配 FP32 投影 `[Parts, 2, T, D]` 和历史 `[B, r, 2D]` 工作区，分别占 `8 × Parts × T × D`、`8BrD` 字节；投影第二轴依次为 KV 和分数。片上路径无需这两块独立工作区。输出单独分配，元素类型与输入相同。以上容量由源码的形状、槽数和地址计算，不代表编译后的资源占用或硬件利用率。

## 接口选择

| 接口 | 用途 |
| :--- | :--- |
| `@pl.jit(auto_mutex=True, tiling_key=CompressorKey)` | 为三个独立阶段入口按数据类型、压缩率和分块参数编译计算变体，自动管理带显式 mutex ID 的 Buffer 槽位。 |
| `pl.make_tuple` | 将同一阶段的张量和 Buffer 组织为带字段名称的组合，供辅助函数使用。 |
| `pl.make_tile_group`、`pl.set_validshape` | 申请 Buffer 并限制末块的有效范围。 |
| `pl.matmul`、`pl.matmul_acc` | 初始化矩阵乘结果，并沿 H 累加 FP32 投影。 |
| `pl.reinterpret`、`pl.move` | 组织权重面板布局，将输入和权重搬入矩阵乘缓冲区。 |
| `pl.vector_function` 与 `vf` 接口 | 完成部分和合并、历史拼接、最大值、指数、归一化和输出转换。 |
| `pl.load`、`pl.store` | 读写投影与历史工作区，写出有效输出并更新缓存。 |
| `pl.move(..., acc_to_vec_mode=DualModeSplitM)` | 将 Cube 累加结果按行交给两个 Vector 子核。 |
| `pl.system.set_cross_core`、`pl.system.wait_cross_core` | 在 Cube 与 Vector 间通知投影就绪和共享 Buffer 释放。 |

投影与历史快照、分组压缩与缓存写回、片上融合分别使用独立的 JIT 入口，各入口只接收该阶段所需的设备指针。主机侧将张量形状、缓存步长和可选元数据是否存在组织为不可变配置，并据此复用相应入口实例。

分块选择只读取形状、数据类型、可选参数是否存在及平台核数。BSH 的固定序列长度来自形状配置；TH 的序列边界、调用方提供的 `seqused` 和 `start_pos` 数值，以及缓存物理块号，由 kernel 读取设备侧元数据张量。

## 流水设计

通用路径先完成 `Stage=0` 的全部投影和历史快照，再启动 `Stage=1`。矩阵乘沿 H 使用两槽输入与权重 Buffer；共享激活时，KV 和分数投影复用同一份 L0A 片段。各 H 分区的结果写入独立工作区，压缩和缓存写回前再合并。

片上路径中，Cube 计算当前工作项的两路投影后，等待上一工作项的 Vector 释放共享区，再将累加结果按行半块搬入 UB。就绪事件使用 `event_id=0`，由 FIX 流水通知 Vector 的 V 流水；Vector 接收后完成加权输出及缓存写回。

缓存块大小是行半块大小的整数倍时，直接从投影 Buffer 写回缓存，由 MTE3 在搬出完成后发送 `event_id=1` 释放事件。否则先复制到独立缓存临时块，再按环形边界分段写回，由 V 流水在共享区最后一次读取完成后发送释放事件。下一工作项只有收到释放事件后才能覆盖共享区；循环结束时，Cube 等待最后一次释放完成收尾。
