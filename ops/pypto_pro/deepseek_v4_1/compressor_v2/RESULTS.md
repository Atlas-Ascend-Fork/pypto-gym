# CompressorV2 结果说明

## 用例

`tests/test_compressor_v2.py` 采用 AscendC CompressorV2 单用例入口默认启用的 20 组参数，将不同起点展开为 25 个用例。输入激活与两路权重均为 BF16，特征宽度 `H=4096`；历史缓存为 FP32。输入激活、权重和历史缓存均按默认参数的 `[-10, 10]` 范围均匀采样，激活和权重随后转换为 BF16。

表中 `B × S` 表示序列数与每条序列的 token 数。BSH 输入形状为 `[B, S, 4096]`，TH 输入形状为 `[B × S, 4096]`；`D` 为输出特征宽度，`r` 为压缩率。各序列使用表中相同的起点，`seqused=None`，使用完整序列长度；TH 的 `cu_seqlens` 为 `[0, S, 2S, ..., B × S]`。

缓存形状为 `[B, block_size, 2D]`，后两轴连续。缓存配置中的 `pad` 表示块步长额外增加的 FP32 元素数，`offset` 表示缓存起始位置相对分配区的 FP32 元素偏移，块步长为 `block_size × 2D + pad`。`Contiguous0` 使用连续缓存；其余用例保留带填充的块步长配置。

## 精度标准

参考计算位于 `tests/assets/compressor_v2_golden_cpu.py`：读取已经量化为 BF16 的输入和权重，在 CPU 上以 FP64 计算投影、历史拼接和压缩；有效压缩输出转为 BF16，更新缓存转为 FP32。

数值判据采用 [AscendC CompressorV2 默认单用例测试](https://gitcode.com/cann/ops-transformer/blob/master/experimental/attention/compressor_v2/tests/pytest/compressor_golden.py) 的 `check_result`。按该测试的调用方式，有效输出、KV 缓存更新区和分数缓存更新区都先转为 FP32 比较，并使用输出类型 BF16 选择容差：

| 检查项 | 通过条件 |
| :--- | :--- |
| 元素匹配率 | 至少 99.5% 的元素满足 `abs(actual-expected) <= 0.0001 + 0.0078125*abs(expected)` |
| 不匹配元素的归一化误差 | 先令 `b=max(abs(actual),abs(expected),2^-14/0.005)+1e-9`，再要求 `abs(actual-expected)/(b+1e-9)` 小于 10 |

第二项沿用官方函数检查前一千万个不匹配元素的规则；本组各比较区域的总元素数均小于一千万。NaN、Inf 的数值处理也保留该函数原有规则，不增加其他误差门槛。

数值检查覆盖全部有效输出及两个缓存更新区域。未更新缓存要求逐位不变，缓存视图以外的分配保护区保持原值；输出还检查形状、类型和连续布局。25 例测试全部通过，0 失败、0 错误、0 跳过；有有效输出的用例还验证整片有效输出损坏后比较器会拒绝。性能采集的两种实现各 575 次调用（每例 3 次预热和 20 次计量）均通过同一数值判据及缓存保护检查。

## 性能结果

> **采集机器**：本节全部耗时、带宽与占用率数据均在本机 `Ascend950PR_9589`（32 AI Core，32 Cube / 64 Vector，L2 128 MiB）上采集。

采集设备为 Ascend 950PR_9589（32 个 Cube 核、64 个 Vector 核），使用物理 0 号卡。软件为 PyPTO 0.3.0、PyTorch 2.8.0+cpu、torch_npu 2.8.0.post4；msprof 来自 CANN Toolkit 9.3.0 安装目录。采集时记录设备上的其他上下文，以下结果适用于该次共享卡测量条件。

双方使用相同输入与独立的初始缓存。采用 cann-bench 的预热算子，并在每次调用前执行 `CannBenchCacheClean`，读取 `[96,1024,1024]` FP16 缓冲区（192 MiB）后同步完成。双方交替先后顺序，每例各预热 3 次，再各采集 20 次，共 20 对计量样本。

采集遵循 [msprof AI 任务采集说明](https://www.hiascend.com/doc_center/source/en/CANNCommunityEdition/910/devaids/Profiling/atlasprofiling_16_0011.html)，启用任务耗时和 PipeUtilization。每次完整调用的全部设备任务均计入，使用 `op_summary` 的 `Task Duration(us)` 求和，再对 20 个样本取中位数。[该字段](https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/910beta2/devaids/Profiling/atlasprofiling_16_0067.html)包含调度、加速器执行和结束响应，不含任务间等待；主机耗时、输入准备、清 L2 和精度检查不计入。PyPTO-Pro 每次包含 2 个设备任务，AscendC 每次包含 1 个。

AscendC 基线使用官方源码提交 `637598412a4a295d02b84b1b5bb2b8d9f1154bcf` 编译的 CompressorV2，算子目录与本轮核查的 master 提交 `62884679af1b2fb6ceef3b8e9950bc89a030b254` 完全一致。

### 理论评估对比

按一次乘加计 2 次浮点运算，两路投影的数学计算量为 `4THD`，其中 `T` 为本次输入 token 总数、`H` 为输入特征宽度、`D` 为投影输出宽度。实现沿 H 切分时，各分区的 FP32 部分和再合并，不改变该矩阵乘计算量；softmax、缓存更新和数据搬运另计。

下表按用例的实际形状计算两路投影的数学运算量，1 GFLOP 表示十亿次浮点运算。

| 用例 | T | H | D | 两路投影计算量（GFLOP） |
| :--- | ---: | ---: | ---: | ---: |
| `Prefill0` | 8192 | 4096 | 512 | 68.719 |
| `Prefill1` | 8192 | 4096 | 128 | 17.180 |
| `Prefill2` | 8192 | 4096 | 512 | 68.719 |

性能表按完整调用的全部设备任务计量，包含投影、压缩和缓存更新；此处的数学运算量只统计两路矩阵乘。
