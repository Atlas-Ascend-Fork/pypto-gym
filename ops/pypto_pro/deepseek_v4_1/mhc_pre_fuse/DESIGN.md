# mhc_pre_fuse 设计说明

> 算子本体：`op_kernel/mhc_pre_fuse.py`；CPU 参考实现与精度比较器：`tests/assets/`。
> 运行平台：Ascend 950PR（`Ascend950PR_9589`，`NpuArch=3510`），cube 32 核 / vector 64 核。
> 下文容量数字取自 CANN 平台配置 `Ascend950PR_9589.ini`：每个向量核的片上缓存（UB）
> 253952 字节（248 KiB，`[VectorCoreSpec] ub_size`），L2 134217728 字节（128 MiB，
> `[SoCInfo] l2_size`）。

## 计算阶段划分

算子的全部工作由一个 kernel 完成，kernel 在 64 个向量核上运行。每个核一次领取
`tb` 个词元（默认 8 个）组成的一个「词元块」，先算出这块的混合系数，再拿这些系数去
加权求和 4 路残差。混合系数很小（每个词元 24 个 FP32），算完就留在片上，直到这一块的
`layer_input` 全部写完才被下一块复用，中途不需要写回全局内存；残差数据量大，按隐藏维
分块流过片上缓存。

融合的价值在于减少全局内存往返：分开实现时，`layer_input` 这一步要重读一遍残差，中间
结果也要往返全局内存；融合后残差只读一次，混合系数算完直接在本块内使用。

```text
[一次性] 载入 mhc_scale(3) / mhc_base(24)
   ↓
[每个词元块]
  ┌ 阶段 A  mixes = gemm_out_mul × rms
  │ 阶段 B  pre  = sigmoid(mixes[0:4]  × scale0 + base[0:4])  + pre_eps
  │         post = sigmoid(mixes[4:8]  × scale1 + base[4:8])  × mult
  │         comb =          mixes[8:24] × scale2 + base[8:24]
  │ 阶段 C  Sinkhorn：4×4 矩阵行列交替归一化，共 repeat 轮
  │ 阶段 D  写回 post_mix / comb_mix
  └ 阶段 E  layer_input[t,:] = Σ_m fp32(residual[t,m,:]) × pre[t,m]
```

其中 A~D 只涉及每个词元 24 个数值，数据量极小，中间结果只在寄存器和片上暂存之间
周转；E 是唯一的大数据量步骤，读 `4 × H` 个 BF16、写 `H` 个 BF16。

数值上有两处细节属于算子的数值定义，实现必须照此计算（本目录的 CPU 参考实现同样如此）：

1. Sinkhorn 第一轮的行归一化**不加**稳定项，之后每一轮都加；
2. 求 `exp` 之前，先把每一行减去它自己的最大值（行内 4 个数的最大值）。
   这个减数是「逐行常量」，在紧接着的行归一化里会被约掉，因此不改变数学结果；
   它的作用是把 `exp` 的自变量压到 0 附近，避免 `comb` 数值偏大时上溢。

## 核间切分策略

- 起核数取平台信息中的向量核数量（Ascend 950PR 为 64）。
- 词元先按 `tb` 切成 `n_t = T / tb` 个块，核 `c` 依次处理第 `c`、`c + 64`、`c + 128`…
  个块（网格步长）。块数少于一轮时，未领到块的核直接结束。
- `tb` 默认取 8。当 `T` 不能被 8 整除时依次退化到 4、2、1，保证任何 `T` 都不丢词元
  （`tb` 取 8 的依据见「核内切分策略」）。

## 核内切分策略：基本块选择、核内 Buffer 划分

**基本块选择**

| 维度 | 取值 | 选择依据 |
| :--- | :--- | :--- |
| 词元块 `tb` | 8（`T` 不整除时退化为 4 / 2 / 1） | 一个寄存器行装一个词元（64 个 lane，有效 24 路），`tb` 是这一块里放几个词元。取 8 使 `T = 512` 这类小规模也能切出 64 个块，占满 64 个向量核 |
| 隐藏维块 `h_blk` | 从 512 / 256 / 192 / 128 / 64 中取**满足下面两条约束的最宽值** | 块越宽，每个词元分到的搬运指令越少（次数正好是 `H / h_blk`），单次搬运的数据量也越大 |
| 流水深度 `PIPE_DEPTH` | 5 | 残差流展开后的循环体一次推进 5 个分块，输入块与输出块各 5 份在 UB 里轮转 |

`h_blk` 的候选值按从宽到窄依次试，同时还要满足另外两条：`H / h_blk >= 5`（隐藏维
至少能切成 5 块，撑满 5 级流水），以及片上 Buffer 装得下 `PIPE_DEPTH` 份输入块加
`PIPE_DEPTH` 份输出块。`64` 是最窄的候选，在 `H` 为 64 的倍数且 `H / 64 >= 5` 时它一定
满足这两条，所以这正是算子能接受的形状范围。都不满足时 wrapper 直接报错。

**核内 Buffer 划分**

固定驻留部分（地址从 `0x0000` 起，单位字节）：

| 缓冲 | 形状 / 类型 | 地址 | 用途 |
| :--- | :--- | :--- | :--- |
| `mix` | `[tb, 64]` FP32 | `0x0000` | 24 路 mixes（有效列 24） |
| `pre_t` | `[tb, 64]` FP32 | `0x1000` | pre 系数（有效列 4） |
| `post_t` | `[tb, 64]` FP32 | `0x2000` | post 系数（有效列 4） |
| `p0`~`p3` | `[tb, 64]` FP32 | `0x3000`…`0x6000` | 组合矩阵的 4 行（有效列 4） |
| `sqv` | `[1, 64]` FP32 | `0x7000` | 本块的平方和 |
| `sct` | `[1, 64]` FP32 | `0x7100` | 三个缩放系数 |
| `bst` | `[1, 64]` FP32 | `0x7200` | 24 个偏置 |
| `srt` | `[4·tb, 64]` FP32 | `0x8000` | Sinkhorn 暂存，每词元 4 行 |

表中地址是各缓冲的起始地址。`[tb, 64]` 的 FP32 tile 在 `tb = 8` 时占 `0x800` 字节，
而地址按 `0x1000` 递进，所以条目之间留有间隔；`srt` 是最大的一个，占到 `0x9FFF`。
`0xA000`～`0xBFFF` 是留空区，把驻留部分和下面的流式部分隔开。

流式部分从 `0xC000` 起，输入和输出各 5 份轮转：

| 缓冲 | 形状 / 类型 | 份数 | 用途 |
| :--- | :--- | :--- | :--- |
| `xg` | `[4·tb, h_blk]` BF16 | 5 | 残差输入块，行 `4t + m` 是词元 `t` 的第 `m` 路 |
| `o_b` | `[tb, h_blk]` BF16 | 5 | `layer_input` 输出块 |

`h_blk = 512`、`tb = 8` 是最宽的组合，性能用例均为该组合：`xg` 5 份是
`5 × 8 × 4 × 512 × 2 = 163840` 字节，`o_b` 5 份是 `5 × 8 × 512 × 2 = 40960` 字节，
加上起始偏移 `49152`，一共 `253952` 字节，正好达到一个向量核的片上缓存末尾
（`0x3E000`）。因此 `h_blk` 的上界是 512。

**寄存器布局**

一个 FP32 向量寄存器有 64 个 lane。因此 `[tb, 64]` 的 tile 中**一行正好是一个词元**，
lane 下标就是混合系数的编号：

- `mix` 的 lane 0…23 是 24 路 mixes；
- `pre` / `post` 只用 lane 0…3；`p0`~`p3` 每行只有 lane 0…3 是有效数据。

向量指令按整行 64 个 lane 读写，`p0`~`p3` 中 lane 4…63 不承载有效数据，也不参与输出
计算：Sinkhorn 里唯一跨 lane 的动作是求每行的最大值，它只看 lane 0…3；其余运算都是逐
lane 的，lane 0…3 只由 lane 0…3 决定。写回 `comb_mix` 时又受有效列限制只写 4 列，因此
高位 lane 的内容不会进入输出。

## 接口选择

| 环节 | 用法 | 理由 |
| :--- | :--- | :--- |
| 全局内存 ↔ 片上 | `pl.load` / `pl.store` + `set_validshape` | 把有效形状限制在真实列数以内，避免越界读写 |
| 片上 ↔ 寄存器 | `vf.load_align` / `vf.store_align` | 按寄存器行寻址，用掩码限定参与运算的 lane |
| 标量广播 | `LoadDist.BRC_B32` | 把一个标量广播到整行，供逐元素运算使用 |
| BF16 展开 / 打包 | `UNPK_B16` / `PACK_B32` | 一边搬一边完成 BF16↔FP32，省一趟转换 |
| 取指定 lane | `vf.gather` | 从 `mix` 里按 lane 取出 pre / post / comb 各自的 4 路 |
| 行内取最大值 | `vf.reduce_max` + `vf.gather` | 把一行 4 个数的最大值归约到 lane 0，再用全零下标广播回整行 |
| 带稳定化的指数 | `vf.exp_sub` | 一条指令完成「减最大值 + 取 exp」 |
| 乘加 | `vf.mul_add_dst` | 真融合乘加，比拆成乘 + 加少一条指令 |

所有 tile 通过 `pl.make_tile_group` 创建并交给 `auto_mutex` 自动管理同步，流式的
输入/输出块各用 5 组互斥信号量做轮转。

`T` 与 `H` 决定 tile 形状、Buffer 地址与主循环的展开方式，因此它们作为编译期常量
参与实例化；实例按 `(T, H, 核数, 迭代轮数, 各稳定项与乘数)` 缓存，同一组合只编译
一次。其余标量（稳定项、乘数）也以常数形式编进 kernel；像 `1 / (m × H)` 这种由形状
算出来的系数，在编译期就算好，运行时不再重复计算。

## 流水设计

**先发起残差流**

每个词元块的开头先一次性下发 5 个残差分块的搬运指令，然后再开始算 A~D。这样系数计算
在向量管道上执行的同时，搬运单元已经在把残差往片上搬，两边的耗时就重叠在一起。

**主循环的 5 级流水**

阶段 E 展开成如下节奏，每一步处理一个隐藏维分块：

```text
每一步:
    算第 i 块 → 写第 i 块 → 预取第 i + 5 块
```

即同一时刻可以有三类动作在执行：某一块的向量计算、另一块的写回、再往前 5 个位置的
预取。写回走搬出单元（MTE3），预取走搬入单元（MTE2）。展开后的循环体一次连续走 5 步
（i 到 i+4），刚好用满 5 份输入块和 5 份输出块，保证写回尚未完成时不会被下一块覆盖。

尾部的余数分块（凑不满一整轮的部分）在循环外用条件判断单独处理，避免越界预取。

**同步**

kernel 里有三处 `bar_all()`。它是**核内**的流水线排水（等价于 `barrier(Pipe.ALL)`）：
等本核的标量、向量、MTE1 / MTE2 / MTE3 各条流水线都走完，不涉及跨核。

| 位置 | 频次 |
| :--- | :--- |
| 一次性载入 `mhc_scale` / `mhc_base` 之后 | 每个核一次 |
| 每个词元块算完 Sinkhorn、写回 `post_mix` / `comb_mix` 之前 | 每个词元块一次 |
| 词元块循环之外，kernel 末尾 | 整个 kernel 一次 |

前两处都落在「搬运」与「向量」两条管道的交界上，排水用于固定先后顺序：第一处等本核的
`mhc_scale` / `mhc_base` 载入完成（搬运写 → 向量读），第二处等本块的 Sinkhorn 算完
（向量写 → 搬运读，随后才写回 `post_mix` / `comb_mix`）。第三处放在循环外，整个 kernel
只排一次。除此之外，kernel 里只有 `vf.mem_bar` 的局部排序，没有别的整核排水；主循环里
的依赖由 tile 的互斥信号量（`auto_mutex`）描述。
