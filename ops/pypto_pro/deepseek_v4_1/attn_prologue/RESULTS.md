## 用例

设备场景共 **32 个**（12 decode + 20 prefill），覆盖固定生产几何
`(H,R,N,D,Dr)=(5120,1280,64,512,64)` 下唯一动态轴 `T=batch*seq` 的全部生产取值（21 个唯一 T，
`1…262144`）。kernel 为单二进制、只按动态 T 特化，同一 T 的不同 `(batch,seq)` 组合设备执行相同
（仅 `cache_index`/`kv_cache` 页布局不同）。用例 id 与 `--list` 输出一致：

| 阶段 | batch | seq | T | 工作分配模板 |
| :--- | :--- | :--- | :--- | :--- |
| decode（12） | 1,4,8,12,16,32 | 1,6 | 1,4,6,8,12,16,24,32,48,72,96,192 | 单元分布（`n_tiles<32`）；T≤128 另启阶段 1 的归约维切分（split-K，2 分区） |
| prefill（20） | 1,4,8,16,32 | 1024,2048,4096,8192 | 1024…262144 | T<4096 单元分布；T≥4096 逐 tile |

另有 CPU 侧判据自检 12 项（`test_fp8_value_criterion` 6 项 + `test_full_output_validator` 6 项），
随 pytest 收集、不需要 NPU。

## 精度标准

**独立参考实现**：`tests/assets/attn_prologue_golden_cpu.py` 在 CPU 上独立实现算子契约的全部数学
（MXFP8 解码用 `ldexp` 保证 `e=-127` 位精确、`frexp` 取 `floor(log2)`、零量化组「借 1.0 参与运算、
整组清零、scale 字节 0」、E4M3 最近偶数舍入、KV `view(uint8)` 字节重解释、QB 消费量化后的 qr、
KV 先归一化和 RoPE 再量化），不读取设备输出、不与 kernel 共享中间量。

**比较器**：`tests/assets/attn_prologue_precision.py`，判据 `fp64_value_domain`，阈值冻结、不可由
测试输入覆盖。逐项检查：

1. **q**（BF16，按 FP32 比较）：全部有限，且 `|got-ref| > 0.02 + 0.02*|ref|` 的元素比例
   （q_bad_rate）≤ **1e-3**；
2. **qr / descale_qr / KV 命中 slot**（字节精确类）：payload 字节差异先做 FP32 归因
   （`boundary_rel=1e-5` 冻结），scale 字节单独移动的行经 `groups_needing_review` 显式提名；命中
   行**整行**用独立 FP64 影子重算，按值域裁决为 value_identical / adjacent_bracket（临界舍入
   差异）/ own_scale_consistent 三类之一，其余记硬失配——通过要求 **`qr_hard == 0` 且
   `kv_hard == 0`**；
3. **未命中 cache slot**：与随机初值**逐字节相同**（0 容差）。

## 性能结果

**环境与口径**：DAV_3510（32 Cube / 64 AIV），CANN 9.3.0、PyTorch 2.12.0+cpu、torch_npu、
Python 3.12，设备 1。指标为 **msprof 导出的纯 NPU `task duration(us)`**（排除 host 启动、编译、
输入准备与 L2 冲刷本身）；每个正式样本前用 **512 MiB FP16 `ArgMax` 全量读冲刷 L2** 并同步；
**3 轮预热**（排除编译与首跑）加 **7 轮正式**采样，取**中位数**；msprof 会话按每批不超过 8 个
case 分批，规避单会话 launch 数上限导致的记录缺失。

### 理论评估对比（MFU / Bound / 利用率）

这里的 **Bound 指性能瓶颈**（哪一段资源决定了 kernel 耗时）。**结论**：全场景占比最大的 pipe
均为 **AIC MTE2（GM/L2→L1 载入）**，达 0.80–0.88——decode 由「每次调用必搬的 52.8 MB 权重流」
决定，prefill 由「逐 tile 模板下每 tile 重读权重的聚合流加 X/q 字节」决定；MAC 占比 0.42–0.85、
随 T 上升，重叠在载入之下，T≥4096 时与 MTE2 双高共同约束。AIV 侧全部 pipe ≤0.20，Vector 不是
任何场景的瓶颈。

**MFU 说明**：decode 的 MFU（相对 Cube MAC 峰值）不足 1%，且是**设计使然**——算术强度被算子形态
钉死（每 token 102.2 MFLOP 计算对应整份 52.8 MB 权重搬运，T 小时权重流与 token 数无关），Cube
大部分时间在等数据。因此 MFU 不是本算子合适的优度指标；有意义的是**权重流有效带宽**（decode
≈1.33 TB/s，约为聚合流参照的 89%）**与 MTE2 占用**（0.80–0.88，达到工程约定阈值 0.8）。

#### 分析过程

按「先排除、再定位、最后用字节模型收口」的顺序：

**第 1 步：排除 Vector 与 FIXPIPE。** 五个代表 T 的 pipe 快照中 `aiv_vec ≤ 0.183`、
`aiv_mte3 ≤ 0.194`、`aiv_mte2 ≤ 0.086`、`aic_fixpipe ≤ 0.096`，均远小于最大项；阶段 2 的
RMSNorm/量化与阶段 4 的 RoPE/BF16 都在寄存器内完成并与载入天然重叠。Vector 与窄化写出不是
瓶颈。

**第 2 步：定位最大项为 AIC MTE2。** `aic_mte2_ratio` 在 T=1/72/192/1024/4096 分别为
0.863/0.862/0.830/0.804/0.882，是全部 pipe 中唯一始终不低于 0.8 的项；`aicore_time ≈ Task
Duration`（无核级空闲）。kernel 为 GM/L2→L1 载入带宽受限。

**第 3 步：decode 字节模型收口。** 每次调用必须读入的权重加 scale：Wqb 41.94 MB + Wqa 6.55 MB +
Wkv 2.62 MB + 三个 descale 1.67 MB ≈ **52.8 MB**（与 T 无关；X/qr/中间缓冲/q 在 decode 均只有
数 MB）。T=1 实测 39.58 µs，有效权重流带宽 **≈1.33 TB/s**，为本平台 32 核聚合流参照（~1.5 TB/s，
相邻核读相邻 NZ 128 行带的满速形态）的 **≈89%**；剩余差距对应 launch 加双屏障地板（≈4 µs）与
阶段 1/2 的少量暴露。roofline：`t_est = 52.8 MB ÷ 1.5 TB/s ≈ 35.2 µs`，计入固定地板后
`t_meas/t_est ≈ 1.01`（不计地板 ≈1.12），在 1.25 判据内。

**第 4 步：prefill 字节模型收口。** 逐 tile 模板的设计取舍是 **qr 驻留、权重流式**：每 tile 把
`qr[128,1280]`（160 KB）驻留 L1 一次、跨 256 拍复用，代价是每 tile 重读整份权重（由 L2 吸收，
HBM 只读一次）。T=4096（32 tile / 32 核）：MTE2 搬运 ≈ 权重 52.8 MB×32 + X（组宽 2，每 tile
7 次载入）147 MB + qr 回读 ≈ **1.87 GB**，MTE2 busy = 0.882×582.44 µs ≈ 514 µs，聚合
**≈3.6 TB/s**（≈114 GB/s/核，达单核 MTE2 能力）；同时 `aic_mac_ratio=0.846`（419 GFLOP ÷
493 µs busy ≈ 850 TFLOP/s）。大 prefill 为 **MTE2 与 MAC 双约束**，q 输出写（268 MB）经
MTE3/FIX 重叠其下。

**第 5 步：确认无发射串行残留。** 载入调度已按「少而大」原则定型：K0=256（32 KB 突发）、权重
窗口深度 4、scale 缓冲深度 2 轮转、单元跨步的带局部性、屏障窗口预载/预取被首拍实际消费；
`aic_scalar_ratio ≤ 0.34`，不超过最大 pipe 的 0.42 倍，标量只承担地址与循环控制、不主导。
