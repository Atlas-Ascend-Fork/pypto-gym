# KvCompressEpilogV2 设计说明

## 计算阶段划分

每个输入行独立完成分组量化与缓存写回，分为四步：

1. 读取本行 slot，检查有效范围；无效 slot 不搬入输入，也不更新缓存。
2. 将该行 BF16 数据一次搬入片上 Buffer。
3. 按组计算 scale 和量化值，在同一输出 Buffer 中形成连续的数据、BF16 scale 和必要的二维行尾补零。
4. 将完整记录一次写回 slot 指定的缓存位置。

量化计算全部在向量核完成。FP8 保留 FP32 scale 和 FP32 除法；FP4 保留 BF16 指数位规则、BF16 乘积及 E2M1 转换顺序。数据格式和物理写址遵循 [README](README.md) 的约定。

## 核间切分策略

默认使用 `min(T,40)` 个向量 worker。编号为 `b` 的 worker 按 `b, b+workers, b+2×workers, ...` 处理输入行。每行由一个 worker 完成，不按组拆分到多个核。

行之间没有归约或共享中间结果。合法 slot 唯一时，各 worker 写入互不重叠的缓存记录，不需要核间同步。slot 检查在输入搬运之前完成。

目标性能用例的 `T=4`，每个 worker 最多分配一行。二维默认 slot 中有 2 行有效，四维有 3 行有效；无效行跳过输入搬运、量化和写回。

## 核内切分策略、基本块选择与核内 Buffer 划分

每个 worker 以完整输入行为搬运单位，按量化组或 128 个 BF16 元素的块计算：

| 路径 | 核内计算方式 |
|---|---|
| FP8，group 32 | 每次处理一组 32 个元素，完成 FP32 最大绝对值归约、scale 计算、FP32 除法和 FP8 转换。 |
| FP4，group 32 | 逐组计算指数最大值和缩放结果，将 BF16 乘积暂存在输入 Buffer，再以最多 128 个 BF16 元素转换并打包。 |
| FP4，group 16，组数小于 16 | 使用 BF16 暂存与 128 元素转换方式。 |
| FP4，group 16，组数不少于 16 | 每块最多处理 128 个 BF16 元素，同时计算最多 8 组指数统计量，在寄存器中广播逆 scale，直接转换并写入数据。 |

128 元素块的 FP4 输出为 64 字节，在片上输出 Buffer 内的块起点保持 32 字节对齐。最后一块使用实际有效元素数。每组 scale 使用精确的 2 字节写入，起点由实际 `D` 决定。

设 `W` 为覆盖 `D` 的最小 2 的整数次幂，FP8 的 `W` 至少为 32，FP4 至少为 128。片上分配如下：

| Buffer | 大小 | 用途 |
|---|---|---|
| 输入 BF16 Buffer | `2W+256` 字节 | 保存一行输入及整寄存器读取余量；FP4 暂存路径还复用有效区域保存 BF16 乘积。 |
| 输出 UINT8 Buffer | FP8：`ceil32(W+2W/32)`；FP4：`ceil32(W/2+2W/g)` 字节 | 保存最终连续记录。 |
| 输出 BF16 view | 与输出 UINT8 Buffer 共享存储 | 在数据之后写入 BF16 scale，不单独分配 Buffer。 |

向量 load 按整寄存器读取片上数据。输入 Buffer 在 `2W` 字节之后预留 256 字节，容纳尾组的完整寄存器读取；输出 Buffer 从这块输入存储之后开始。全局内存（GM）搬入仍只读取实际 `D` 个 BF16 元素。组和块的掩码限制参与归约、缩放与转换的有效元素，预留空间不参与量化结果。

`ceil32(n)` 表示向上对齐到 32 字节。输入、输出各使用单份 Buffer，不产生额外的 GM 中间张量。`D=8192` 时，声明的两份 Buffer 总容量分别为 FP8 25344 字节、FP4 group 16 的 21760 字节、FP4 group 32 的 21248 字节。

tiling key 区分量化格式、组大小、scale 舍入、slot 整数类型、容量、按每行组数选择的 FP4 计算路径及缓存布局。`Layout4` 将二维与四维寻址在编译期分开；实际 `T`、`D`、slot 值、页大小和缓存步长仍为运行期输入。同一容量和算法类别可处理多种实际尺寸。

## 接口选择

| 接口 | 用途 |
|---|---|
| 公开包装函数 | 校验 dtype、shape、容量和属性，推导元数据并发起一次 JIT 调用。 |
| `pl.jit` | 将 slot 检查、量化和写回放在同一个 kernel 内。 |
| `pl.vector_function`、`vf.*` | 完成归约、位运算、缩放、转换与打包。 |
| `pl.load`、`pl.store` | 按实际有效长度搬入完整行、写回完整记录。 |
| `make_tile_group`、`auto_mutex` | 管理 Buffer 使用次序以及搬运与计算的依赖。 |
| `pl.reinterpret` | 为输出存储建立 BF16 view，以实际数据长度确定 scale 位置。 |

输入使用独立的 tile group；UINT8 输出与 BF16 scale view 继承同一个输出 group。两种 view 表示同一块存储，不作为独立 Buffer 管理。

## 流水设计

FP8 路径在处理前保存浮点转换控制位，并显式启用保留 Inf/NaN 的转换模式。全部行处理及搬运完成后，恢复原控制位，确保 FP8 转换遵循本算子规定的 Inf/NaN 规则。FP4 路径使用 BF16 到 E2M1 的转换，不执行这组控制位操作。

同一 worker 按行顺序复用 Buffer，形成“搬入一行 → 量化 → 写回一条记录”的处理链。各组数据与 scale 直接写入最终输出位置，避免逐组 GM 搬运和单独的 scale 拼接。

二维记录存在行尾补零时，先清零输出记录范围，再由量化阶段覆盖数据和 scale 区域。清零与量化使用同一输出 group 的两次向量函数调用，自动互斥依赖保证写入顺序。二维无补零及四维路径直接量化；四维只写 `bundle` 字节。

FP4 暂存路径先将 BF16 乘积写入输入 Buffer，再通过 `VST_VLD` 同步保证后续转换读到这些结果。group 为 16 且组数不少于 16 的路径在寄存器中完成广播和缩放，省去这次片上暂存读写。输出数据、BF16 scale 和二维补零共同组成一次写回的数据源。
