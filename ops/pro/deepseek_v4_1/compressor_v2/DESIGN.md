# CompressorV2 设计说明

## 计算阶段划分

FP16 和 BF16 共用计算流程。两路矩阵乘以 FP32 累加，分组加权和状态缓存使用 FP32，输出转换为输入类型。入口根据形状、压缩率、可选参数是否存在及平台核数选择执行路径；总 token 数为 `0` 时不启动计算 kernel。

| 路径与阶段 | 主要工作 | 中间结果 |
| :--- | :--- | :--- |
| 通用路径，`Stage=0` | Cube 计算 `K=X@wkv.T`、`G=X@wgate.T`；Vector 保存可能被首个完整组读取的历史前缀。 | FP32 投影和历史快照。 |
| 通用路径，`Stage=1` | 合并 H 分区部分和、拼接历史前缀，按组计算 softmax 加权，写出输出并原位更新缓存。 | 与输入同类型的输出及更新后的 FP32 缓存。 |
| 片上路径，`Stage=2` | Cube 将两路投影交给两个 Vector 子核，完成分组加权和缓存写回。 | 两路投影在片上交接。 |

每个完整组先求各通道最大分数，再计算指数权重、加权和与归一化。KV 在加权前乘以 `1/r`，归一化后乘回 `r`，其中 `r=cmp_ratio`。末尾不足一组的新投影仍参与缓存更新。

历史前缀从调用前缓存读取，避免后续环形写回覆盖首组所需状态。前缀为空时不读取历史；当前缀长度加全部输入 token 数仍不足 `r` 时，也不读取历史，因为该序列不可能产生完整组。其余情况保留快照路径。

ACLNN 使用构建系统为混合入口和纯 Vector 入口自动生成的两组两段式接口。调用侧按 host 计划选择 `Stage=0→1` 或单阶段 `Stage=2`，分配中间 Tensor，并分别查询各阶段工作区后提交执行。通用路径在同一 stream 上按序下发，保持投影、历史中间张量及缓存视图一致；stream 顺序保证先读取历史、完成投影，再压缩和更新缓存。各张量和工作区的生命周期覆盖相应设备任务。

## 核间切分策略

通用投影按“投影种类、H 分区、token 行块、输出通道块”分配工作项，Cube 核以核号为起点、启动核数为步长领取任务。工作项足够时共享激活，同一激活块先后用于 KV 和分数投影。启动核数取平台 Cube 核数与投影、历史快照所需核数上界的较小值，减少空闲核。

工作项较少且 H 足够大时，可沿 H 切为 `2` 至 `4` 个分区，各分区写出独立 FP32 部分和，Vector 按分区顺序相加。主机先比较工作轮数、块大小和 H 方向工作量，仅在分区估算代价低于原方案的 `4/5` 时采用。对于共享激活的 `128×128` 块，还比较不分区与二分区所需的面板处理次数，二分区至少减少 `1/8` 时才选用。估算只用于分块选择，不代替实测性能。

历史快照按序列和 `64` 个缓存通道切分。分组加权按压缩组与 `64` 个输出通道切分。BSH 且 `S<=128` 时，Vector 按序列和通道领取任务。多序列 TH（`B>1`）在省略 `seqused`、显式提供 `start_pos`，且 `T<=128`（`r=64` 时为 `T<=64`）时，也按序列和通道分配；该范围保证每条序列最多需要一个压缩组块。TH 的输出起点使用实际 `cu_seqlens` 和 `start_pos` 累加前序序列的有效组数，保留变长序列和空序列的语义。每个核只初始化一次前缀；处理当前序列后，将当前组数和到下一条任务之间跳过的序列组数加入累计值。已累计的序列不再重复计数，单核对序列元数据的遍历次数随 B 线性增长。这两类切分的启动核数不超过 `B×(D/64)`，且为 `D/64` 的整数倍。

其余 TH 输入按组和通道分配，依次处理各序列。选中单序列编译分支时直接处理第 `0` 条序列，省去动态 batch 循环。当主机根据形状和参数存在性确认 `B=1、T=1`、省略 `seqused` 且显式提供 `start_pos` 时，选择单 token 分支：输入起点固定为 `0`、新输入长度固定为 `1`，TH 无需再读取 `cu_seqlens`。起点值仍由设备张量读取，是否产生完整组由实际历史前缀决定。

缓存写回按投影种类和通道分配；分组任务之外有足够核数时，由其他 Vector 核承担写回。单 token 分支直接写入 `start_pos % block_size` 对应的槽位，不进入通用的分段环形写回循环。

BSH、`S=r` 且省略 `seqused` 时，完整组的 KV 和分数块可复用于缓存写回。设备端进一步检查起点对齐压缩组边界、且本组不跨缓存块边界；满足时直接保存已经合并的 FP32 块，避免重新读取投影。不满足时使用通用环形写回。

片上路径按 token 行块和输出通道块切分。每个 Cube 的两路累加结果按行分成互不重叠的两个半块，分别交给两个 Vector 子核。

## 核内切分策略、基本块选择与核内 Buffer 划分

通用投影的列块宽度在 `T<=128` 时取 `64`，否则取 `128`。设列块宽度为 `N`、Cube 核数为 `C`，先估算并行行块数 `max(1,C//(2×(D//N)))`，再从 `16、32、64、96、128` 中选择可容纳所需行数的首个值；超出候选容量时取 `128`。

H 分区默认使用 `256×64` 块。`T<=128` 时缩小到可容纳输入的上述行容量；`128<T<=256` 且改用 `128` 行后全部投影工作项仍可在一轮内完成时，使用 `128×64` 块。对于不分区的共享激活 `128×128` 块，当 `T` 为 `256` 的整数倍，且 `256×128` 方案的工作轮数乘 `2` 不大于原方案的工作轮数时，使用 `256×128` 块，以补偿矩阵子步从 `128` 缩为 `64` 带来的额外步数。

片上路径要求 `B=1`，且省略 `seqused` 和 `start_pos`。候选 `(行数,列数)` 为 `(256,128)、(128,128)、(64,64)、(32,64)`，要求 `T` 是行数的整数倍、行数至少为 `2r`；行数为 `256` 时，`block_size` 还须为 `128` 的整数倍。主机按工作轮数和块大小选择估算代价最小的候选，同代价时保留靠前候选。

下表的 `M`、`N` 为行、列容量，`P` 为每次装入的 H 面板宽度，`Q` 为矩阵乘沿 H 的子步，`Parts` 为 H 分区数。Mat、Left、Right、Acc、Vec 分别对应 L1、L0A、L0B、L0C 和 UB。槽数表示同形状 Buffer 的份数。

| 阶段 | Buffer 划分 |
| :--- | :--- |
| 通用投影 | Mat：激活 `M×P`、权重 `N×P`，均与输入同类型、两槽；共享激活时另设两槽分数权重。Left 为 `M×Q`，Right 为 `Q×N`，均为输入类型、两槽；Acc 为 `M×N`，FP32、两槽。 |
| 历史快照 | Vec：`r×64`，FP32、单槽。 |
| 通用向量处理 | KV、分数、临时块均为 `128×64`、FP32；部分和另占 `max(1,Parts-1)` 个同形状槽。输出容量为 `(128/r)×64`、输入类型、两槽。 |
| 通用向量处理的槽数 | `Parts<=3` 且未选中短输入分支时，KV、分数各两槽，临时块一槽；短输入分支或 `Parts=4` 时，KV、分数各一槽，临时块两槽。 |
| 单 token 分支 | KV、分数各 `r×64`、FP32、单槽；临时块为同形状、两槽，部分和为同形状的 `max(1,Parts-1)` 槽；输出为 `1×64`、输入类型、两槽。保留 `r` 行容量，用于容纳最多 `r-1` 个历史 token 和当前 token。 |
| 完整 BSH 组的紧凑分支 | `S=r`、省略 `seqused` 且 `r<=64` 时，除显式提供 `start_pos` 的单序列分支外，KV、分数和临时块缩为 `r×64`，均为 FP32、两槽；部分和为同形状的 `max(1,Parts-1)` 槽；输出为 `1×64`、输入类型、两槽。其余情况使用通用缓冲布局。 |
| 片上投影 | Mat：激活 `M×256`、两路权重各 `N×256`，输入类型、两槽。Left、Right、Acc 的形状和槽数同通用投影。 |
| 片上向量处理，每个子核 | 两路投影各 `(M/2)×N`、FP32、单槽；输出 `(M/(2r))×N`、输入类型、单槽。非直接缓存写回另设两块 `(M/2)×N` 的 FP32 Buffer。 |

缓冲策略中的短输入分支要求显式提供 `start_pos`、省略 `seqused`，且 `T<=128`（`r=64` 时为 `T<=64`）；`S=r` 的完整 BSH 组另行选择完整组分支。通用投影在共享激活或 `M=256` 时取 `P=256`，否则取 `P=512`。通常 `Q=128`；`M=256` 时取 `64`，H 分区且 `M<=64、N=64` 时取 `256`。片上路径取 `P=256`，`M=256` 时 `Q=64`，其余取 `128`。末块通过有效形状限制读写范围。

## 接口选择

| 接口 | 用途 |
| :--- | :--- |
| `@pl.jit`、TilingKey 与 `datatype` | 为混合入口和纯 Vector 入口编译合法分块分支，分别承载 `Stage=0/2` 和 `Stage=1`；选择 FP16 或 BF16。D、布局、可选参数存在性及选中的短输入、单序列路径作为编译分支的一部分。 |
| TilingData | 传入 token 数、H、D、序列数、固定序列长度、缓存块大小和步长、输出容量及可选参数标志，共 12 个运行参数。 |
| `pl.make_tensor`、`pl.make_tuple` | 根据设备指针和运行参数重建张量视图，组织阶段输入。 |
| `pl.make_tile_group`、`pl.set_validshape` | 划分片上 Buffer，限制末块有效范围。 |
| `pl.matmul`、`pl.matmul_acc` | 初始化并累加两路 FP32 投影。 |
| `pl.reinterpret`、`pl.move` | 组织权重布局和片上搬运，按行分配片上路径的两路累加结果。 |
| `pl.vector_function` 与 `vf` | 合并部分和、拼接历史，计算最大值、指数、归一化及输出转换。 |
| `pl.load`、`pl.store` | 读写输入、中间结果、有效输出及环形缓存。 |
| `pl.system.set_cross_core`、`pl.system.wait_cross_core` | 通知片上投影就绪和共享 Buffer 释放。 |

纯 Vector 入口的 `Rows=16` 表示一般分支，`Rows=1` 表示上述单 token 分支；后者的 KV、分数和临时缓冲行容量为 `r`，不是 `1`。该字段与混合入口中用于选择矩阵行容量的 `Rows` 分别编译和编码。

Python wrapper 与 C++ 主机逻辑使用相同的分块公式。调用侧与 host tiling 共用 `compressor_v2_plan.h`；host 使用生成的 TilingData 写入运行参数，按声明字段顺序调用生成的 key 宏，分别设置启动核数和系统工作区。未提供的元数据由占位指针补齐，其存在性另行记录；序列边界、实际使用长度、起点和物理块号均从设备张量读取。

JIT 与离线编译均显式设置 `enable_slice=False`。离线构建在本算子生成的编译入口中应用该设置；后端启用 Tile Fusion 并保留其合法性检查，该融合过程跳过归约操作。这些配置限定在本算子的 `op_host/CMakeLists.txt`，用于使离线编译采用明确的优化选项。

JIT 与 ACLNN 共用 25 个默认测试定义、输入生成、参考计算及精度检查文件，测试模式只决定调用入口。

## 流水设计

通用路径先完成 `Stage=0`，再启动 `Stage=1`。矩阵乘沿 H 交替使用两槽输入与权重 Buffer；共享激活时，两路投影复用 L0A 片段。H 分区部分和写入不同区域，使用前按分区顺序合并。向量处理交替使用配置的输入、临时和输出槽，缓冲区由对应流水的获取与释放操作管理；缓存复用路径直接保存当前完整组的两路 FP32 块。

片上路径中，Cube 完成两路投影后，等待上一工作项的 Vector 释放共享区，再按行半块搬入 UB。FIX 流水以 `event_id=0` 通知 Vector 的 V 流水，Vector 接收后完成加权输出及缓存写回。直接缓存写回由 MTE3 在搬出完成后发送 `event_id=1`；分段写回先复制到独立缓存临时块，由 V 流水在共享区最后一次读取完成后发送释放事件。下一工作项收到释放事件后才能覆盖共享区，Cube 在循环结束时等待最后一次释放。
