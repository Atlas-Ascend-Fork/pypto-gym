## 核心思想

优化手段只有四个方向。先判绑定资源（`B4`），再从对应方向下手——方向对了收益才存在。

**一、少算**：简化计算本身。消去冗余与重复运算；换用等价但更便宜的形式（如在线递推避免
两趟遍历）；把能在主机侧或编译期定下来的量搬出设备侧循环。→ `B1` `P4` `V4` `X4`

**二、少搬**：减少主存往返。输入只读一次，中间结果不落主存；靠更大且接近方形的分块、
片上驻留与跨核共享提高复用；累加器留在片上，不跨主存边界；**按每个 MAC 附带的操作数搬运量给分块定价**——窄分块会把同一份操作数重复搬入。→ `B5` `Q1` `Q2` `Q3` `T1` `V2` `V3`

**三、少循环**：减少循环次数与每次迭代的固定开销。加大单趟处理量；消除循环内的标量计算
与地址重算；循环次数少时把启动与排空计入代价。→ `T3` `P4` `P5`

**四、多重叠**：把工作铺到所有核与所有流水上。按工作量均衡分核；搬运与计算重叠；
Cube 与 Vector 错拍。→ `P2` `P3` `X1` `X2`

后面各章是这四个方向的具体判据：`B` 定字节预算与上限判定，`P`/`X` 管重叠与并行，
`T` 管切分与容量，`V`/`Q` 分别是两个执行域的手段，`M` 是测量方法。

## 1. 字节预算与 Roofline（`B`）

**主线：先定字节预算，再核算算力；先判绑定资源，再选优化手段。**

| 编号 | 原则 |
|---|---|
| `B1` | 编码前先写代价模型：`bytes_min`（每个输入从主存读一次、每个输出写一次）、`FLOPs`、`AI = FLOPs / bytes_min`，以及 `t_est = max(各流水的时间)`。 |
| `B2` | Roofline 判定对准**执行该运算的那条流水**（不同流水的拐点可差一两个数量级），结论写明绑定的是哪个资源。**「没有流水饱和」是合法结论**——绑定项是依赖链或同步，不要为凑标签硬选计算受限或带宽受限。 |
| `B3` | 上限取**实测可达值**，不取规格峰值；而且必须用流量已知的探针测，不能从做着计算的 kernel 反推。取不到就记 `unknown`（`M1`）。 |
| `B4` | **只优化绑定资源。** 对空闲资源的优化不计为收益。先由 profile 确认绑定资源，再选方向。 |
| `B5` | 主存流量最小化是明确的目标函数：量化流量放大比 `A = bytes_measured / bytes_min` 并逐项处置放大来源。中间结果不往返主存；**融合的判据是中间数据片上驻留，不是 kernel 数量**。 |
| `B6` | 目标可达性先推导：按验收口径（含 benchmark 的评分公式本身）算出上限；目标超出上限时上报差距与原因。 |

## 2. 流水与多核并行（`P`）

| 编号 | 原则 |
|---|---|
| `P1` | 稳态吞吐由最慢的流水决定；非关键路径上的优化不改善端到端时间。 |
| `P2` | 搬运与计算必须重叠。轮转 buffer 的默认深度是 2，仅当 profile 显示搬运在等待时才加深；深度是容量的乘数因子，加深后须复核 `T1`。 |
| `P3` | 多核均衡按**工作量**分配，不按分块数——掩码、变长序列下两者不等价。尾部效率 `η_tail = work / (⌈work / cores⌉ · cores)`。 |
| `P4` | 设备侧循环内不做整数除法、取模与 shape 再推导。切分在主机侧算好后经参数传入，地址按增量推进。 |
| `P5` | 循环次数较少时，启动与排空阶段的时间计入代价模型。 |

## 3. 切分与片上容量（`T`）

| 编号 | 原则 |
|---|---|
| `T1` | 容量**逐空间逐项**列出，每项乘以缓冲深度，求和不超限；tile 尺寸按硬件粒度取整后重新校验。 |
| `T2` | 切分自顶向下求解：分核 → 片上 tile → 指令粒度，每层约束下一层。 |
| `T3` | 纯 Vector 算子没有 `M`/`N`/`K` 轴语义，其切分参数是单趟处理的元素数，取值以单次搬运足以摊薄 DMA 启动开销为准。 |
| `T4` | 尾块逐维度选定策略（有效形状或掩码），不为尾块另起循环。 |
| `T5` | 调参限定在约束可行集内（容量、粒度、均衡度），不做无约束网格搜索；动态 shape 用分桶，不用分支。 |

## 4. Vector 执行域（`V`）

| 编号 | 原则 |
|---|---|
| `V1` | Vector 算子**不预设绑定资源**。同样的逐元素形态，可能受带宽限制，也可能受**发射速率**限制（超越函数、升位宽转换、在线递推）或受**跨 lane 搬运**限制——按 `B2`/`B4` 实测判定后再选方向。 |
| `V2` | 逐元素链融合为单趟：一次读入、片上完成计算、一次写出。 |
| `V3` | 访问步长默认为 1；非单位步长与跨 lane 访问（转置、广播）的代价计入模型。 |
| `V4` | 超越函数、升位宽转换、在线归一化递推的**发射代价**必须计入 Vector 时间。softmax 这类算子常常是 Vector 发射受限，而不是带宽受限。 |
| `V5` | 归约的累加次序显式指定；窄 dtype 的长轴归约用更宽的累加器。 |

## 5. Cube 执行域（`Q`）

| 编号 | 原则 |
|---|---|
| `Q1` | `M`/`N`/`K` 取分形粒度的整数倍，分形填充率是 Cube 效率的首要指标。Cube 吞吐按**本算子 tile 形状**的实测值建模，不要假设它随单条指令的运算量上升——真正随分块形状变化的往往是**每个 MAC 附带的操作数搬运量**（窄分块会把同一份操作数重复搬入），按它给分块定价。 |
| `Q2` | `K` 轴的部分和在累加期间全程驻留片上累加器，不跨主存边界。 |
| `Q3` | 输出 tile 在容量内取大且接近方形：主存流量随 `1/Mt + 1/Nt` 下降。 |
| `Q4` | 布局变换（含转置）优先放进搬运通路完成，其代价计入模型。 |

## 6. Cube–Vector 融合（`X`）

| 编号 | 原则 |
|---|---|
| `X1` | CV 混合 kernel 必须错拍：至少两个分块在途，Cube 与 Vector 并发。代码相邻不等于并发，逐分块「先算后处理」的串行实现要重写。 |
| `X2` | 通过 tile 形状配平两级流水的吞吐，使两侧单分块时间接近；失衡时调整较慢一侧的 tile 维度。 |
| `X3` | 同步粒度须同时给出上界与下界：过细则同步开销主导，过粗则流水气泡主导。写明每次同步交接的数据量。 |
| `X4` | 跨分块归约采用在线化递推以保持单趟；无法在线化时拆为独立 kernel，并以串行化对照实测确认收益。 |

## 7. 度量与证据（`M`）

与平台无关的度量方法。依赖具体平台或流程的度量规则不在本文件，编号空档由那一侧定义。

| 编号 | 原则 |
|---|---|
| `M1` | 未取证的项记 `unknown`，不要记成通过。`unknown` 是合规取值。 |
| `M2` | 先模型、后测量、再**解释差距**。模型与实测的明显偏离不得当作测量噪声吸收；首先怀疑绑定资源判错（`B4`）。 |
| `M3` | 测量协议：固定输入、启动参数与 warm-up；同一配置重复多次，报均值与离散度。**改动以聚合指标判定，单 case 只用于诊断机理**；单 case 异常先单独复测再采信。 |
| `M4` | 偏离某条原则时写明 `{编号, 理由, 实测代价}`。 |
| `M7` | 新测出的上限、定律或常数，要**回头套用到已判定为完成的实现上**——它们是在旧判据下验收的。 |
| `M8` | 多个独立结论若依赖同一个**未经实测**的量，其相互一致不构成验证。采信前先确认那个量有没有人实测过（`B3`）。 |
