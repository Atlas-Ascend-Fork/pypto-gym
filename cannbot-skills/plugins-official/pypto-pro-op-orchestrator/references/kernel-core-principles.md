## 核心思想

优化可从以下四个方向考虑。先判绑定资源（`B4`），再选择可验证的改进。

**一、少算**：简化计算本身。消去冗余与重复运算；换用等价但更便宜的形式（如在线递推避免
两趟遍历）；把能在主机侧或编译期定下来的量搬出设备侧循环。→ `B1` `P4` `V4` `X4`

**二、少搬**：减少输入重复读取与中间结果的主存往返；比较分块形状、片上驻留与合法共享
带来的复用，计入容量与并行度的代价；**按每个 MAC 附带的操作数搬运量给分块定价**——窄分块会把同一份操作数重复搬入。→ `B5` `Q1` `Q2` `Q3` `T1` `V2` `V3`

**三、少循环**：减少循环次数与每次迭代的固定开销。加大单趟处理量；消除循环内的标量计算
与地址重算；循环次数少时把启动与排空计入代价。→ `T3` `P4` `P5`

**四、多重叠**：按工作量均衡分核；存在独立工作且容量允许时，比较搬运与计算重叠、
Cube 与 Vector 错拍的收益。→ `P2` `P3` `X1` `X2`

后面各章是这四个方向的具体判据：`B` 定字节预算与上限判定，`P`/`X` 管重叠与并行，
`T` 管切分与容量，`V`/`Q` 分别是两个执行域的手段，`M` 是测量方法。

## 1. 字节预算与 Roofline（`B`）

**主线：先定字节预算，再核算算力；先判绑定资源，再选优化手段。**

| 编号 | 原则 |
|---|---|
| `B1` | 编码前先写代价模型：`bytes_min`（每个输入从主存读一次、每个输出写一次）、`FLOPs`、`AI = FLOPs / bytes_min`。理想重叠下 `t_est = max(各流水的时间)`；另计依赖、启动与排空代价。 |
| `B2` | Roofline 判定对准**执行该运算的那条流水**（不同流水的拐点可差一两个数量级），结论写明绑定的是哪个资源。**「没有流水饱和」是合法结论**——绑定项是依赖链或同步，不要为凑标签硬选计算受限或带宽受限。 |
| `B3` | 上限取**实测可达值**，不取规格峰值；而且必须用流量已知的探针测，不能从做着计算的 kernel 反推。取不到就记 `unknown`（`M1`）。 |
| `B4` | **优先优化关键路径上的资源。** 由 profile 和对照实验定位瓶颈，以端到端时间验证收益。 |
| `B5` | 量化流量放大比 `A = bytes_measured / bytes_min`，评估减少重复搬运的收益及新增计算、同步与存储代价。融合要检查中间数据是否片上驻留，不能只数 kernel 数量。 |
| `B6` | 目标可达性先推导：按验收口径（含 benchmark 的评分公式本身）算出上限；目标超出上限时上报差距与原因。 |

## 2. 流水与多核并行（`P`）

| 编号 | 原则 |
|---|---|
| `P1` | 稳态吞吐由最慢的流水决定；非关键路径上的优化不改善端到端时间。 |
| `P2` | 搬运等待影响总耗时时，比较单缓冲与轮转缓冲。先保持切分和算术验证同步，再改变重叠；深度按生命周期、容量与实测选择，每次复核 `T1`。 |
| `P3` | 多核均衡按**工作量**分配，不按分块数——掩码、变长序列下两者不等价。等成本工作单元可估 `η_tail = work / (⌈work / cores⌉ · cores)`；变长工作检查最忙核的实际负载。 |
| `P4` | 检查设备侧循环内整数除法、取模与 shape 推导的代价。可由元数据确定的量提前计算，并比较增量地址推进；运行时数据决定的量保留在设备侧。 |
| `P5` | 循环次数较少时，启动与排空阶段的时间计入代价模型。 |

## 3. 切分与片上容量（`T`）

| 编号 | 原则 |
|---|---|
| `T1` | 容量**逐空间逐项**列出，每项乘以缓冲深度，求和不超限；tile 尺寸按硬件粒度取整后重新校验。 |
| `T2` | 切分自顶向下求解：分核 → 片上 tile → 指令粒度，每层约束下一层。 |
| `T3` | Vector 切分围绕实际行、归约轴与单趟元素数选择，不照搬 Cube 的 `M`/`N`/`K` 粒度；比较 DMA 启动开销、计算与容量。 |
| `T4` | 尾块逐维度选定有效形状或掩码；比较统一循环与独立尾部路径，并验证边界及额外控制开销。 |
| `T5` | 调参限定在约束可行集内（容量、粒度、均衡度），不做无约束网格搜索；动态 shape 结合支持域比较运行时轴、分桶和必要的静态特化。 |

## 4. Vector 执行域（`V`）

| 编号 | 原则 |
|---|---|
| `V1` | Vector 算子**不预设绑定资源**。同样的逐元素形态，可能受带宽限制，也可能受**发射速率**限制（超越函数、升位宽转换、在线递推）或受**跨 lane 搬运**限制——按 `B2`/`B4` 实测判定后再选方向。 |
| `V2` | 逐元素链融合为单趟：一次读入、片上完成计算、一次写出。 |
| `V3` | 访问步长默认为 1；非单位步长与跨 lane 访问（转置、广播）的代价计入模型。 |
| `V4` | 超越函数、升位宽转换、在线归一化递推的**发射代价**必须计入 Vector 时间。softmax 这类算子常常是 Vector 发射受限，而不是带宽受限。 |
| `V5` | 明确归约的累加次序与中间 dtype；长轴归约可比较更宽的累加器，但须保持原数值合同并验证误差与代价。 |

## 5. Cube 执行域（`Q`）

| 编号 | 原则 |
|---|---|
| `Q1` | 物理 `M`/`N`/`K` 满足分形粒度，填充率纳入效率模型。Cube 吞吐按**本算子 tile 形状**的实测值建模，不要假设它随单条指令的运算量上升——真正随分块形状变化的往往是**每个 MAC 附带的操作数搬运量**（窄分块会把同一份操作数重复搬入），按它给分块定价。 |
| `Q2` | 优先比较 `K` 轴部分和的片上驻留；跨核或分段归约时，计入部分和写回、合并与累加次序的代价。 |
| `Q3` | 在容量内比较更大的输出 tile。操作数条件对称时，接近方形可降低 `1/Mt + 1/Nt` 对应的流量；仍需计入实际复用、粒度与并行度。 |
| `Q4` | 布局变换（含转置）优先放进搬运通路完成，其代价计入模型。 |

## 6. Cube–Vector 融合（`X`）

| 编号 | 原则 |
|---|---|
| `X1` | CV 混合存在独立分块时，保留串行对照并比较错拍。先验证同步与槽位生命周期，再引入并发；代码相邻或声明多个缓冲不证明已经重叠。 |
| `X2` | 比较 tile 形状对两侧计算、搬运、容量与并行度的影响，以完整调用时间选择，不能只追求两侧单分块时间相等。 |
| `X3` | 同步粒度须同时给出上界与下界：过细则同步开销主导，过粗则流水气泡主导。写明每次同步交接的数据量。 |
| `X4` | 数值合同允许时比较跨分块在线递推；也可比较分阶段归约，计入中间流量、合并及启动代价，以正确性和完整调用实测选择。 |

## 7. 度量与证据（`M`）

与平台无关的度量方法。依赖具体平台或流程的度量规则不在本文件，编号空档由那一侧定义。

| 编号 | 原则 |
|---|---|
| `M1` | 未取证的项记 `unknown`，不要记成通过。`unknown` 是合规取值。 |
| `M2` | 先模型、后测量、再**解释差距**。模型与实测的明显偏离不得当作测量噪声吸收；首先怀疑绑定资源判错（`B4`）。 |
| `M3` | 保持验收指定的测量协议，固定比较输入、启动参数与 warm-up，重复测量并报告指定指标及离散度。代表 case 可筛选候选；最终按承诺范围与聚合公式确认，异常先复测。 |
| `M4` | 偏离某条原则时写明 `{编号, 理由, 实测代价}`。 |
| `M7` | 新实测若影响已有结论，核对其设备、配置与测量口径，再复核受影响的判断；不要直接将局部结果当作通用上限。 |
| `M8` | 多个独立结论若依赖同一个**未经实测**的量，其相互一致不构成验证。采信前先确认那个量有没有人实测过（`B3`）。 |
