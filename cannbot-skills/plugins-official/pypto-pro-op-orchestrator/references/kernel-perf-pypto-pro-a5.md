# 性能原则在 PyPTO-Pro + A5 上的落地

适用范围：**PyPTO-Pro 框架 + 本仓的算子开发流程 + Ascend A5（950PR/950DT）芯片**。
换框架或换芯片时可新增一份同级适配参考。

> 本文件是 [`kernel-core-principles.md`](kernel-core-principles.md) 的落地层。原则对芯片、
> 框架、工具链与流程都不作假设，因此不含具体对象与数值；本文件把这些补上——术语对应、
> 诊断阈值、自检清单、取舍比较、以及结论写到哪里。本文件随框架与实测更新。
>
> **依赖是单向的**：本文件引用原则，原则不引用本文件、也不提及任何平台、工具或 skill。
> 本文件只适用于已确认的 A5 目标。

## 1. 平台与框架映射

原则里的抽象术语在本平台的具体对象：

| 原则中的说法 | 本平台 / 本框架 |
|---|---|
| 主存 | GM（HBM） |
| 片上存储层级（`T1` 逐空间列举） | UB、L1、L0A、L0B、L0C，各自独立寻址、独立限容 |
| 片上累加器（`Q2`） | L0C |
| 轮转 buffer（`P2`） | `make_tile_group` 显式分配槽位；`auto_mutex` 管核内复用，跨核另需交接同步 |
| 有效形状 / 掩码（`T4`） | `pl.set_validshape`、VF 的 `update_mask` |
| 执行流水（`B2`/`P1`） | MTE1/MTE2/MTE3、Cube(MAC)、Vector、Scalar、FixPipe |
| Vector 占比证据（`V1`） | msprof 的 `aiv_vec_ratio` / `aic_mac_ratio` 等 pipe ratio |
| 布局变换（`Q4`） | ND ↔ NZ、`order=` 形式的转置搬入 |
| 单趟元素数（`T3`） | 设计文档里记作 `elements_per_pass` |
| 分核数 | `block_dim`，上限从匹配安装版本的 runtime 平台信息获取，不要硬编码 SKU 核数 |

A5 容量、核数及配置从匹配版本和 SKU 的 PyPTO/CANN 源码读取：
`framework/src/platform/parser/simulation_platform/platform_config/950PR_*.ini` 或 `950DT_*.ini`，以及 `python/pypto_pro/runtime/platform.py`。
带宽与流水吞吐另需匹配工作负载的探针和原始 profile，不能把配置值当作实测上限。

## 2. 自检清单（`G`）

调优收尾时逐项自查，当「还有哪里没看」的清单用。没测过的记 `unknown`——它是合规取值，
不是缺陷（`M1`）。不要求产出专门的门禁文件，写进你本来就有的报告即可。

| 编号 | 检查项 | 参考判据 | 证据来源 |
|---|---|---|---|
| `G1` | 正确性前置 | 待测配置的用例数值通过；最终验收覆盖完整合同 | 测试日志 |
| `G2` | 标量开销 | 标量流水占比 > 0.5 × 最大流水占比时，检查循环内除法、取模及地址计算（`P4`） | msprof pipe ratio + 源码扫描 |
| `G3` | 流水重叠 | `max(pipe_ratio) < 0.8` 时检查同步、依赖链与启动/排空；高占比本身不证明吞吐最优或已经重叠 | pipe ratio + 时间线 / 对照实验 |
| `G4` | 多核均衡 | `η_tail ≥ 0.9`（`P3`）；有分核时间线时核间离散度 ≤ 10% | `block_dim` + 分核数据 |
| `G5` | 流量 | 参考 `A ≤ 1.1`（`B5`）；区分逻辑搬运量与物理内存流量 | 源码计数 / 匹配的内存计数器 |
| `G6` | Roofline 差距 | `t_meas > 1.25 × t_est` 时检查模型与剩余代价（`B1`–`B3`）；接近估计值不证明已达硬件上限 | 模型 + 实测 |

先满足当前待测配置的 `G1`，再按观测瓶颈选择 `G2`–`G6`；不要求每轮收集全部数据。

**这些阈值仅是诊断参考**，可随平台、工作负载和计量口径调整，不能作为验收或停止调优的依据。
以用户目标、完整调用实测和剩余可行实验判断进展；未完成的比较如实说明。

## 3. 常见取舍的比较

下列取舍在当前工作负载与容量下比较，不预设统一赢家。

| 取舍 | 比较方法 |
|---|---|
| 大 tile（`B5`/`Q3`）↔ 多缓冲占用（`P2`） | 固定传输宽度比较深度，再在新容量下复查 tile 大小与完整调用时间。 |
| 少而大的任务（`B5`）↔ 多核均衡（`P3`） | 同时核算重读、填充及最忙核工作量，比较 tile 与分核组合。 |
| 减 GM 字节（`B5`）↔ CV 错拍（`X1`） | 计入新增计算、同步与存储，比较完整路径的时间（`B4`）。 |
| 深度融合（`B5`）↔ 片上容量（`T1`） | 比较多趟片上遍历与分阶段实现，复核各阶段容量、总流量和启动代价。 |
| 重读小张量省不省（`B5`）↔ 实际代价 | 用工作集、计数器或对照实验检验 L2 复用；逻辑重读量不等于 DRAM 流量。 |

## 4. 平台实测与结论汇总（`M5`–`M6`）

| 编号 | 规则 |
|---|---|
| `M5` | 用可复现的 A5 实测校准同一量的估计，记录数值与证据路径。复用历史值前核对设备、工具链、源码、工作负载与测量口径；条件不同的值不能直接替代。 |
| `M6` | 汇总测量结论时，不带证据路径的按 `unknown` 计，不要当成已验证。 |

## 5. 结论写到哪里

不新增产出物。

| 阶段 | 写进 | 内容 |
|---|---|---|
| 设计 | 现有设计说明或当前上下文 | 代价模型（`B1`）、Roofline 判定与上限来源（`B2`/`B3`）、目标可达性（`B6`）、容量核算（`T1`）、分核与 `η_tail`（`P3`）、切分参数 |
