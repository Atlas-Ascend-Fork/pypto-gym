# 多 agent 协作说明

本说明仅在用户明确开启多 agent 模式时生效。协作只改变任务分工和上下文管理；全部技术要求、执行顺序和完成条件均以 `pypto-pro-kernel` 及其参考文档为准。

## 主代理做什么

主代理读取 `pypto-pro-kernel` 的当前任务指引，用于路由和审核，在具体执行前通过宿主原生工具派工。OpenCode 使用下表完整名称；角色按需选择，不是固定阶段，也不要求每次全部出场。工具不支持子代理时，说明限制，不声称已按本模式执行。

需求与验收分析交 planner，主代理核对依据，必要时向用户澄清。**主代理每次准备写文件或执行命令前，改为派工；环境准备也不例外。** 主代理可读取必要源码和原始结果作判定；缺少证据、子任务失败或仍未达标时，安排下一子任务，不自行接手开发或排错。

主代理保留需求、当前代码与基准版本、验证结果摘要、未通过的检查、剩余预算和下一问题。完整源码、日志留在原处，需要时再查看。

## 什么时候调用子代理

| 子代理 | 调用时机 | 本次任务 |
| --- | --- | --- |
| `pypto-pro-op-planner` | 需要梳理需求与验收标准，或它们发生变化时 | 只读分析，返回需求、约束、验收标准、待澄清项及依据；需要落盘时，由主代理审核内容后交 tool 写入指定位置。 |
| `pypto-pro-op-coder` | 需要实现，或已明确如何修复时 | 完成一个完整的最小实现或一次修复，并做必要检查；遇到新的失败就交回，不在同一会话中反复排错。 |
| `pypto-pro-op-debugger` | 失败原因未明，或验证结果互相矛盾时 | 复现、定位一个问题，给出依据和修复建议；可按 skill 编写诊断程序，不改交付候选。 |
| `pypto-pro-op-verifier` | 需要检查本次修改或最终交付时 | 独立运行所需检查，报告通过范围和失败；不修改被检查的文件。 |
| `pypto-pro-op-optimizer` | 需要验证一个优化思路时 | 完成这一思路的实现、所测用例的正确性检查和性能对比，不包揽全部优化。 |
| `pypto-pro-op-tool` | 需要环境核对、资料查证、接口探针、编译运行、计时采集或交付整理时 | 执行一项有明确目标的操作，可编写辅助脚本或落盘已审核内容；返回原始结果，遇到未知失败交回，不接管排错、验收或优化决策。 |

实现后通常交 verifier 检查。原因不明的错误先交 debugger 定位，再安排修复和复查；原因已明确可直接交 coder。coder 的必要自检不包含持续定位未知错误；不能以“全部通过后返回”让其包揽排错闭环。已有代码从 skill 要求的当前工作继续，不从头重做。

每个问题、职责切换和优化实验使用新会话。OpenCode 新任务不复用旧 `task_id`；同一任务仅缺一条信息时，可短续原会话。换会话仍要保留已知需求、失败结论、剩余预算和未完成的验证。

一轮优化围绕一个完整思路，不按一行代码或一次测量拆任务。skill 要求在同一测量程序、进程和设备锁内完成的 AB/BA 测量，不拆给不同子代理。数值错误的版本不用于性能比较；可以放弃并恢复最佳已验证版本，也可以另派任务修复。一轮结束后，仍按 skill 继续检查、比较并判断是否完成。

独立的通用执行任务交 tool；各专业角色仍可自行调用职责内的工具，不把每条命令再拆成派单。单次计时采集不能替代 verifier 的独立检查或 optimizer 的完整对比。首个完整用例、计时采集和测试矩阵的顺序遵循 skill，不因分工推迟检查，也不额外要求每次小修都运行完整测试矩阵。

## 上下文预算与续接

上下文交接阈值默认是 **384K tokens（384000）**；用户明确指定其他值时，以用户指定值为准。派工时将本次阈值交代给子代理。每轮读取或工具返回后，核对宿主提供的用量；取不到计数时明确说明未知，保守安排提前交接，不声称已准确计数。

达到或预计下一轮会接近阈值时，子代理即使尚未完成任务，也应在安全点返回，明确说明“因上下文预算需要交接”，并报告当前进展和未完成项。主代理审核后创建新子会话继续，不续用接近阈值的旧会话。主代理自身接近阈值时，保留摘要并使用宿主支持的压缩或续接方式。

交接摘要保留需求、skill 约束、代码与基准身份、验证进度、未解决问题、剩余任务预算及下一步；换会话或压缩不重置实验历史和预算。控制读取范围与输出量；不可拆开的测量在开始前留足空间，不能为换会话拆开 AB/BA。

skill 要求的正文仍须完整读取；分段读取时补齐缺失或截断内容，不能为省上下文跳过必要依据或检查。必读内容本身无法容纳时，报告限制并调整任务范围，不能改变 skill 流程或声称已完成。

## 给子代理什么信息

- 说明本次已启用多 agent 模式，给出本次目标、完成条件、任务预算、上下文交接阈值、可修改范围和返回条件；明确不再派生子代理。派单不得扩大角色职责，子代理发现冲突时返回说明，不越权执行。
- 工作目录、算子需求、当前代码和基准版本、运行配置与设备锁；skill 及本次所需参考文档的路径。只阅读相关内容，缺失或截断时补齐。
- 原始结果的位置与简短说明、已排除的原因、尚未通过的检查。不复制整段对话或全部日志。

子代理返回：结论、实际改动、所用代码和环境版本、关键命令与退出码、原始结果路径、已检查范围、未解决问题及建议下一步。未知或未运行的项目直接说明，不强制新增交接文件或实验记录。

主代理核对结果后再派下一任务；缺少前提时派工补齐或说明阻断。代码、依赖、配置或工具链变化后，按 skill 重验受影响项。同一个待验证版本同时只由一个子代理修改，运行验证期间不修改其代码，设备任务遵守项目锁；只读调查可并行。压缩或恢复上下文时保留多 agent 模式、主代理职责和前述摘要。
