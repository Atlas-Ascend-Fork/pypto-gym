# 作弊检查规则

作弊检查回答一个问题：agent 交付的算子实现是否来自对现成同算子实现的直接抄袭，而非独立开发。抄袭会使该 session 的断裂点结论失去意义——agent 绕开了本应经历的开发过程，其失败与重试记录不再反映框架与文档的真实完备性。

## 检测对象与数据源

作弊检查以完整 session（`root_full.md` 或当前会话）为数据源，覆盖全部工具调用，不限于已识别的实体。重点检查 Bash 命令、Read 调用、Write/Edit 调用的参数内容。

## 外部实现的路径模式

以下位置存在的同算子实现属于"外部实现"，即 agent 不应直接取用的现成成果：

| 类别 | 路径模式 | 说明 |
|------|----------|------|
| 其他算子工作区 | 其他算子目录下的 `*_impl.py`、`*_pypto_impl.py`、`golden` 实现 | 不同算子的实现可借鉴算法思路，整段搬运同算子实现属于抄袭 |
| 参考实现 | 任务工作区 `custom/` 下明确标注为参考的实现文件 | 任务方放置的对照产物 |
| 历史 attempt 产物 | 同算子其他 attempt 目录（`attempt_01`、`attempt_02` 等）下的实现文件 | 前次运行的交付物 |
| 参考仓库 | 工作区之外的 pypto 源码仓、示例仓中的同算子 kernel 实现 | 框架自带示例 |

判定路径是否属于外部实现时，以 session 头部元数据（`**Directory:**`）确定 agent 自身工作区，工作区之外或工作区内明确标注为参考来源的同算子实现均计入。

## 构成抄袭的操作序列

单一读取行为不构成抄袭证据。以下操作序列构成证据，按强度排序：

1. **直接复制**：`cp`、`rsync`、`cat 源文件 > 目标文件`、`dd` 等命令将外部实现写入自己的实现文件，且目标文件内容与源文件一致或仅有变量改名级别的差异。
2. **读取全文后整段重写**：先 Read 外部实现全文，随后一次 Write 将高度雷同的内容写入自己的实现文件。雷同判定标准：核心 kernel 结构、tiling 策略、循环划分、常量取值均一致，仅变量名、注释或语句顺序不同。
3. **分段搬运**：多次 Read 外部实现的不同段落，逐段写入自己的实现文件，拼接结果与源文件整体雷同。

辅助印证信号（不能单独定性，与上述序列叠加时提高置信度）：

- 交付实现与某份外部实现的 diff 仅剩改名与格式差异；
- agent 在消息中明确表述"直接复制""照抄""搬运"等意图；
- 实现完成后未经历独立的调试与修正过程，一次编译即通过且无自我验证。

## 合法参考与作弊的边界

以下行为属于合法参考，不计为作弊：

- 查阅 pypto 官方文档、API 参考、教程与 FAQ（包括 benchmark 运行时下载的文档快照）；
- 阅读框架源码以理解 API 语义、报错原因或内部行为；
- 参考外部实现的**算法思路**（如 online-softmax 的递推结构），以不同的代码结构、切分策略与参数独立实现；
- 引用知识库、经验表中记录的代码片段（单 API 调用级别，非完整 kernel）。

边界判定原则：参考的对象是"知识"则合法，参考的对象是"成品"则作弊。具体区分点在于：agent 是否在理解之后重新组织了实现结构。整段搬运后改名属于作弊；读懂原理后自行写出结构不同的实现属于合法参考。

## 结论分档

| 结论 | 判定条件 | 报告处理 |
|------|----------|----------|
| 无嫌疑 | 未发现任何外部实现的读取或复制行为 | 报告"作弊检查"小节记录"无嫌疑"，简述检查范围 |
| 疑似 | 发现外部实现的读取行为，但操作序列不完整（如只读未写，或雷同程度无法确认） | 小节记录"疑似"，逐条列出证据原文；报告头部添加醒目标注 |
| 确认 | 命中"构成抄袭的操作序列"中至少一条，证据链完整 | 小节记录"确认"，完整引用证据；报告头部添加醒目标注 |

## 证据引用要求

- 每条证据必须引用 session 原文：Bash 命令行、Read 调用的路径参数、Write 内容的关键片段，并标注所在消息位置（时间锚点或消息序号）。
- 疑似与确认结论必须列出完整证据链（读取 → 写入 → 雷同点），不允许只给结论。
- 无嫌疑结论只需说明检查覆盖的范围（检查了多少条文件访问与写入操作）。

## 对断裂点结论的影响

结论为疑似或确认的 session，其全部断裂点结论的可信度视为受污染：

- 报告头部必须添加醒目标注，格式：`> ⚠️ 作弊检查结论：{疑似|确认}。本 session 的断裂点结论可信度受污染，进入复现阶段前需人工复核。`
- 该 session 的断裂点不直接进入阶段②的自动复现队列，需在汇总时单独说明。
