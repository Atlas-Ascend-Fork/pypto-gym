# 性能知识卡片独立审核指南

本指南供审核者与 Agent 独立检查卡片及其证据。格式、材料与性能门槛统一采用[贡献指南](CONTRIBUTING.md)；贡献者自评和独立审核共用本页的[五项评分标准](#score-the-five-criteria)。

## 审核范围与前置条件

独立审核适用于新增卡片、实质性修订及已收录卡片的复审。审核对象包括固定版本的卡片、适用时的双语材料、完整对照实现、测试、原始证据和自评报告。材料应完整、可追溯，并具备执行设备验证及隔离盲测的条件。

新增卡片和实质性修订按当前规范验收。仅复审已收录卡片时，形式与语言按其原收录版本核对，不因未采用新英文模板而判错，也不要求在复审中翻译、迁移或改写原卡。内容、正确性、收益与证据仍须独立核查，报告注明适用规范；缺少证据或执行条件时标为待补充材料或验证。

审核者独立作出内容、正确性、性能及适用性判断，交付逐卡报告和修改建议。卡片修订属于贡献者职责，后续复审以修订后的固定版本为对象。

<a id="audit-an-existing-library"></a>
## 建立审核清单

固定索引、卡片 ID、路径、版本和文件摘要，核对审核范围完整。查重覆盖全部类别与状态、待审候选及同批材料。同一 ID 的不同修订、不同语言版本及不同 ID 的重复机制应分别识别。复审时按来源版本核对实现与原始结果，记录已有评审结论的适用范围。

## 内容与实现检查

1. 逐卡建立卡片、完整 before/after 实现、独立参考、用例及证据的对应关系。
2. 逐行核对代码片段与受测实现中的操作、变量、偏移、顺序及上下文，验证标注的抽象、改名和省略。
3. 检查数据类型、形状、布局、数据归属、初始化、同步、尾块及调度。基线应执行原工作，候选应实施所述机制。
4. 对包含多项优化的实现采用匹配对照，区分各项改动对收益的贡献。

<a id="compare-the-chinese-original-with-the-english-card"></a>
## 双语语义检查

对由中文来源生成英文卡片的投稿，应以已归档且 SHA-256 一致的实际中文原稿为核查依据，固定两版 ID、版本和对应位置。先从中文核对每项英文表达，再反向检查英文主张的中文依据。覆盖元数据、适用及排除条件、代码、机制、验证和局限，并核对 API、dtype、形状、数值、单位、不等式及限定词。

英文原创和仅保留原收录语言的存量复审无需补造另一语言版本；记录不适用的原因。有中英文对照时，通过条件为全部技术主张双向对应且语义一致。语义问题应记录两版具体位置、影响及建议改文。[材料规范](CONTRIBUTING.md#author-preflight)

<a id="independently-run-the-operator"></a>
## 独立设备复测

1. 使用可信版本的验证工具，固定契约、参考实现、精度门槛、用例和计时计划。
2. 在目标设备上独立构建并执行两个版本，按设备执行规范核实测量期间的负载可比性。按固定计划区分收益、正确性边界及排除用例，执行[验证与材料规范](CONTRIBUTING.md#freeze-the-cases-and-collect-the-evidence)要求的覆盖范围和数值检查。
3. 按[配对测量标准](CONTRIBUTING.md#freeze-the-cases-and-collect-the-evidence)采集每个声称获益用例的 AB、BA 原值。用同一规范的数值门槛和指标要求判定，正确性边界和排除用例不要求证明提速。
4. 记录设备与会话、软件版本、源码及驱动摘要、实际命令、退出状态、数值误差和计时文件。通过生成代码、对照实验或剖析数据检验机制及其他可能解释。
5. 使用材料检查器核对结果摘要绑定、声明的用例与指标覆盖以及统计计算。对照运行记录确认实际执行的实现和计划版本，检查原生计时的调用边界和任务归属，并判断覆盖是否足以支持卡片的适用范围、设备声明及收益归因。

<a id="score-the-five-criteria"></a>
## 五项评分标准

每个检查项有充分证据支持时得 5 分；未完成或不符合的检查项不得计分。每项标准满分 20 分，总分 100 分。评分应逐项引用固定版本或产物，并标识检查是否完成。作者自评与独立审核采用相同标准。

| 标准 | 检查 1 · 5 分 | 检查 2 · 5 分 | 检查 3 · 5 分 | 检查 4 · 5 分 |
| --- | --- | --- | --- | --- |
| 新颖性 | 使用机制名称、同义词和源码中的特征写法检索整个卡库，覆盖全部类别和状态。记录检索词和范围。 | 检查最相近的卡片、可获得的待审候选，以及本批材料中的其他候选卡。引用对应卡片 ID，或记录未命中时的检索过程。 | 与最相近的条目比较前置条件、代码变换及消除的开销。说明区别，或指出应扩充哪张已有卡片。 | 新卡给出了独立且可复用的机制，或在原 ID 下对已有卡片作了实质性纠正或扩充。不存在重复条目。 |
| 格式 | 文件头元数据、正文及必需章节符合适用版本的格式与语言规范；新增及实质性修订按[当前规则](CONTRIBUTING.md#card-format-and-admission)及[模板](CARD_TEMPLATE.md)核查。 | ID、路径、类别、状态、索引条目和证据链接相互一致。 | 基线说明及其代码片段（新卡的 Before）对应真实基线源码，并包含必要上下文。 | 优化说明及其代码片段（新卡的 After）来自实际运行的候选源码，在同一范围内展示改动。两段代码的执行状态标注都准确。 |
| 通用性 | 读者无需知道示例算子的名称，就能根据标题和规则识别一类计算。 | 读者能根据可观察的特征，判断未见过的工作负载是否满足前置条件。 | 卡片解释了改写如何改变这类计算中的依赖关系、数据搬运或资源开销。特定用例的常量和耗时只用于描述该示例。 | 卡片给出具体的排除条件或反例，并说明如何识别。 |
| 清晰性 | 一张卡片讲清一种优化机制。 | 读者能依次理解基线做法、具体改动和预期效果。 | 行文简洁直接，没有无助于理解的口语套话。 | 必要术语在首次出现时有解释，没有多余标签。适用时，归档中文原稿与固定英文卡片还须通过上述双语核对。 |
| 验证 | 提供的两个完整算子版本均可运行，固定版本的源码和实际执行的产物与卡片描述相符。 | 两个版本在阈值不变的条件下，均通过独立数值参考的比对，覆盖契约要求的全部范围。 | 每个预先声明的收益用例在全部必测指标和两种执行顺序下通过验证规范中的计时门槛；正确性边界与排除用例不要求提速。由原始配对数据可复算出报告数值。 | 生成代码中的可观察结果、条件匹配的对照实验或性能剖析数据检验了卡片所述原因，并回应了其他可能解释。凭借产物和运行记录可以确定被测代码。 |

<a id="run-a-fresh-blind-implementation"></a>
## 基于卡片的独立实现验证

每张卡片由一个无既有对话或任务记忆的子代理独立实现。执行环境仅提供固定版本的卡片、公开 SDK 和设备运行接口；新增或实质修订用英文卡片，存量复审可用原收录语言。通过访问控制隔离来源算子、配套样例、卡片之外的原稿、其他实现及共享缓存。

1. 子代理自行选择算子，提交接口、数值契约、适用条件、反例、用例及测量计划。
2. 主审固定该计划，独立准备隐藏参考和用例，再启动实现阶段；实现阶段不提供来源代码或定制实现提示。
3. 子代理从零实现两个版本，返回源码、执行记录及测量结果。
4. 主审独立复跑，确认基线工作量、候选机制、正确性及性能门槛，保存卡片摘要、任务指令、隔离配置和复测产物。

不具备独立子代理或信息隔离条件时，记录该验证待完成，不以主审复测代替，也不据此判定卡片内容错误。

验证失败时，定位最早失败阶段，区分指导内容、实现、适用范围和执行条件的原因。问题结论应具有可复现证据，并列出支持依据、替代解释和建议验证方法。

## 审核结论与报告

评分记录 20 项检查的完成度。若差异仅涉及文字润色，且不影响规则理解、术语含义、代码复用或证据复核，可记录为润色建议并反映在清晰性得分中。涉及技术语义、适用边界、格式合规、双语一致性或验证证据的问题仍须解决。

| 结论 | 判定条件 |
| --- | --- |
| 通过 | 满足适用规范的五项要求，证据完整可复现，独立设备复测与逐卡独立实现验证均通过。仅有文字润色建议时仍可通过 |
| 需修订 | 有明确证据表明未达到五项要求中的一项或多项，记录位置、预期与实际结果、影响和建议改法 |
| 待补充材料或验证 | 审核前置条件、必需材料或检查结果尚不完整，列明具体补充要求和验证标准 |

报告应包含审核范围与版本、材料清单、20 项结果和得分、双语核对、独立数值与计时结果、机制证据、独立实现验证结果及逐项修改建议。区分已确认问题与待验证判断，标明结论的证据强度和适用范围。报告交付后完成本次审核。
