# 技术卡片 recurrence-01：长仿射递推分段

> **一句话机制**：把串行状态递推切成可独立计算摘要的段，先并行计算摘要，再按依赖顺序恢复真实状态。
>
> **示例**：KDA 解码使用 4 个头，每个头划分 7 段，共形成 28 个并行摘要任务。
>
> **适用前提**：状态转移系数只依赖输入，不依赖待求的入口状态。

一条状态链沿时间串行更新。独立链数量不足时，空闲核没有可执行的任务。
分段方法先独立计算每段对入口状态的作用，再按依赖顺序恢复真实状态。
它增加局部并行任务，但仍保留较短的段间依赖。

## 何时用（诊断特征）

- 每条递推链由一个任务沿时间轴串行执行，少量长链占据关键路径，其余核缺少有效工作。
- 状态转移系数由输入决定，与未知入口状态无关；段摘要可独立产生。
- 所需观测结果也能表达成入口状态的仿射函数，或接口只需要段末状态。

这种结构可出现在状态空间更新、线性滤波和分块扫描中。
使用前需从当前计算图证明适用条件。只多启动核不产生新的独立工作：分段前必须先证明摘要可独立计算。

## 何时不适用

- 状态转移系数依赖当前状态，或更新对入口状态非线性，不能形成可独立计算的仿射摘要。
- 只保留段末摘要，却无法恢复接口要求的段内观测结果。
- 链很短、天然任务已足够多，或摘要/恢复的额外计算与搬运成本过高。
- 工作区、精度或同步能力不足以在项目允许的执行范围内完成状态恢复。

## 原理

设状态更新为 `H_t=A_t @ H_previous+B_t`。`A_t` 和 `B_t` 由输入确定。
对第 s 段，连续更新可写成 `H_out=P_s @ H_in+Z_s`。
`P_s` 表示入口状态的映射，`Z_s` 表示该段自身的贡献。二者合称段摘要。
先执行段 i，再执行段 j，其摘要组合为：

```text
结构示意：仿射组合，省略 dtype、布局、工作区和同步，不能直接编译。
compose(j, i) = (P_j @ P_i, P_j @ Z_i + Z_j)
```

各段先独立计算 `P_s` 和 `Z_s`。段内观测指接口需要返回的各位置结果。
若观测对入口状态也是仿射函数，则可写成 `O_s=C_s @ H_in+D_s`。
各段可独立计算 `C_s` 和 `D_s`。

从初始状态出发，按顺序应用摘要，得到每段的真实入口状态和最终状态。
再将入口状态代入观测公式，得到完整输出。仅保留段末状态不能替代所需的段内输出。

组合在精确算术下满足结合律。顺序恢复或树形 prefix 的成本不同，浮点组合顺序也不同；
选择恢复方式时同时评估精度、工作量和同步，不能仅凭结合律认定浮点结果等价。

## 怎么改（改写前 / 改写后）

以下为**结构示意**，不规定 launch 数或同步 API：

```text
改写前：
  每条链一个任务，沿完整长度更新状态并产生观测
改写后：
  每条链划分若干连续段，每个段交给独立任务
  从局部输入计算段摘要及所需观测的入口状态系数、局部项
  从原始 initial_state 有序组合摘要，恢复每段 H_in
  补齐段内观测；仅该链最终段的 owner 写 final_state
```

选择段数时，需同时考虑独立链数量、可用核数、链长和恢复成本。
核数变化时，重新检查以下内容：

- 每个任务处理的范围及末段负载。
- 摘要、入口状态和同步标志的存储位置。
- 负责写入最终状态的任务。

事件或互斥量的编号不一定表示任务数，不能随核数机械替换。
各段属于同一条链。初始状态只在恢复起点加入一次，不能在每段重复加入。

## 性能与验证指标

- 有效任务数、每任务工作量、最长段耗时、摘要与恢复成本、额外工作区传输量。
- 完整调用的关键路径和各阶段成本；增加段数后重新检查恢复是否成为瓶颈。
- 与原串行递推比较全部观测和最终状态，覆盖非对称非零入口、短链、尾段及不同转移系数。
- 检查跨段、连续调用的状态接续与方向，以及多链的映射和写入隔离。

现有验证同时覆盖摘要、入口恢复和输出，没有分段方法的单因素性能对照。
其他流程需重新选择任务数、段长和恢复方式。不能按核数比例推算性能收益。

## 技术限制与风险

- 映射组合可能增加运算量和舍入误差；利用对角、低秩等结构前需证明其保持原更新语义。
- 状态为方阵时，shape 检查不能发现方向或转置错误，应使用非对称入口验证。
- 摘要、入口状态和观测系数的发布/消费及工作区生命周期属于正确性条件。
- 数学分段不自动允许额外 launch；目标版本无法在既定执行合同内落地时记录能力缺口。
