# 技术卡片 recurrence-02：独立逻辑块打包

逐块处理小数据块会重复支付搬入和调度准备成本。
将多个块放入一个物理数据块（tile），可以批量处理独立的局部计算。
物理批量可以改变，数学定义的逻辑边界必须保留。

## 何时用（诊断特征）

- 很多小逻辑块重复执行搬入、局部预处理和调度准备，固定开销占比高。
- 块内归约、扫描或局部矩阵系统相互独立，批处理可以屏蔽所有跨块项。
- 较大工作 tile 的实现已验证，存储容量和尾块处理允许打包。

判断对象是局部计算的依赖边界。后续即使存在跨块递推，也可只打包独立预处理，再有序消费。

## 何时不适用

- 局部计算本来就依赖前块的结果，无法独立准备。
- 大 tile 增加的屏蔽运算、搬运、容量或同步成本抵消收益。
- 只改变参数或工作 tile 大小，却把多个逻辑块当成一个系统处理。

## 原理

设每个逻辑块包含 L 行，一次装入 m 个块。物理数据块包含 `m * L` 行。
局部扫描仍需在每个逻辑块的起点重置。独立系统之间的关系项仍为零。

对于独立三角系统，打包后的矩阵是 `block_diag(T0, ..., T[m-1])`。
`block_diag` 表示将各系统放在对角线上，其他区域为零。
其逆也是各系统逆矩阵的块对角组合。打包不产生跨系统求逆项。

打包只改变处理批量。每块的边界结果和下游消费次数仍需保留；有状态的消费者继续使用前块
末状态作为后块入口。

## 怎么改（改写前 / 改写后）

以下为**结构示意**，省略 DSL、物理布局、tail 和同步，不能直接编译：

```text
改写前：
  对每个 L-row 逻辑块单独准备、搬入和执行局部计算
改写后：
  一次准备和搬入 m * L rows
  对每个逻辑块分别重置归约/扫描，形成独立局部结果
  若计算关系矩阵，将跨逻辑块区域屏蔽为零
  若执行局部求解，仅在对应逻辑系统内部合并
  为每块保存独立边界结果，按原有顺序交给消费者
```

修改打包比例时，同步调整分派、局部结果索引、步长和工作区。
为每个逻辑块保留独立的边界结果存储位置。
物理数据块的行数变化，不意味着特征维或状态维也要变化。

同一个物理数据块可以承载不同大小的逻辑块。
每种逻辑块大小都需要对应的扫描重置、掩码和消费规则，不能混用。

## 性能与验证指标

- 准备次数、每任务 tile 数、搬运/cast 指令数、有效及屏蔽运算量、容量和尾块成本。
- 与未打包路径比较每块局部中间量及最终结果；给相邻块设置不同数据，检查边界重置与隔离。
- 检查未满 tile、多种打包比例、边界结果数量；存在递推时补查非零状态和跨块接续。
- 比较完整调用，检查局部准备的收益是否被下游布局或消费成本抵消。

现有验证覆盖独立局部系统和有序状态消费。
验证没有提供同一逻辑块大小下的打包与未打包性能对照。
因此，不同逻辑块大小之间的耗时差不能直接归因于打包。

## 技术限制与风险

- 任一 reset、mask、边界结果或消费者仍按工作 tile 边界处理，都会改变逻辑块语义。
- tail 的屏蔽和初始化须覆盖实际被读取的物理区域，避免读取前次工作区残值。
- 大 tile 的额外舍入、UB/L1 生命周期和跨引擎可见性需重新验证。
- 先证明局部计算独立，再评估打包；屏蔽计算不计为有效工作，busy 增加不代表收益。
