## Prove an invariant before removing work

Start with the property's source: the formula, actual metadata or a complete device certificate. An observed distribution or a configured chunk size does not prove an invariant of the current tail. Derive the reduced algorithm from that property, then separately qualify its finite-precision behavior and physical cost. This can remove work even when the original mapping keeps its arithmetic pipe busy.

Derive rank from the complete producer expression. In `G[i,j]=sum_r A[r,i]*B[r,j]`, one actual contributor gives an outer product in exact arithmetic. A dense residual or bias added to G can destroy that property even when the contraction still has one contributor; arbitrary elementwise masks or nonlinear transforms need their own proof. Entrywise finite-precision rounding can also perturb exact rank. Qualify the rewritten arithmetic against the original reference rather than claiming bitwise equivalence from the real-arithmetic identity.

For a concrete mathematical example, let `G=u*v^T` and `X_0=G/d`, where d is the contract's normalizer, including its epsilon. For nonzero u/v, write `X_k=s_k*u_hat*v_hat^T`. An odd matrix polynomial

```text
X_next = a*X + b*(X*X^T)*X + c*(X*X^T)^2*X
```

then reduces in exact arithmetic to `s_next=a*s+b*s^3+c*s^5`, starting from `s_0=norm(u)*norm(v)/d`. Reconstruct the result from the same directions. Handle zero norms with the original zero/epsilon semantics before forming unit vectors. Replacing a matrix norm by a product of vector norms, changing normalization order or reconstructing the result changes finite-precision arithmetic and requires the original checker. Keep prescribed iteration counts, updates and all dependent outputs. Actual single-term gradients can establish rank one; a sum of several outer products generally cannot.

A multiplier form avoids introducing division by a possibly zero vector norm. For the same normalized `X_0`, set `s=norm(G)/d` and `m=1`; at each required iteration use `f=a+b*s^2+c*s^4`, then `m=m*f` and `s=s*f`. The final expression is `m*X_0`. Retain the contract's norm/denominator path unless a replacement has its own numerical qualification. With zero G and a positive epsilon, X remains zero; later weight normalization or state/output work still executes when the contract requires it. This is a mathematical recipe, not a newly validated native implementation.

Other invariants need different proofs. For integers, `gcd(u,v)=gcd(v,u-q*v)` holds for any integer q, but an approximate quotient is useful only with exact representable integer residuals and a proved progress/termination domain. Floating remainder arithmetic does not inherit that identity. An affine recurrence summary likewise needs coefficients and injections with the required independence from prior state; its construction, duplicated work and extra stages can defeat the cost model.

[Gated outer state](../../examples/algorithms/gated_outer_state/) is a native anchor for outer-product recurrence and resident state. It still maintains the matrix and does not implement the scalarized polynomial above. For a new reduced path, preserve a complete ordinary control, test the actual qualifying tail, zero/tiny values and qualification boundaries, and compare the entire call including norm formation, reconstruction, launches and lost parallelism. The derivation itself is not device or performance acceptance.

## 1. Cancellation in Chained Matmul: `|golden|` Is Not the Scale for rtol

At output positions where a reduction cancels opposite-sign terms, `|golden|` can be much smaller than those terms. Relative error then mixes implementation defects with sensitivity to valid FP32 reduction orders. The [swiglu_ffn example](../../examples/algorithms/swiglu_ffn/) provides a measured instance and an independent sensitivity test; its results retain their own shape/toolchain scope.

When the task allows deriving an acceptance bound, an elementwise backward-error-style candidate is `|out - golden| <= RTOL * (Σ_j |a_ij|·|b_jk|) + ATOL`, using the sum of absolute terms (`reference.cancellation_scale`). Derive its coefficients from the permitted arithmetic and verify that incorrect indexing or omitted contributions fail it. When the task supplies ordinary atol/rtol, diagnose and fix the implementation within those criteria instead.

**Discriminating experiment:** on the same CPU input, vary FP32→FP64 without changing summation order, then single-shot→blocked summation without changing precision. Deviations caused by those changes establish numerical sensitivity, not the absence of an implementation defect; retain localization checks on the device result. Reusable case: `swiglu_ffn/test.py::test_reduction_order_sensitivity_is_inherent`.

For cancellation between a few products, such as a paired rotation, separate product rounding from summation error. When the contract permits more accurate arithmetic, a candidate is to form an independently rounded product `p = round(a*b)` and a residual `fma(a,b,-p)`, then combine product and residual terms with a justified summation scheme. This is not an unconditional error-free identity: establish operand/result ranges, residual representability, rounding and true FMA behavior, and inspect whether contraction/reassociation changed the intended operations. Summation compensation cannot recover a product residual that was never retained. Revalidate the complete expression at the original criterion and compare its actual cost; do not remove a contract-required intermediate rounding.

Apply the chosen criterion consistently to all elements, and retain required reproducibility and localization tests. Nonnegative normalized weights do not prevent cancellation when payloads have mixed signs; inspect the absolute weighted terms and the final consumer rather than inferring stability from the weights alone.

### Preserve intermediate precision

Distinguish input/output storage, accumulator dtype and the value passed to the next operation. FP32 accumulation followed by a BF16 intermediate does not preserve a reference that keeps that intermediate in FP32. Even a two-term contraction can expose the loss: `(1 + 2^-10) - 1` is nonzero in FP32, while first rounding both terms to BF16 makes it zero. Trace the executed reference's caller and helper dtypes before inserting a narrowing conversion.

When a matrix primitive requires lower-precision operands, compare a path that retains the derived operand in FP32 with a residual representation. For finite values within the component dtype's range, construct `c_i = round_low(r_i)` and `r_(i+1) = r_i - widen(c_i)`, starting with `r_0 = x`. For one derived operand and an already representable weight, accumulate every `c_i @ W` into FP32 before the next nonlinear operation or contractual output cast. If both operands are decomposed, the product needs their cross terms too.

Choose the number of components from the original error criterion and permitted ranges. With reconstruction residual `E = x - sum(c_i)`, its exact-arithmetic contribution satisfies `abs(E @ W) <= abs(E) @ abs(W)` elementwise; budget product, accumulation and downstream sensitivity separately. Check near-zero and cancellation criteria as well as mean relative error. Compare the producer's output and its reconstructed value separately: improving reconstruction cannot recover information already lost by the producer. For a long producer reduction, compare independent K partials plus an FP32 merge when that addresses the observed error, accounting for scratch, merge cost and the changed summation order.

One concrete Cube candidate distributes successive K blocks among `P` independent accumulators: block `j` contributes to accumulator `j % P`, preserving increasing K order within each partial. Merge the completed FP32 partials with an explicit tree, such as `(p0 + p1) + (p2 + p3)` for `P=4`. Compare this cyclic assignment with contiguous K partitions and the original chain; neither a fixed accumulator count nor a statistical rounding estimate establishes accuracy. Choose `P` from the actual error and live-resource budget. If static unrolling simplifies the per-accumulator initialization, finalization or slot schedule, also handle a K-block count not divisible by `P` and fewer than `P` blocks: initialize every consumed partial or supply its neutral value without reading an unwritten GM record. Hardware `AccPhase`/`STPhase`, when used, must match each accumulator's actual last update and supported drain path; they do not choose which products are accumulated. Validate all dependent outputs at the original criterion and time the complete partial-store/merge path before retaining the candidate.

Revalidate the complete chain at the unchanged criterion, then compare representation cost and native execution paths using [thin-row contractions](gemm.md#thin-row-contractions-compare-arithmetic-and-transport-paths). The [projection/normalization example](../../examples/algorithms/mla_prolog/) demonstrates these choices; its component count and tiling are scoped to its contract, not defaults for another kernel.

Stop adding residual components when the reconstruction residual is exactly zero: further components cannot recover a producer error already present in `x`. To screen precision plans before device implementation, replay the complete expression on CPU with the proposed storage conversions, component construction and reduction order explicit. Grade every dependent output through the supplied comparator, including its native-reference input when required. A failing model rules out that modeled arithmetic, not every device implementation; a passing model prioritizes a candidate but does not validate the backend's reduction order, conversions, underflow or timing.

### Localize errors by stage substitution

First validate the [reference/evaluator path](../workflows/authoring.md#reference-and-evaluator) and the [diagnostic transport](../verification/board-runs.md#diagnostic-probes). Choose statistics over the actual failing region: relative errors in a normal region and absolute errors near zero or cancellation, as defined by the supplied checker. Retain elementwise signed errors before reporting percentiles or maxima; a bulk statistic that excludes the failing elements cannot identify their source.

For `B -> C`, let `b_ref` be B's independent reference output, `b_dev` its observed device output, `C_ref` the reference consumer and `C_dev` the device consumer. Preserve all contract-required rounding at each boundary. With `truth = C_ref(b_ref)`, evaluate on the same inputs:

```text
e_inherited   = C_ref(b_dev) - truth
e_own         = C_dev(b_ref) - truth
e_total       = C_dev(b_dev) - truth
e_interaction = e_total - e_inherited - e_own
```

These substitutions require C to accept the proposed boundary representation. If injecting `b_ref` needs a narrowing conversion, treat that conversion as a separate stage and measure its error; silently casting it cannot isolate C's own error. Check like-for-like axes, validity and pre/post-scale values, and keep the original complete-chain verdict as the acceptance result.

The signed decomposition is an identity; root-sum-square attribution is not. `rms(e_total)^2` is approximately the sum of the inherited and own squared RMS values only when the interaction is negligible and `mean(e_inherited * e_own)` is negligible (for example, approximately zero-mean, uncorrelated errors). Maxima, percentiles and per-element absolute errors do not add in quadrature. Inspect the interaction or use additional substitutions when those assumptions fail. After repairing one stage, revisit candidates previously hidden by its error. Where an output branch does not depend on the changed stage, retain it as an internal unchanged-output control.

### Calibrate mathematical and native references separately

Converting inputs to FP64 before calling a reference does not establish an FP64 oracle: an internal `.float()`, library call or output cast can restore FP32. Trace the complete caller/helper type flow. Keep a separate mathematical implementation when needed for diagnosis, and retain the specified native reference and checker as the acceptance target.

For example, the exact sum of `[0.5, 2^-25, -0.5]` is `2^-25`. An explicitly ordered round-to-nearest-even FP32 left fold first rounds `0.5 + 2^-25` to `0.5`, then returns zero. An FP64 sum retains the residual. This witness distinguishes those two arithmetic models; it does not specify the reduction tree of an arbitrary CPU sum. Make the downstream output sensitive enough to reject the wrong model, for example with a contractual bias causing cancellation. A witness hidden below the final absolute tolerance cannot qualify the reference.

When reproducing a native reduction is actually required, qualify the library build, CPU dispatch/ISA, full matrix/reduction dimensions, vector grouping, tail merge order and FMA mode. Changing a CPU GEMM's M or a reduction's tail can change its dispatch or arithmetic even when only one row is inspected. A CPU simulator verifies only its tested CPU branch. Likewise, a Host capability guard that rejects execution is an entry/runtime failure, not a measured precision mismatch; deleting it does not establish the missing arithmetic qualification. Unknown environments remain unqualified until supported by an independent comparison. More accurate real arithmetic and faithful reproduction of a prescribed finite-precision program are different objectives.

### Budget residual products through the full consumer

For two decomposed operands, write the intended expression explicitly: `(Ah + Al) @ (Bh + Bl)` has four products. Omitting `Al @ Bl` needs an error budget, not the phrase “high/low representation.” Its exact-arithmetic omitted contribution is bounded elementwise by `abs(Al) @ abs(Bl)`; include reconstruction, product and accumulation errors too. Low components, scaling and cross-products need their own exponent bounds. An exact decomposition of bounded FP16-scale times a small integer does not prove that two BF16 components reconstruct arbitrary FP32 data, nor that all product partial sums are exact.

Preserve high/low information until the cancellation point that needs it. Rounding each partial to the output dtype before adding can lose a residual that a single final conversion would preserve. Test signed scales, representable extremes, tiny/subnormal values and near-zero final results, then every nonlinear/discrete consumer under the original checker. A zero reconstruction residual excludes further representation error, not a producer error or disagreement with a prescribed native reference. Use [stage substitution](#localize-errors-by-stage-substitution) to distinguish them before adding more components.

## 2. Small magnitudes in normalized ratios

A finite floating-point interval includes subnormal values unless the contract excludes them. The smallest positive normal value (`np.finfo(dtype).tiny`) and the smallest positive representable value (`np.nextafter(dtype(0), dtype(1))`) are different boundaries. Derive the permitted range for each input and their products before choosing an arithmetic path.

Trace every divisor, including those introduced by an algebraic rewrite. A positive epsilon in one denominator does not protect a later data-dependent scale. An externally rounded statistic may also be unsuitable as an internal divisor: underflow of that output is not proof that the mathematical input group is zero. Retain well-scaled internal state where the consumer's contract needs it.

An accurate-looking small scale does not establish an accurate normalized output. If both a numerator and its normalization statistic are tiny, flushing either operand or an intermediate to zero can change an order-one ratio into zero or a nonfinite value. Check the ratio and its consumers directly, including exact/discrete outputs, rather than relying only on an absolute tolerance for the scale. Include allowed tiny normal values, subnormal values, mixed signs/zeros and a nonzero normalized result; an all-zero control alone cannot expose this failure.

**Make the boundary probe discriminate the failure.** Uniform nonzero inputs may all normalize to a clipping endpoint; division by zero followed by integer conversion and clipping can then produce the expected endpoint by accident. Include distinct nonzero magnitudes with expected interior outputs as well as endpoints, both signs and zero. Check the constructed input's bit patterns and the independent expected output categories, so a test named “tiny” cannot silently become an all-zero or saturation-only control. Use more than one exponent: the smallest representable value alone does not exercise every underflow path.

**Combine the ranges of interacting inputs.** Testing each operand's extrema separately misses products and masked contributions. Within one output's reduction domain, include widely separated magnitudes and zero factors: the largest value of one operand can multiply zero in another, while the nonzero products remain tiny. Normalizing one factor by its own maximum can erase those products before the final ratio is formed. Trace and bound the complete expression, including every transformed intermediate and zero-set test, rather than assuming that a well-scaled operand statistic guarantees a well-scaled consumer.

For a normalization homogeneous in its inputs, a common positive power-of-two factor can move the numerator and denominator into a normal range while leaving their real-valued ratio unchanged. Derive exponent bounds from the full stated input domain, reduction extent and every intermediate; check overflow as well as underflow. Restore the factor for any externally returned statistic, keep the zero-set convention explicit and preserve mandated intermediate rounding. This is an implementation candidate to verify on the actual arithmetic path, not permission to change the input contract or tolerances.

The [residual_rms_quant example](../../examples/algorithms/residual_rms_quant/) provides one bounded-domain implementation and independent tests for these principles. Its source header owns the exponent bounds, physical mapping and toolchain scope; its particular scale factor is not a default for other kernels.

Validate scale restoration through the final storage dtype. A representable BF16 result can be lost when restoration first produces an FP32 subnormal that the chosen path flushes. [Bounded MLA](../../examples/algorithms/mla_bounded/) retains a scaled FP32 product through an explicit nearest-even BF16 encoding stage; its finite-domain encoding and additional native call are part of the contract and timing. Test normal/subnormal boundaries and both signs. An oracle that converts FP64 through FP32 before BF16 can itself double-round near these boundaries; compare exact neighboring representable values when checking the rounding rule bit for bit.

### Positive floors and factor cancellation

For a finite common factor `c > 0`, let `u_i = c * v_i`, `m = max_i(abs(v_i))` and `D = max(c * m, tau)` with `tau > 0`. In real arithmetic, `u_i / D = v_i / max(m, tau / c)`. Replacing the denominator with `m` drops the floor-active branch; guarding only `m == 0` does not restore it. A zero-only fallback and a positive floor are different contracts. Transform the floor with the factor, or prove that the floor is inactive throughout the supported domain before removing it.

Preserve any separately returned scale and any prescribed intermediate rounding points. The real-arithmetic identity does not establish identical floating-point or quantized outputs: division by a rounded scale and multiplication by a separately computed reciprocal can cross different integer rounding boundaries. Retain the supplied exact/discrete criterion and verify the chosen arithmetic path rather than widening its tolerance.

Include nonzero maxima below, at and above the floor, as well as the contractual zero case. Use mixed magnitudes with expected interior quantized values: correct zeros or clipping endpoints alone can hide a lost contribution or an invalid division. Compare the returned statistic and final discrete outputs separately.

### Locate a discrete-output disagreement

Passing a tolerance on a returned scale does not establish an exact quantized output. Record the mismatching coordinates, reference and native pre-round quotients, and their distances from the relevant rounding boundary. A few FP32 ULPs can move a value across a half-integer while both scales pass a floating criterion. Matching storage dtype or requesting a higher-precision primitive does not establish the same reduction tree, intermediate rounding or backend arithmetic as the reference. Preserve the supplied integer criterion and compare the actual rounding mode, clipping and conversion separately.

Dump values inside their owning stage and first verify that instrumentation leaves the original outputs unchanged. For a consumer `Q(payload / scale)`, run a controlled 2×2 diagnostic with payload and scale independently selected from the reference or the native producer, keeping the consumer, data, dtype and launch fixed. The native/native cell must reproduce the original quotient and discrete output before interpreting the split experiment. In each cell, also apply the reference consumer to the same selected inputs; passing only the reference/reference cell does not validate the consumer on different native inputs. CPU/reference-stage inputs are diagnostic controls; they are not a production implementation or device-performance evidence.

If the reference/reference cell passes while the native/native cell fails, investigate the producers and their interaction before blaming the conversion. Mixed cells distinguish sensitivities to payload and scale, but cannot by themselves identify the first incorrect upstream operation. Check the consumer's observed quotient against the required rounding/clipping rule: agreement there separates a correct discrete conversion from an earlier arithmetic difference. If the reference/reference cell fails, isolate the consumer's division and conversion using identical stage inputs. Preserve positive scale floors and prescribed rounding points throughout; cancelling a common normalizer or adding a rounding bias is a new numerical algorithm requiring its own contract proof.

### Certify a discrete decision before taking a fast path

Locate the first comparison, floor, winner, index or discrete conversion that can change the downstream set. Recovering exact payload values after selecting the wrong set cannot repair it; see [selection keys versus payloads](../patterns/ordered-selection.md#exact-payload-recovery-cannot-repair-lossy-selection). A sampling weight computed accurately after a wrong floor still reads the wrong cells.

For a finite decision quantity z enclosed by `[L,U]`, `z>threshold` is certainly true when `L>threshold`, certainly false when `U<=threshold`, and otherwise unknown. A floor is determined when both interval endpoints have the same floor and the index representation covers that range. The bound must cover the quantity required by the reference, including prescribed intermediate rounding; enclosing only the exact real expression does not qualify a different finite-precision reference. Ordered NaN comparisons, ties, clipping and epsilon need their original rules rather than an invented interval convention.

An unknown result triggers precise repair or the original correct path. Retain the original operands or a proved lossless representation until that choice completes; repair cannot reconstruct discarded low information from a rounded root. Prove the error bound, repair arithmetic, native operations and all outputs on the selected Pro/toolchain version. [Bilinear sampling](../../examples/algorithms/bilinear_sampling/) supplies integer-neighbor and adjacent-ULP controls, while [Top-2](../../examples/algorithms/row_top2/) supplies exact index/payload controls; neither currently implements this interval-certificate/repair path.

Measure certificate and repair at the actual execution granularity. A first-order branch model is `T_cert + p*T_fast + (1-p)*T_repair` only when those branches execute exclusively; unconditional/speculative work and merges belong in the terms that actually execute. If a whole 64-lane block needs every lane to qualify, a hypothetical independent 98% lane rate gives only `0.98^64`, about 27%, whole-block success. Real lane correlations and fallback costs need measurement. Test both sides of boundaries, unknown cases, tails and changed inputs; measure the complete call at the original criterion before retaining the shortcut.

## 3. Centering and accumulation order

For centered statistics, choosing a stable formula and choosing an accumulation order are separate decisions. Subtracting two large raw moments can lose a small variance even when each moment is individually accurate. A centered second pass or a mergeable centered aggregate avoids that subtraction, but still needs bounds and validation for its sums, merges and finalization. A shift near the data can help; an arbitrary first sample can also be an outlier. Track the error when a large shift is restored to a small final result. Clamping a negative result to zero does not repair lost information.

List the reduction hierarchy: terms within a lane, lanes within a register, registers within a transfer, transfers within a row, and any cross-worker merge. A source sequence of opposing signs can become large same-sign lane sums, followed by one cancellation-prone horizontal reduction. Bound the error of those partials before that final subtraction. Compensation applied at one level cannot recover information already lost below it. Pairwise merging, compensated summation and multiple independent partials are candidates with different arithmetic and dependency costs. When reducing less frequently for performance, bound the longer per-lane sums and recheck cancellation; a positive sum of squares and a signed sum need not use the same strategy.

Exact-output clauses need their own arithmetic argument. For example, a mathematically constant input need not have exactly zero computed deviation from a rounded mean. Verify nonbinary constants and awkward counts as well as powers of two. To distinguish stability failures from indexing failures, place an outlier first and last, perturb opposing large terms so their expected sum is small but nonzero, and permute the same multiset across lane/chunk boundaries. These transformations preserve the mathematical statistic while changing the numerical reduction path. Compare each output to an independent higher-precision reference at the original tolerance; do not require bitwise equality across valid floating-point reduction orders unless the contract does.

**Check the probe's sensitivity after finalization.** Quantify the result if the small contributions are lost, then compare that error with the actual output tolerance. A perturbation of one term can disappear below an absolute tolerance after division by a long reduction extent. Choose magnitude and multiplicity within the input contract so the targeted loss is detectable; a named “cancellation” case or a merely nonzero reference is insufficient. A small CPU experiment with deliberately lossy accumulation can check this sensitivity, while only the actual device path establishes kernel behavior. Check constructed input bounds too: adding variation to a range endpoint can accidentally test outside the supported domain.

## 4. Fixed references in bounded exponential normalization

Before selecting a max-based or online normalization, propagate the full contractual score bounds. A common fixed reference `c` gives `w_i = exp(s_i - c)`, denominator `d = sum(w_i)`, weighted output `sum(w_i * v_i) / d`, and logsumexp `c + log(d)`. The same identities apply to dense, gathered and segmented payloads. When the bounds permit this representation, discovering a data-dependent maximum or rescaling state after each term may be avoidable work.

For scores in `[L,U]`, at most `K` terms and `|v_i| <= B`, check the actual backend's exponential interval and these bounds: smallest nonempty denominator at least `exp(L-c)`, largest denominator at most `K*exp(U-c)`, and absolute weighted sum at most `K*B*exp(U-c)`. Require a distinguishable positive nonempty denominator, safe intermediate sums/products, and final errors within the original tolerance. Account for reduction order, any coefficient narrowing, and contributions that may underflow; a safe exponential alone does not prove the consumer safe. Use full-domain bounds, not extrema observed in a sample.

**Check the narrowest representation, and construct inputs that attain the bound.** FP32 `exp` can be finite while a subsequent FP16 coefficient overflows. For a length-128 dot product with inputs in `[-1,1]` and scale `1/sqrt(128)`, all-one operands give a score of `sqrt(128)`; with `c=0`, its exponential is about 81937, above FP16's maximum 65504. Random dot products commonly cancel and miss this legal endpoint. Use aligned/opposed endpoint operands and, for a nonempty normalized weighted sum, a constant payload whose expected output is that same constant. Check the narrowed weights and final consumer for nonfinite values, underflow and quantization error. Agreement with an earlier kernel can preserve the same range defect; it does not replace these independent controls or the supplied checker.

**Solve for the reference, rather than testing only `c=U`.** Let `[a,b]` be a verified exponential-argument interval with positive representable results, and `F` a safe accumulation magnitude below overflow. Sufficient range constraints are `c >= U-b`, `c <= L-a`, and `c >= U+log(K*max(1,B))-log(F)`. Intersect them to obtain a feasible interval for `c`; zero or another interior value may work even when using the upper score bound underflows. Use the maximum reduction extent over the whole contract, not only the timing shape. State the instantiated bounds and chosen reference in the kernel's numerical comment. A nonempty interval establishes range feasibility, not the final accuracy: validate endpoint, cancellation and long-reduction cases at the original tolerance before measuring it.

Partials using the same reference can merge their denominators and weighted sums directly; different references require rescaling. Empty domains still need their contractual outputs. If the full range proof fails, retain a data-dependent stable reference. Validate endpoint and constant-score rows as well as varying scores, then compare complete calls, including any shared-coefficient materialization, scheduling and merge tasks. A fixed reference is a candidate justified by a bounded contract, not a universal softmax setting.

## 5. Representation-preserving outputs

Separate approximate arithmetic, exact numerical values and exact bit patterns. Floating `array_equal` treats positive and negative zero as equal; allowing equal NaNs also ignores their payloads. For bit preservation, first check dtype/shape, then compare contiguous byte or same-width unsigned-integer views without a numeric conversion. For example, FP16 copies can use `assert_array_equal(actual.view(np.uint16), expected.view(np.uint16))`. Seed preserved regions with both zero signs and subnormals; include distinct NaN payloads and infinities only where the contract permits them. Constraints on computed inputs need not constrain untouched destination storage.

For a partial transform or conditional update, the reference must define both the transformed/written region and its complement. Derive the complement from the original input or pre-call destination as required, rather than leaving a zero-initialized reference buffer. Check the reference's identity/no-update parameter cases before blaming a device mismatch. Repeat on the same storage with changed runtime metadata, and compare untouched bytes as well as computed values.

## 6. Reproducible reductions

Separate the required accuracy from the required reproducibility. Repeated floating atomic sums that happen to agree do not prove schedule-independent bits. A fixed logical reduction order/tree, independent of worker arrival order, is one candidate; integer accumulation is another only when the complete representation satisfies the numerical contract. See [indexed ownership](../patterns/multi-output-reductions.md#reproducible-indexed-reductions) for the work mapping.

For bounded approximate sums, quantizing a computed term to a multiple of a power-of-two step `h` can permit exact integer accumulation. With nearest rounding and at most `L` terms, budget `L*h/2` for quantization, plus term evaluation and final conversion error. Prove that every partial sum fits the integer type using the sum of absolute integer contributions, not just the final signed result; cancellation does not prevent intermediate overflow. Verify the actual rounding mode and conversion range on the installed backend. Choose a feasible step from the entire contract, rather than observed input magnitudes. This changes the arithmetic and is unsuitable when prescribed intermediate rounding, exact values or a tighter error bound exclude it.

Test coherent small terms near quantization boundaries, both signs, maximum same-sign sums and small residuals after cancellation. Check that a deliberately lossy alternative would exceed the supplied bound; random errors may cancel. Accuracy, reproducibility and speed need separate evidence: exact integer updates can still be costly or highly contended.

## 7. Special values and branch semantics

When the contract permits NaN or infinity, inspect their positions and required signs before finite-error summaries. Follow the supplied comparator's actual special-value rules; a zero reported norm can coexist with a NaN-position failure. First distinguish extra NaNs from missing NaNs. A missing NaN may have been replaced by a finite default, rather than produced by an invalid address. A poison/write-coverage test cannot expose that substitution: the output was written, with the wrong value.

Build a branch truth table for positive, zero, negative and NaN inputs before changing a protective guard. For example, with ordered comparisons, `den > 0` is false for NaN as well as zero/negative values; selecting a zero output on that false branch can erase a NaN that the reference propagates. This is different from detecting an empty domain. Preserve the contract's empty-domain predicate and exceptional-value behavior separately, and test the safe-denominator selection and final output selection together. Do not universally replace one comparison by another: the negative-value convention and target comparison/select behavior still need verification.

Likewise, `x == x` rejects NaN but admits both infinities. Applying a finite residual identity to an infinite value can then create `Inf - Inf = NaN`. Use a verified finite-value classification or a separately defined exceptional path before such arithmetic; do not assume a zero multiply or another algebraic test survives compiler transformations with the desired NaN behavior. Include all permitted exceptional sources, such as scales and coefficient tables, rather than testing only the main data tensor.

Do not infer a device float-to-integer result for NaN/Inf from a Host cast. Check the chosen conversion's documented range, saturation and exceptional-value behavior, define the contractual handling before conversion, and test the actual path. For comparison probes, include known finite control rows, both infinity signs and NaNs with initialized transport under the [probe controls](../verification/board-runs.md#diagnostic-probes); plausible-looking unwritten output cannot establish comparison semantics.

### Masking arithmetic and proving a shortcut are separate tasks

`0 * NaN` does not clear a lane. Distinguish an instruction that preserves an inactive destination, zeroes it, skips an access, selects a reduction participant or selects a completed result. Verify the actual Pro instruction and physical predicate positions; another frontend's default mask behavior is not that contract. Initialize every lane a later unmasked load/reduction observes, and keep the task's required NaN propagation distinct from padding cleanup. An inactive contribution whose reference still evaluates a NaN product cannot universally be replaced by zero.

A data-derived shortcut needs a sufficient predicate over the full relevant domain plus a correct fallback. For an all-zero softmax candidate, an exact raw-carrier test can OR every element after excluding only the sign bit; zero then admits both zero signs and rejects every nonzero magnitude, Inf and NaN. This is a proof of the input condition, not a dtype-conversion recipe or a constant-output assumption based on shape. Validate the constant result through the actual reference rounding. Read the entire certified domain before selecting the shortcut; on failure run the complete algorithm without consuming unwritten or destructively overwritten input.

Measure the certificate, reduction/flag publication, branch, output fill and fallback in the complete call. A separate scan plus template initialization can cost more than the original reduction. Fusing certification with an already required traversal/output fill is a different candidate, with changed scratch and last-reader lifetimes to prove. Test first/last nonzero elements, both zero signs, NaN/Inf, tails, several blocks and repeated slot wraparound. This is a conditional design recipe, not a newly validated Pro softmax implementation.
