# Tools

The optional [local MCP server](mcp.md) exposes these same CLI implementations through `check.py mcp`. It adds transport, process supervision and a measured output budget; semantic contracts remain here and in their linked owners.

The bundled [scripts/check.py](../../scripts/check.py) performs static source checks and documentation consistency checks without importing `pypto_pro`, compiling or using a board. Its opt-in `run` subcommand then executes the caller's command, which may use the installed framework/device. Implementation and tests live in `scripts/_checks/` and `scripts/_checks/tests/`. The companion [profile_kernel.py](../../scripts/profile_kernel.py) measures native-task sums, pipe counters and paired synchronized wall time; [timing contracts](../verification/native-timing.md) keep those metrics distinct. The optional [perf_collect.py](../../scripts/perf_collect.py) adds external `msprof` / `msopprof` collection and offline parsers; its boundaries live in [performance collection](performance-collection.md). No-device regressions live in `scripts/tests/` and `scripts/_checks/tests/`. Run these examples from this skill’s root:

```bash
python scripts/check.py                    # rules + knowledge admission
python scripts/check.py query --validate --format json
python scripts/check.py rules [paths...]   # defaults to examples/
python scripts/check.py run --source trial -- python -m pytest trial/test.py -q
python scripts/check.py explain --source candidate.py --baseline baseline.py --function stage
python scripts/check.py explain --source candidate.py --error-log failure.log
python scripts/check.py suggest --source candidate.py  # bounded optimization hypotheses
python scripts/check.py experiment --state /scratch/current.json  # current state, no history
python scripts/check.py coverage           # VF assignments versus actual calls
python scripts/check.py catalog            # matmul/algorithm directories versus selection tables
python scripts/check.py links [paths...]   # local Markdown targets and heading anchors
python scripts/check.py surface            # live API-to-example index
python scripts/check.py api [pl|vf|pl.simt] # live declaration signatures
python scripts/check.py api --check-pyi   # generated API reference freshness
python scripts/check.py api --write-pyi   # regenerate the API reference
python scripts/check.py srcrefs            # source-line references versus ../pypto/
python -m pytest -c /dev/null --confcutdir=scripts -p no:cacheprovider scripts -q                # all tool tests; no device needed
```

From elsewhere, use the script's absolute path; neither PYTHONPATH nor a directory change is required. Explicit relative inputs follow the caller's working directory. Default example/source paths follow the skill's repository layout; `coverage` and `catalog` read this skill's bundled coverage contract and example catalog respectively.

## CLI and MCP modes

CLI is independently usable; MCP is an optional transport over the same commands. Neither mode maintains a second knowledge source or checker. Use an exposed, authorized MCP tool when convenient. If the server is absent, cannot start, or does not expose the needed tool, invoke the corresponding CLI on the execution host without installing MCP first. Ordinary commands do not import its SDK.

Complete example discovery and knowledge admission require `sys.stdlib_module_names` (Python 3.10+) to classify imports without guessing. A query requesting examples, including an unfiltered query, returns an explicit unavailable-runtime result when this capability is missing; repeat it with a capable interpreter. It does not turn unavailable example coverage into an empty successful result or API absence.

In the table, CLI arguments follow `python /path/to/skill/scripts/check.py`; put `--pypto-root` and `--examples-root` before the subcommand. Use the same interpreter, environment, working directory, roots, sources and input metadata as the MCP execution host. If only a local shell is available and the required runtime lives remotely, establish the existing remote execution route before claiming parity. See [MCP setup and input semantics](mcp.md#start-on-the-execution-host).

| MCP tool and principal inputs | Equivalent CLI arguments |
| --- | --- |
| `kernel_search(paths, pattern?, glob?, files?)` | `search --path PATH [--path PATH...] --pattern TEXT [--glob GLOB]`; use `--files` without a pattern for listing |
| `kernel_read(paths?, requests?, start_line?, max_lines?, offset_bytes?, source_sha256?, fragment?)` | `read --path FILE [--path FILE...] [--start-line N] [--max-lines N] [--fragment SLUG]`; use repeated `--request JSON` instead for per-file ranges; continue with the returned hash/offset/fragment |
| `kernel_status(receipt, request_id, source, wait_seconds?)` | `status --receipt JSON --request-id ID --source FILE [--wait-seconds N]` |
| `kernel_query(text?, kinds?, filters?, limit?, cursor?, reference_sha256?, source?, task?, goal?, validate?)` | `query [TEXT] [--kind KIND...] [--filters JSON] [--limit N] [--cursor TOKEN] [--reference-sha256 SHA] [--source FILE] [--goal GOAL] --format json`; separate modes are `query --task MANIFEST [--goal GOAL]` for a declared task inventory and `query --validate --format json` for knowledge admission |
| `kernel_check(sources)` | `rules FILE... --format json` |
| `kernel_native(spec)` | `native --spec SPEC --format json` |
| `kernel_run(sources, argv, native_spec?, cwd?)` | `run --source FILE [--source FILE...] [--native-spec SPEC] --format json -- COMMAND ARG...`; launch from `cwd` |
| `kernel_suggest(sources, measurements?, limit?, goal?)` | `suggest --source FILE [--source FILE...] [--measurements JSON] [--limit N] [--goal GOAL]` |

| `kernel_experiment(state, action, input?)` | `experiment --state STATE`; add `--init INPUT`, `--select INPUT`, `--observe INPUT` or `--export-best DIR` for that action; `show` needs no extra flag |
| `kernel_claim(spec)` | `claim --spec CLAIM_JSON`; source/workload/metric consistency of a supplied performance assertion, no execution |

Optional `details` maps to `--details` on commands that expose it. MCP output budgets and timeouts belong to the adapter, not CLI flags; preserve an explicit command watchdog/device lock when using CLI execution. Both modes retain the source/native gates and original child status. MCP additionally reports delivery status; its [result contract](mcp.md#result-budget-and-failure-contract) distinguishes a complete report from an interrupted or oversized response.

| Observed situation | Next action |
| --- | --- |
| Host returns a running command/session | Wait or poll that session until it exits. Starting the same verifier again duplicates pending work; a running session is not a completed failure |
| No server/tool, startup failure, or missing MCP SDK before dispatch | Use the equivalent CLI within the already authorized scope |
| Host rejects an operation for permission/approval | Respect the rejection; switching transport is not permission to perform the rejected operation |
| Query/check/suggest/explain response is lost | Retry the read-only operation through an available mode with the same inputs; recheck source identities |
| Native import, run or state mutation times out, disconnects, or exceeds the response budget | Inspect the owned process, explicit artifacts and `experiment --state STATE` first. A missing response does not mean the operation never ran. Do not automatically replay it; resolve an unknown outcome with the execution controller |
| CLI is also unavailable | State the missing environment/access and continue supported source/document work; do not claim execution or numerical acceptance |

There is no automatic mode-switching executor or hidden retry queue. The agent selects the available interface; the same execution authorization applies to both.

## Bounded context I/O and existing execution status

`search` and `read` operate on explicit paths within configured roots. Their default serialized CLI reply limit is 12 KiB, including JSON metadata and its newline; `budget.result_bytes` is measured UTF-8 bytes, not tokens. Search also limits enumerated files, scanned bytes, individual file size and matches. Search uses ripgrep without importing source. `status: partial` and incomplete coverage mean that absence was not established; narrow the path/glob or read the relevant lines instead of repeating a whole-workspace search. A missing backend is an explicit error. Search matches carry the SHA of the bytes searched.

`read` returns original UTF-8 `text`, a source SHA, byte offsets and an absolute `start_line` for each item. `numbered_text` presents the same delivered bytes with an absolute `line|` prefix on each source line, including blank lines; use those positions and the returned SHA for citations rather than manually counting lines or transcribing hashes. Both views count toward the reply byte limit. `start_column_bytes` is the zero-based byte position within the first source line, so a continuation can explicitly identify a partial line. Line prefixes and a valid hash identify the original passage, not whether a claim follows from it; inspect the signature, guard and product/version conditions belonging to each statement. Use literal `--start-line` / `--max-lines` values or per-file requests for another range. An explicit `--max-lines` request is complete when that range is delivered, even if `file_complete` is false; a source excerpt does not require consuming the rest of the file. Without `--max-lines`, the request covers the remaining file subject to the page limits. `next` supplies `offset_bytes`, `source_sha256` and, for an explicit range, remaining `max_lines`; preserve these fields on continuation. A changed file invalidates it. A long line can span pages. `remaining_path_index` identifies unvisited inputs when a multi-file read stops. Missing, binary or oversized inputs do not become empty successful reads.

For Markdown, `--fragment SLUG` selects an ATX heading subtree or explicit HTML anchor in one file, using the same slug rules as `links`; Setext and generated headings are outside this reader. Duplicate headings use suffixes such as `usage-1`; percent-encoded Chinese fragments are accepted. Fenced code headings do not participate. An adjacent explicit anchor includes its following heading; a standalone anchor ends at the next heading. Missing or ambiguous fragments fail explicitly instead of reading the whole file. Do not combine a fragment with a `start_line` override. A partial fragment read returns its fragment together with the hash/offset; preserve all three so continuation cannot enter the next section. Batch `requests` accept the same `fragment` field. Roots, UTF-8 byte accounting and existing read budgets still apply.

For different file ranges, use repeated `--request '{"path":"owner.md","start_line":180,"max_lines":30}'` arguments instead of `--path` and global ranges. MCP accepts the same objects in `requests` instead of `paths`. All requests share one scan/reply budget. Each result carries `request_index`; a partial page's `next.request_index` identifies the unfinished request, while `remaining_request_index` identifies the unvisited tail. Continue that page with its hash/offset before reading the tail. The adapter also batches literal mixtures of `cat`, supported `sed -n` and `head -n` separated only by `&&`; command expansion, other execution and combined pinned receipts remain outside that batch form.



```bash
python /path/to/skill/scripts/check.py search --path /path/to/pypto/python/pypto_pro/ir/op --pattern FP16 --glob '*ops.py'
python /path/to/skill/scripts/check.py read --path /path/to/owner.md --start-line 180 --max-lines 40
python /path/to/skill/scripts/check.py read --path /path/to/owner.md --offset-bytes 12000 --source-sha256 SOURCE_SHA
python /path/to/skill/scripts/check.py read --path /path/to/owner.md --fragment usage-1 --source-sha256 SOURCE_SHA
python /path/to/skill/scripts/check.py status --receipt /scratch/verification-state.json --request-id EXISTING_ID --source /scratch/candidate.py --wait-seconds 20
```

`status` never launches a command. It waits at most 30 seconds on the requested ID and the current source SHA, reporting elapsed time, receipt reads and the original exit code. A matching terminal receipt yields `status: observed`, `terminal: true` and process `outcome: passed|failed`; the CLI read operation exits zero for either terminal outcome. `native`, `numerical` and `performance` remain unestablished. Missing/partial receipts, replaced IDs, source changes and unknown states remain unverified; a wait budget ending on a running request is pending. Receipt fields are `request_id`, `source_sha256`, `state` (`queued`, `running`, `completed`, `failed`, `cancelled`) and a terminal integer `exit_code`. These are controller claims, not authenticated kernel acceptance. Keep executing source immutable; the reader cannot detect edits reverted between samples.

Use `--policy` on `search`, `read` and `status`, or server startup `mcp --context-policy FILE`, for fixed roots and limits. Relative policy paths resolve beside the policy file. A minimal policy is:

```json
{"schema":"pypto-context-policy/1","roots":["../workspace"],"limits":{"max_output_bytes":12288,"max_files":128,"max_scan_bytes":2097152,"max_file_bytes":524288,"max_lines":120,"max_matches":24}}
```

MCP startup fixes the policy; the model cannot supply another policy as a read-tool argument. This policy governs these context operations, not existing native imports or arbitrary commands. Default roots are the caller workspace, skill, selected framework and examples; every search still needs explicit paths. Path resolution checks symlink targets. Policies and counter/state files containing concrete environment paths belong in ignored local configuration or scratch.

The current action can be declared through the optional [goal and action guidance](optimization.md#action-scoped-guidance). It separates a conditional experiment choice from native, numerical and timing verification; it does not relax any execution or acceptance gate.

### Declared task context

When the controller provides an inventory, inspect it with `query --task /scratch/task-context.json [--policy POLICY]` or `kernel_query({"task":"task-context.json"})`. This is separate from a text/source API query. The controller supplies the inventory from known inputs; the tool never scans directories to create it or executes an artifact. Paths resolve beside the manifest and remain within the fixed context roots. A minimal input is:

```json
{"schema":"pypto-task-context/1","artifacts":[{"path":"candidate.py","role":"source","sha256":"EXPECTED_SOURCE_SHA256"}],"inline_evidence":[{"id":"diagnostic","kind":"synthetic_fixture","value":"The task's supplied diagnostic text, not another file."}],"unavailable":["No native timing evidence was supplied."]}
```

Artifact roles are `source`, `reference`, `diagnostic`, `measurement` and `verification`; inline kinds are `user_statement`, `synthetic_fixture` and `verifier_observation`. Keep the original supplied values and their provenance rather than adding a suggested repair or answer. The inventory describes declared task inputs, not every file accessible in the workspace. `verified_bytes` establishes only the expected SHA. Missing/changed/oversized files remain unverified; the manifest itself is hashed. Inline labels are unauthenticated declarations and never establish native/numerical/performance acceptance. Large inventories that exceed the reply limit fail explicitly or report incomplete artifact coverage; narrow the declared inventory instead of treating omitted data as absent. All context defaults and budgets above apply to this operation too.

### Host read interception

`host-hook --policy FILE --config` prints a Codex hook definition without installing or enabling it. The synchronous `PreToolUse` adapter rewrites supported `rg`, `cat`, `head -n` and `sed -n` reads to the shared bounded CLI. Pure `cat A && cat B` chains become one bounded multi-file read. Standard Python invocations of this skill's `search`, `read` and `status` receive the fixed host policy even when omitted or replaced by the caller. Bulk `api`/`surface` inventories are refused in this context profile; use an exact query or the returned conditional route. Implicit-root searches, unsupported readers/options and other compound source reads receive a short refusal with working syntax; unrelated execution remains unchanged. This is a guardrail for recognized read commands, not a filesystem sandbox: arbitrary Python, alternate programs, shell indirection and hosted tools are outside its coverage. Confirm the actual rewritten command/result in the host before claiming enforcement. The [official hook contract](https://developers.openai.com/codex/hooks) owns discovery, trust and host coverage; a skipped or untrusted hook provides no enforcement. Normal activation requires review of the exact hook definition. Process-local tests may trust only the audited test hook without modifying global settings or execution approvals.

The policy may pin an existing controller receipt:

```json
{"schema":"pypto-context-policy/1","roots":["../workspace"],"receipts":[{"path":"../workspace/verification-state.json","source":"../workspace/candidate.py","request_id":"CONTROLLER_REQUEST_ID"}]}
```

A recognized read of that single pinned receipt becomes the bounded `status` call; explicit status arguments must match the controller-pinned request/source too. A combined receipt/source read must be split. Optional `host-hook --counters FILE` overwrites per-session call, rewrite and refusal counters, without command/output history. `evaluate --events EVENTS --host-counters COUNTERS` binds them to the event session and includes pre-tool attempts omitted from ordinary JSONL. A known hook-trust notice is not a tool action; without matching counters hook-enabled attempt coverage remains unverified. Status replies count their internal receipt reads separately; neither metric substitutes for total host tool calls or input-token telemetry.

## Run a command after source checks

`run` checks every Python file under each `--source` path, refuses empty source sets and static violations, and prints each checked file's SHA256 before starting the command without a shell. It preserves the child's output and exit status (signals become `128 + signal`) and fails a successful command if the selected source set or contents differ at completion. This before/after comparison does not detect edits reverted during the run; keep executing sources unchanged. It creates no report or experiment ledger. Run it on the execution host after synchronization, under the device lock/timeout from local configuration; use `--pypto-root` before `run` when the matching framework source is elsewhere.

The command supplies parsing, compilation and numerical assertions; the runner does not invent those checks. For example, an assertion-based test can validate outputs before calling the native timer, or separate correctness and performance commands can be joined with shell `&&`. An arbitrary child shell can still swallow its own failures with `| tail`; avoid that pipeline and retain the full output. A print-only `FAIL`, a skipped test or source hashes for files the child never imports do not establish a numerical pass. Read [board runs](../verification/board-runs.md#execution-and-evidence-capture) for evaluator calibration, import identity and failure controls. Source advisories keep their existing meaning and require review.

On a nonzero child exit, `run` inspects bounded diagnostic lines for recognized entry-kind, annotation, Tensor rank, group-depth, VF add operand-type and transfer/store-contract errors. Rank matches retain `source_contract_diagnostic` with source SHA, declaration locations and same-name Host allocation ranks. Transfer feedback needs an unambiguous source span and matching descriptors before attaching path-specific context; keywords alone do not prove a Vec→Vec NZ pitch defect. Exact group-depth and VF add diagnostics route to their allocation and dtype owners without assuming an unrelated cause. Quoted source is excluded from matching; unmatched failures keep a bounded raw tail and can offer conditional source-contract reviews. `explain --error-log` uses the same diagnostic routing and transfer matching without importing the source or replaying execution, binding the original log and source SHA; its exit zero means inspection completed. Stdout/stderr remain live and the original failure status is preserved. The final [feedback envelope](../diagnostics/messages.md#tool-feedback-contract) owns review scope and distinguishes the source gate, optional native parse and actual command exit from numerical/performance acceptance.

## Scenario query and native preflight

Prose references written as `pypto/...` resolve against the selected framework source during document discovery. Configure that source with `PYPTO_SRC` or `--pypto-root`; the skill does not require a companion checkout at a fixed repository-relative location.

```bash
python scripts/check.py query 'UB to L1' --source candidate.py
python scripts/check.py query pl.insert --format json
python scripts/check.py query vf.add --format json
python scripts/check.py rules candidate.py --format json
python scripts/check.py native --spec /path/to/native-spec.json
python scripts/check.py run --source /path/to/kernel.py --source /path/to/test.py --native-spec /path/to/native-spec.json --format json -- python -m pytest /path/to/test.py -q
```

`query` matches exact symbols or a maintained scenario's aliases/ordered path terms. Latin abbreviations use word boundaries; reversing the named path does not select the forward recipe. Scenario metadata stays beside its owning reference section; the query reads that body and its example, without a separate knowledge database. `pl.make_tile_group` and `vf.full` also return their focused allocation/dtype contracts; same-type errors do not by themselves prove a broadcast mistake. The UB→L1 pilot returns both move/insert signatures and the [complete handover recipe](../api/datamove.md#ub-to-l1-handover). `--source` adds bounded local transfer facts and resolved group-depth checks, including the allocation owner when required slots are missing. Unmatched queries return exit 2, not a claim of API absence. Relocation still uses `--examples-root` and `--pypto-root` before the subcommand; unavailable companion examples are explicit.

The Acc-to-GM query follows the selected source's literal Store binding: legacy `"a5"` or `NpuArch.DAV_3510`. For an ordinary/quantized table pair, `selected_frontend_store` reads only the ordinary table; it does not infer quantized support from those rows. Missing, ambiguous or computed bindings remain unverified, with source hashes and declaration lines retained.

### Knowledge discovery and exact symbols

The shared [`knowledge.py`](../../scripts/_checks/knowledge.py) defines `pypto-knowledge-query/1`, input kinds/filters and deterministic ranking/paging. Both interfaces call the same `query.report`; MCP only translates arguments to the CLI. Ordinary CLI lookup needs neither the MCP SDK nor a framework import. Examples:

```bash
python scripts/check.py query pl.system.bar_all --kind api --format json
python scripts/check.py query pl.DT_FP16 --format json
python scripts/check.py query pl.MemorySpace.Vec --kind enum_member --format json
python scripts/check.py query --kind contract --filters '{"source_memory":"UB","destination_memory":"L1"}' --format json
python scripts/check.py query 'FP16 to FP32' --kind contract --format json
python scripts/check.py query --kind contract --limit 2 --format json
python scripts/check.py query contract:ub-l1 --format json
```

At least one of `text`, nonempty `kinds`, or nonempty `filters` is required. CLI repeats `--kind`; MCP supplies `kinds: ["contract", "api"]`. `limit` is 1–50, default 10. `filters` is a JSON object with string values for `source_memory`, `destination_memory`, `dtype`, `layout`, `source_dtype` and `destination_dtype`; other keys are rejected. Memory aliases such as `UB`/`Vec`, `L1`/`Mat`, `L0C`/`Acc`, `L0A`/`Left`, `L0B`/`Right` normalize together. Dtype names such as `pl.DT_FP16` normalize to `FP16`. `reference_sha256` pins a document/docstring or example kernel ID read to a discovered lowercase SHA256; it is not a runtime acceptance claim. `query --task` is a separate operation and cannot combine with knowledge text/source/kinds/filters/limit/cursor/reference_sha256. `goal` adds the existing action guidance; lookup does not run a kernel.

The `knowledge` field adds the typed result alongside the existing feedback envelope:

| Field | Contract |
| --- | --- |
| `schema`, `request` | Knowledge schema and normalized text/kinds/filters/limit; the CLI envelope still carries selected-source and checker identities |
| `items[].id`, `kind`, `title` | Stable `symbol:<public-name>` or `contract:<owner-marker-id>`; document IDs use a declared scope and relative path, docstring IDs use the public symbol, and example IDs use the public program's relative `kernel.py` path. IDs exclude the absolute checkout root and source hash |
| `reference` | Absolute original path, SHA256 and real declaration/heading line when available; C++ binding enums omit synthetic AST line numbers |
| `evidence` | `source_declaration`, `maintained_contract`, `official_documentation`, `source_docstring`, `maintained_reference` or `native_example_source`; native, numerical and performance acceptance remain `not_established` |
| `declaration`, `symbol`, `aliases`, `callable` | Original function signature or type/value declaration; `vf` and `pl.Vf` resolve to the same object. Values/members/namespaces have `callable: false`; types/enums use null because construction is not established by lookup |
| `conditions`, `facets`, `missing_facts`, `applicability` | Owner-declared routing conditions and unresolved workload facts. A matching facet is conditional, an absent facet is `unknown`, and a conflicting declared facet excludes the item; neither status proves installed support |
| `relations` | Typed links to symbols, parent namespace/type, owning contracts, documentation/docstrings, diagnostic rule IDs and declared companion examples. A literal document mention is distinct from its primary API owner; neither a link nor an example file is execution evidence |
| `match`, `resolve` | Match reason/score, any contract basis for filter-only API discovery, and the stable-ID query for the item |
| `page`, `corpus_sha256` | Total matches, returned count and `next_cursor`; identity binds consumed source bytes, locations, companion identities, interpreter and checker/source inputs |
| `coverage`, `rejected_conditions`, `missing_items` | Provider scope/errors, declared condition conflicts and missing declared companions. Partial source coverage never becomes API absence |
| `recovery` | On a complete unqualified scenario miss, up to three source-bound programs may share sufficiently distinctive words. These are separate from `items` and do not change lookup status, exit code or acceptance; resolve their original conditions before adapting |
| `content`, `sections`, `source_reconciliation` | Exact document/docstring resolution returns the shared context-reader report and available heading locations. Source statements remain separate and semantically unreconciled; missing content or conflicts do not inherit support from another source |

Public-symbol kinds are `api`, `type`, `constant`, `enum`, `enum_member`, `namespace` and `field`. The provider reuses the generated-reference resolver for selected `pypto_pro.language` exports, exported namespaces, public class members and C++ enum bindings; `pl.parser` internals are excluded. It reads AST/binding declarations without evaluating expressions or importing PyPTO. The `document` adapter reads official Pro material, skill topics and full docstrings as described below. The `example` adapter discovers complete native programs through the shared source-call and catalog implementation. `diagnostic` and `evidence` retain explicit `not_integrated` discovery; checker rules and externally bound observations remain their unique owners.

Ranking uses exact object ID, exact alias, ordered scenario terms, symbol relation, maintained discovery terms, namespace prefix and finally declaration/title words, with explicit reason and stable-ID ties. Explicit qualified public API names inside a question, or a namespace plus a bare name such as `VF addc carry destination`, yield `public_name_hint` candidates from the current exports, their official API pages and their docstrings; multiple named APIs remain separate sources. This does not infer an unmentioned API, select a directional recipe or reconcile those sources. Conditions add a declared-match score; an API found through a contract keeps its own unknown applicability. Broad declaration keywords do not select directional conversion/transfer recipes. `move` can offer several conditional routes; `FP16 to FP32` cannot borrow the reverse narrowing route. This is deterministic matching over declared sources, not general semantic search.

For a longer scenario with no primary result, `recovery` can suggest related programs using original program-source words, owner aliases/scenario terms, small English word-form variants and adjacent Chinese character pairs. Incidental numbers do not contribute to ranking. Program identity comes from its directory title, catalog selection row, kernel's first descriptive line and owner metadata; reference/test bodies and resource mechanics supply supporting overlap. A candidate needs distinctive identity clues or multiple declared scenario groups, so resource words alone do not select an algorithm. Strong identity clues may survive unmatched prose in a long question; otherwise the source-overlap threshold still applies. Matching owner scenario groups precede lexical candidates and exclude weaker tiers from that response. It includes matched/unmatched terms, source hashes, original entry roles, declared facets, static dependencies and SHA-pinned entry/condition reads; overlap is not a support condition. The condition reads select original kernel/reference/test statements independently, so resources, stage order and input scope can be compared without treating ranking as acceptance. Declared dtype conflicts and program exclusions still apply; undeclared filters stay unknown. Named APIs, qualified symbols other than namespaces, exact symbol requests, directional queries and incomplete source coverage skip this recovery path. A namespace-only technical context such as VF or pl.simt requires at least two distinctive identity or owner-scenario clues; the namespace itself supplies neither a program clue nor a support condition. Insufficient evidence yields no suggestions. No persistent index or additional fact registry is maintained; first-query matching and successful recovery remain separate outcomes.

With only legacy text/source arguments, `context`, `signatures` and companion behavior remain compatible. Constants never appear in `signatures`. Explicit kinds/filters/limit/cursor or stable-ID queries use the object page: selected contract IDs/aliases/scenarios return their original body in `knowledge.items[].text`, while weak discovery routes carry `resolve` instead of selecting a recipe. Read the returned conditions before applying a contract. To browse further, repeat the same text/kinds/filters/source and roots with the returned `cursor`; `limit` may change. A source, checker, query or location change invalidates the cursor and requires a fresh read-only query. There is no persistent index or cursor session.

`lookup.status` distinguishes `matched`, `retrieval_miss`, `not_integrated`, `source_unavailable` and `evidence_insufficient` (filter-only lookup without declared routing evidence). `missing_items[].reason: declared_knowledge_missing` identifies a promised companion that is absent. `coverage.metadata` and `coverage.integrity` retain owner-validation and ambiguous-ID findings alongside provider coverage. Invalid or duplicated owners are quarantined; healthy owners can still return `matched` with `lookup.coverage: partial`. When relevant source coverage is incomplete, an empty result is `source_unavailable`, not a complete retrieval miss. `knowledge_absence` stays `not_established` in all cases. No result, a missing relation, a declaration or a maintained contract establishes whole-framework absence, runtime support, numerical correctness or performance.

Semantic request failures return the same feedback JSON in CLI and MCP: `invalid_request` with `reason: invalid_cursor` rejects malformed cursors; `cursor_invalidated` means source/query identity changed or the prior item is unavailable; `source_changed` refuses a mixed snapshot. Retry these read-only operations from a fresh query after checking the selected sources. Command-line syntax errors remain parser errors, and MCP schema violations remain adapter `invalid_arguments`; neither is a knowledge miss.

The small [retrieval fixture](../../scripts/_checks/tests/data/knowledge_queries.json) records expected object IDs, allowed conditional routes and explicit deferred adapters, with tests in [test_knowledge.py](../../scripts/_checks/tests/test_knowledge.py), [test_api_stub.py](../../scripts/_checks/tests/test_api_stub.py), [test_documents.py](../../scripts/_checks/tests/test_documents.py), [test_example_programs.py](../../scripts/_checks/tests/test_example_programs.py) and [test_mcp.py](../../scripts/_checks/tests/test_mcp.py). It is a tool-contract baseline, not an agent or hardware evaluation.

Related-program recovery hints supply the same role and condition reads; they can be used before resolving a complete program report. API queries prefer minimal API examples, then matrix mechanisms, then integrated algorithms; explicitly declared counterexample-only uses rank separately as `negative_control_api`. Source-call presence does not establish a supported combination or a recommendation to copy the program. These retain kernel/reference/test roles, support modules, package initialization, shared `conftest.py` and `pytest.ini` identities. `program.read_requests` independently selects the kernel, mathematical reference and ordinary test; each file also supplies a SHA-pinned `read` request. Exact resolution reads the original kernel through the existing context reader; use `read --request JSON` / `kernel_read.requests` for the reference, test, support modules and content continuations. Metadata and source text are separate pages, as with document discovery. Broad cross-kind queries can exceed MCP's unchanged 32 KiB default: request a larger `max_output_bytes`, such as 65536, or choose kinds/limit and follow the returned cursor. The server reports budget excess rather than silently dropping content.

`dependencies` records external imports, standard-library imports, environment variable names and unresolved local/dynamic loading sites without importing modules, inspecting environment values or checking installed packages. Conditional import presence is not a mandatory dependency assertion; version or optional evaluator requirements remain in the original source statements. Missing entry roles, malformed source/metadata, escaped paths, unresolved local modules and scan limits retain explicit partial provider coverage. Dynamic imports are marked unknown rather than executed. Source guards are unevaluated source conditions, not inferred runtime constraints.

For example, the batched transposed GEMM declares its Chinese scenario alias, FP16→FP32 roles and exclusion of N/K-tail requests beside its original contract and shape guard. Same-timestamp edits, additions, removals and renames are read afresh. A rename changes the path-derived program ID; dangling selection links remain catalog findings. `reference_sha256` pins the selected kernel file, not the entire dependency graph: compare `program_sha256` for graph changes and keep each component's read SHA. File presence, test entry argv, docstring pass claims and linked documentation are source statements only. `validation.status` and native/numerical/performance evidence remain `not_established`; no external execution bundle or historical board result is automatically promoted to current acceptance.

### Knowledge admission and refresh

Run `check.py query --validate --format json`, or `kernel_query({"validate":true})`, before admitting knowledge-source changes. This is a read-only mode, separate from discovery and task inventory; it accepts neither their text/source/filter/paging arguments nor `goal` or a task-context policy. The no-subcommand repository check runs source rules and the same admission gate. Relocated source-only checks remain available through `rules` and `run` without requiring every linked document or example.

The shared [metadata validator](../../scripts/_checks/query_metadata.py) and [admission checker](../../scripts/_checks/knowledge_admission.py) consume the existing collectors and matcher. The gate checks owner schemas, unique object/candidate IDs, declared companions, program roles, integrated relation targets, Markdown fragments, exact-ID round trips and declared alias/scenario witnesses. Witness checks follow result pages so an owner beyond the first page is still tested. It also reuses `links`, `catalog`, `coverage` and the generated API reference freshness implementation; no parallel inventory or copied API contract is maintained.

An owner declaration uses a single-line `<!-- kernel-query: {JSON} -->` comment immediately before its ATX heading. Required `id` is a lowercase token of letters, digits, underscores or hyphens. Optional fields are `aliases`, ordered `term_groups`, `symbols`, `rules`, `example`, `when`, `missing_facts`, `review_symbols`, `discovery_terms`, `discovery_aliases`, `facets` and `candidate`. String-list fields contain nonempty strings; term/review groups contain nonempty lists; `review_symbols` requires an explicit `when`. Public-symbol spellings normalize `pl.Vf` to `vf`. A companion `example` names a public relative `kernel.py` under the selected library. `candidate` uses the existing [optimization metadata contract](optimization.md#bounded-candidate-lookup). Example markers use only the fields in the [program contract](#complete-example-programs). Unknown fields, duplicate JSON keys, non-finite values, invalid types and malformed markers fail admission with the owning path, line and consumed source identity.

Every owner sharing a duplicate ID is quarantined. Queries retain healthy objects and explicit partial coverage; they do not choose the first duplicate as a signature, document read or contract. Shared aliases instead appear as `routing_overlaps` with `conditional_alternatives` and both owners' references. They require checking each owner's conditions and are not automatic semantic contradictions. `source_reconciliation` and semantic conflict assessment remain `not_assessed`. Inferred source calls/mentions outside selected exports are listed as unresolved with source locations; deferred diagnostic relations are counted separately. Neither establishes that an API is absent or unsupported.

The feedback stage is `knowledge_admission`, with `admission.schema: pypto-knowledge-admission/1`, object counts, relation checks, `queryability.objects_checked`, `declared_routes_checked`, overlaps and maintenance-gate results. Exit 0 means static admission passed; exit 1 means blocking findings; exit 2 means an invalid request or unverified source when there is no blocking finding. A broken local link can still be a blocking finding when another provider is incomplete. Admission establishes structure, declared routing and consumed-source identity, without importing PyPTO, executing examples or validating installed support, numerics, timing or agent effectiveness.

Queries and admission read current bytes on every call, then verify consumed source identities before returning. Source edits invalidate pinned reads and cursors even when size and timestamps are unchanged. A document/program rename changes its path-derived ID; update incoming links, selection rows and owner relations together. Stable symbol/contract IDs remain tied to their declarations. The next call sees additions, deletion, repaired metadata and rename results without rebuilding an index. There is no persistent derived cache; existing scan/read/MCP budgets remain in effect. CLI admission requires no MCP SDK; the same `kernel_query` mode serves every admitted document or program without adding tools per source.

### Native preflight

The source checker follows direct TileType/make_tile/group declarations, common group-slot accessors, simple constant expressions, direct tuple bindings and local aliases in recognizable JIT bodies. It reports ND→NZ/ZN UB→L1 as an address-map advisory: a prepacked view may be intentional. A directly resolved, unconditional Vec→Vec move into a non-16-aligned NZ destination is a hard error only when the selected frontend's exact pitch-guard source is recognized; changed/missing source or unresolved control flow yields an advisory requiring native verification. It does not demand an odd pitch for ordinary handovers. Helpers, parameters, namespace shadowing and control-flow rebindings remain unverified. A descriptor is not evidence that its producer wrote the expected bytes.

`native` takes a JSON input specification; relative entry paths resolve beside that specification, not the caller's cwd. For the pilot kernel, the contents are:

```json
{
  "entry": "/path/to/ub_l1_handover/kernel.py:handover",
  "args": [
    {"shape": [64, 128], "dtype": "float16"},
    {"shape": [128, 16], "dtype": "float16"},
    {"shape": [64, 16], "dtype": "float32"}
  ],
  "block_dim": 1,
  "tiling_key": {"ROWS": 32, "DIRECT": 0}
}
```

Tensor metadata constructs CPU tensors for native binding; numeric scalar arguments are also supported. This first adapter does not represent pointer arguments, noncontiguous/aliased tensor storage or dtype-key specialization. Importing the explicit entry executes its Python module, so keep launch code behind a main guard. The adapter invokes guarded [native parsing adapter](../../scripts/_checks/native_capture.py), including the native transform and parser, without invoking a launcher or device code generation. It imports only the installed PyPTO runtime and the helpers bundled here; no simulator package is required. Unsupported descriptor node kinds leave inspection coverage explicitly incomplete. Framework operand/type/capacity restrictions remain owned by that parser. Captured transfer descriptors provide additional layout advisories; they are not a full lifetime or physical-access proof.

The adapter records installed Python/native-library identities and verifies that the selected framework source matches the relevant installed files. Missing capabilities or source mismatch return exit 2 and block `run --native-spec`; an error returns 1. For `run`, include the spec's entry in `--source`, and keep the executed command's entry/arguments consistent with the preflight. Spec/source changes invalidate the result. Native success establishes parsing only; use the original evaluator for numerical acceptance.

Missing metrics stay null. The [agent evaluation protocol](../verification/agent-evaluation.md) owns trial isolation, grading and metric interpretation.

## Source-bound contract and work inspection

`explain` reads Python AST without importing the candidate or using a device. It returns JSON on stdout and creates no report file. Use `--error-log` to associate recognized runtime rank errors with declarations and allocations; use `--baseline` to inspect changed module bindings and added/removed work sites. `--function` selects a function name or qualified nested name, keeping a large kernel's report focused. Each source and supplied error log is hashed.

Work sites include native transfers/compute/synchronization and Host allocation/initialization, with lexical loops, branches, expressions and source lines. Static site counts are not dynamic call counts. Tile declarations and bindings help the model derive the actual work at the chosen workload; unresolved invocation counts and transferred bytes are `null`, never zero. Helpers, runtime specialization, alias shadowing, physical access footprints and generated schedules remain outside this syntax report. A changed AST is not proof of a structural speedup. Use the [mechanism comparison](../diagnostics/performance.md#test-a-mechanism-with-source-bound-evidence) and existing native pipe/timeline evidence to choose a discriminating next test.

## Lexical name checks

`rules` and `run` use the optional Pyflakes version pinned in [requirements-checks.txt](../../scripts/requirements-checks.txt) to reject `undefined-name` findings before invoking the child command. Install it in the Python environment running the source gate:

```bash
python -m pip install -r scripts/requirements-checks.txt
```

The check never imports the candidate or PyPTO. It catches names without a Python lexical binding, including stale accumulator names after a rewrite; unused imports and style warnings do not fail this gate. Missing or unsupported checker versions leave name coverage explicitly unverified while other rules remain usable.

The rule does not prove definite assignment on every control-flow path, factory return values, imported-module availability or DSL binding semantics; framework parsing and numerical checks remain necessary.

## Static rules

`nested-worker-restart` is an advisory for a JIT `pl.range(start, stop, step)` nested in another native range when `start` is a direct block ID, a singly assigned local alias, or `base + worker`. It does not infer runtime group sizes, step/launch agreement, capacity, unique writers, load ordering or performance. Rebound aliases, helpers, nonlinear mappings, and functions shadowing the language import are outside its scope. Keeping the same owners to reuse operands is legal; the finding does not fail `rules` or `run`.

## Scope and known limits

- Group-depth inspection covers direct declarations and native Cube/Vector sections. Conditional branches, loops, helpers, namespace rebinding, dynamic mutex expressions, omitted `mutex_ids` and `**kwargs` remain unverified. Nonempty manual ID sequences may infer depth. A present depth is not proof of a legal positive value, placement, capacity or synchronization; native validation owns those checks. JSON and text reports count checked/unverified declarations. Unknown parser identity never becomes a hard rejection from this rule.

- Tile rank checks only explicit list/tuple lengths, without evaluating expressions, named shapes or `*dims`. It proves neither dimensions, alignment nor capacity. Recognized native import aliases are matched without alias-shadowing analysis.
- VF scope examines directly executed syntax inside recognizable `@pl.jit` functions, traversing conditions/loops/sections but skipping nested functions, classes and lambdas. It does not infer ordinary helpers interprocedurally. Namespace shadowing by JIT parameters/local writes stays unknown; dynamic aliases and module rebinding are not resolved. No finding does not prove helper calls are legal.
- VF runtime-control checks are advisory and do not change gate exit status. They follow conservative local expression dependencies inside recognizable SIMD functions, excluding nested ordinary helpers and SIMT/unknown modes. Factory captures and runtime loop bounds without a conditional body are not reported. Call-site literals, type/path analysis, shadowed aliases and final compiler specialization are not resolved; a finding does not prove that a branch survives or is slow, and no finding does not prove hardware-loop lowering. The tool does not rewrite kernels or schedule their work.
- VF nesting checks direct native import aliases inside recognizable SIMD VF functions; shadowed namespaces and nested ordinary helpers are not inferred. It detects nested call arguments, not every invalid expression or assignment form. The selected parser's content hash is included in findings; unrecognized source never becomes a hard rejection based on a guessed operation list.
- GEMM parameter checks use the same direct-JIT scope and recognize native import aliases plus explicit `compact=` only. They do not expand `**kwargs`, bare imported function names or ordinary helpers; shadowing stays unknown. They neither infer which tiles need compact nor prove other argument combinations. Recheck signatures after framework changes instead of turning version boundaries into permanent hardware rules.
- Scalar annotations recognize known, singly assigned module `DT_*` aliases and bare-name annotations on recognizable JIT parameters. Additional bindings anywhere in the file cause conservative skipping. Alias chains, closures, dynamic rebinding, bare dtype imports, unknown types, return annotations and inline-helper annotations are not inferred. Tensor/Ptr-contained dtypes and named TilingData retain their own semantics.
- Valid-shape tracking covers direct JIT constructors, local aliases and group slots with literal fixed dimensions. Parameters, helper results, nonliteral declarations and control-flow rebinding remain unknown. It does not execute source or classify unknowns as fixed.
- Register-alias analysis tracks common direct VF producers, name aliases, visible loop bodies and each conditional branch separately. It does not propagate between branches and drops changed bindings at joins. Parameters, helpers, unknown APIs and tuples are not inferred. Later reads are review leads, not proof of execution, algorithmic error or liveness. Legal register reuse remains allowed; IR/CCE dataflow inspection is still needed.
- Destination-initialization checks recognize the two named fused updates, direct name assignments and native VF import aliases. The report counts direct FMA assignments checked and visible calls with unclassified forms/namespaces separately from violations. A bare annotation supplies no value. Straight-line statements and each conditional arm are checked in order; branch joins and possible loop-carried value bindings remain unknown. Parameters, helper results, ordinary aliases, complex blocks, dynamic operation aliases and shadowed VF namespaces are not proved initialized or rejected. The rule does not infer register types, mask coverage or every runtime path, and does not inspect ordinary helper bodies; no finding is not an initialization proof.
- Register-dtype checks compare explicit dtypes of `full/arange/astype/bit_cast/pack/unpack` in one sequential block, including common integer/FP16/BF16/FP32 literals, singly assigned module aliases and ordinary aliases. Local/closure dtype bindings, helper returns, implicit result types, tuples and control-flow merges are not inferred. An unknown-source `pack/unpack` chain is not rejected merely for a dtype keyword: overloads can preserve MaskReg identity. Mask granularity, BOOL carriers and low-precision float carriers are outside scope. Unknowns stay unknown; this is not a compiler type system.
- The broadcast advisory tracks direct VF results and their ordinary aliases within one sequential block. Parameters and helper results have unknown kinds, so it asks for review rather than rejecting them; initialized register self-broadcasts remain legal. It does not infer argument kinds through callers, propagate bindings across control-flow joins or inspect helper bodies. No finding proves that a generated broadcast reads initialized storage.
- The narrowing-store advisory uses single-assignment predicate/cast names, explicit or singly bound module dtype aliases, ZERO/default layout and ordinary contiguous/data-block stores. It does not prove the source Tile dtype, propagate data aliases, resolve unknown store distributions or judge intentional raw-container outputs. Explicit packing and a new result from `de_interleave` are outside this suspicious direct chain; their correctness still needs a complete conversion probe.
- The GM-scalar advisory recognizes unrebound 1-D JIT `pl.Tensor` parameters indexed directly by `get_block_idx()` or a row-cyclic `pl.range(get_block_idx(), ..., get_block_num())` variable. It does not infer launches, unique writers, dtype width, base addresses, index arithmetic, aliases/helpers or other ranks. No finding proves safety. Review against the actual toolchain and addresses; verified single-worker uses remain legal. It changes neither exit code nor the allowed GM output layouts.
- The default scan covers all `examples/`; basic_api and matmul writing-style declarations are normalized.
- `auto-mutex-needs-tile-group` does not report declarations, metadata-only uses or recognized single-pipe accesses as races. Its hard proof is limited to adjacent direct `load(tile,...)` / `store(...,tile,...)` statements in one straight-line Vector section, a directly declared Vec Tile, default/explicit True, and matching selected-source roles and pipes. Explicit False stays outside this rule. Helpers, aliases, loops/branches, unresolved decorators or native namespace bindings, manual synchronization and unavailable/changed source guards produce advisories when ordering remains unresolved. Manual events are not automatically accepted as adequate. `coverage.synchronisation` carries source hashes and scope counts; physical aliases, reverse reuse and general synchronization correctness are not proved.
- Overlap compares addresses and explicit IDs per slot in one memory space, excluding explicit `auto_mutex=False`; unevaluable declarations and automatic IDs remain outside coverage. Only direct, non-escaping native accesses in explicit sections can receive a phase advisory: all uses must be strictly separated by unconditional `bar_all` in one core domain. Distinct single core domains receive a handover advisory; equal IDs do not synchronize those cores. Loops, conditional/partial barriers, helpers, aliases and rebinding do not establish phase separation. Findings and advisories require native lifetime review; neither proves an observed race or complete synchronization. The native frontend also warns on manual declaration overlap.
- `init-output-needs-a-drain` follows one same-file helper layer and approximates coexistence of bare tiles and `bar_all`. It proves neither address collision nor barrier order; distant addresses may be false positives and misplaced barriers may escape it.
- Squeeze checks operate within one VF, not across helpers. Complex control flow and unknown modes require report review rather than a safety claim.
- UnalignReg checks count overlapping live ranges, not declarations; five non-overlapping declarations should pass.
- SIMT checks conservatively reject syncthreads under control flow without constant propagation. Compile-time conditions may explicitly declare a counterexample. `threadfence` / `threadfence_block` are not subject to this rule.

Hardware evidence belongs to [VF](../api/vf.md), [SIMT](../api/simt.md) and [validation traps](../diagnostics/validation-traps.md). AST rules do not replace framework parsing, sanitizers or device execution.

API-policy checks follow explicit imports, simple function aliases and annotated `pl.Vf` parameters. Reassigned or shadowed names become unknown; dynamic attribute lookup, containers of callables and cross-file alias/dataflow resolution are outside scope. The report counts resolved VF calls, unverified VF calls and prohibited tile calls. VF membership verifies spelling only: arguments, overloads, result arity and dtype/layout support still require the API contract and a probe. A source checkout must match the installation being targeted; finding a name in a newer local checkout does not verify the remote toolchain.

Allocation-scope checks count direct native allocation calls in recognizable JIT bodies and report unclassified visible calls separately. Rebound/shadowed namespaces and ordinary helper bodies remain unknown; callable aliases, dynamic lookup and cross-file contexts are not resolved. A recognized lexical scope does not prove valid block grammar, allocation size, layout or lifetime. Framework parsing and resource checks remain required.

## Generated API reference

Search [pypto_pro_language.pyi](../api/pypto_pro_language.pyi) for a function, type or enum when choosing arguments. Top-level names represent `pl.<name>`; the `Vf`, `simt`, `system`, `mutex` and `pipeline` classes group their actual public namespaces. Namespace modules are rendered as classes only to make one file searchable. Use the normal native imports in kernels.

The generator follows `pypto_pro.language.__all__` and its source re-exports, retains declared parameters, positional/keyword-only markers, defaults and public class fields/methods, and reads enum member names from the C++ Python bindings. An unresolved export fails generation. `parser` remains a module reference; this file does not inventory parser internals or undeclared parser-only forms. `Any`, missing annotations and IR-builder signatures are preserved as source declarations, without inferring accepted DSL forms or hardware support. Family references and probes own those contracts.

Namespace members can refer to declared names or attributes of literal module/class declarations, such as `SimpleNamespace(mutex_lock=system.mutex_lock)`. Query records and the generated reference share this resolver and retain the target declaration's original path, line and whole-file SHA. Dynamic attribute lookup, calls and unresolved members remain unavailable; no framework code is imported or evaluated.

If an IR `.pyi` contains a malformed top-level block, the resolver may use complete named declarations in the syntactically valid prefix before that block. `knowledge.coverage.api.partial_stubs` exposes the cutoff and original error; the generated reference marks the same scope. It does not repair the broken declaration, enumerate an incomplete namespace, or recover unclosed tokens or invalid executable `.py` files. Public-export coverage can be complete while an unrelated stub suffix remains unparsed; this is not proof that the entire source file is valid or importable.

Regenerate with `api --write-pyi`; never edit the generated file by hand. `api --check-pyi` exits nonzero for a missing, changed or stale reference. Both options cover the whole entry and cannot be combined with namespace filters. The header carries a SHA256 of the ordered paths and contents of the read sources, without machine paths, timestamps or history files. Confirm that the selected checkout matches the target installation before using the snapshot as version-specific guidance:

```bash
python /path/to/pypto-pro-kernel/scripts/check.py --pypto-root /path/to/pypto api --check-pyi
python /path/to/pypto-pro-kernel/scripts/check.py --pypto-root /path/to/pypto api --write-pyi
```

## Counterexample declarations

An intentionally violating example declares this in the owning function's docstring. The Chinese prefix is a preserved machine-readable marker; the explanation may be English:

## Consistency and maintenance

`links` checks local inline Markdown link targets and fragments in Markdown destinations. It recognizes ATX headings, their duplicate suffixes, Unicode heading text and explicit HTML anchors on `a`/heading tags; fenced/indented code, inline code and HTML comments do not supply links or headings. It reports source lines for missing files and anchors, returns 1 for findings or an empty scan, and returns 2 for invalid input paths. Explicit inputs follow the caller's directory; no arguments scans `SKILL.md` and the bundled references. Target directories and non-Markdown files are checked for existence; fragments in those targets are reported as unverified. External URLs are counted but never fetched. Reference-style links, HTML hrefs, setext/generated headings and arbitrary renderer extensions are outside this lightweight check's scope.

Run `links` when editing or moving documentation in a complete workspace; explicit inputs also cover repository documents outside the selected references. The default [knowledge admission gate](#knowledge-admission-and-refresh) checks reference links. `rules`/`run` remain independent: a relocated source-checking skill need not carry every linked framework document, example or ignored environment note. A missing companion file is still a link finding when links are checked; the checker neither invents a replacement root nor treats the absent document as verified. Link integrity does not establish API correctness or agent effectiveness.

`catalog` reconciles the [example catalog](examples.md) with public `kernel.py` directories under `matmul/` and `algorithms/`, including nested examples. Private helper directories are excluded. Each example needs a direct directory or `kernel.py` link in a Markdown selection table; prose, fenced examples and a parent-group link do not replace that entry. Local example links use the catalog's `../../examples/` prefix. Missing entries, missing catalog/groups, empty scans and broken example targets fail the gate. The default command includes catalog and coverage through knowledge admission alongside source `rules`; `rules` and `run` remain source-only gates. This checks discoverability and path consistency, not numerical correctness or hardware performance.

`coverage` consumes the fixed section-8.2 marker in the [example coverage contract](example-coverage.md) and verifies actual calls in assigned examples. `surface` computes its index from source without a checked-in copy. Neither establishes argument-combination or numerical coverage.

`srcrefs` compares Markdown identifiers with text near referenced source lines and can report false positives. Review individually; prefer symbol references. Verified false positives are bound to skill-relative document path, target file and line, so relocation remains valid. Do not replace references with function-definition lines in bulk just to silence the report.

New rules must report both analyzable scope and violation count; zero findings do not mean full coverage. Validate locations and criteria with positive/negative controls and compare against framework checks/sanitizers where semantics overlap. Investigate criterion differences first. Explain unknown-node limitations without executing scanned code or taking over compilation semantics.
