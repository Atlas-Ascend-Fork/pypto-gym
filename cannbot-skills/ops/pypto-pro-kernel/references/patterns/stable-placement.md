# Stable grouping: logical positions and parallel ownership

Use for stable filtering, keyed packing, bucketing and scatter that preserves original record order. Derive each record's deterministic output position before choosing who moves its payload. Stability follows from logical rank; it does not require one worker to process an entire category sequentially.

## Separate reusable metadata from payload execution

Look for a descriptor whose inputs do not depend on the payload channel or tile: a selected row, sample coordinates/weights, a contributor list or retained instruction IDs. Compare deriving it in every consumer with producing a device-side plan once and giving payload consumers a separate grid. Host may select geometry from permitted metadata; tensor-content-dependent plans stay on device. Plan ownership, payload ownership and final writers need separate proofs.

For R uses, screen `T_plan + T_handover + R*T_use` against `R*T_repeat`, including initialization, launches, scratch and publication in the terms that actually execute. A resident descriptor can avoid repeated decoding yet shrink the payload batch, increase waves or serialize its consumers. A small bounded repeated scan can therefore beat a lower-complexity plan. Compare low/high reuse and narrow/wide payloads before choosing a dispatch rule; a fast payload phase alone does not pay for planning.

Count the producers in the actual baseline. A grouped sampler may already hoist coordinates/weights outside its channel loop, leaving G repeated descriptor producers per record rather than C. Selecting another already exposed G is [configuration selection](../workflows/optimization.md#distinguish-family-selection-from-an-implementation-change). A different implementation can instead produce one descriptor per record for payload consumers, either in a separate device stage or in shared on-chip storage. Compare those organizations before assuming the remaining repeated work is unavoidable.

For block-local sharing, one group leader can produce a typed descriptor for its payload lanes. Derive a block-uniform iteration schedule and unconditional producer/consumer barriers, including inactive groups and the final partial group. Protect each slot until every payload reader finishes before reuse; a per-thread loop with unequal iteration counts cannot simply gain a block barrier. Account for descriptor traffic, barriers and live capacity, and verify the actual native handover. A separate global plan changes those costs again. Neither recipe assumes an unverified shuffle primitive or establishes a speedup; the [SIMT lifetime rules](simt-payload.md#keep-a-reused-table-only-within-a-proved-lifetime) own the concrete synchronization choices.

Contributor counts can select different legal work. For an unweighted sum with direct one-term semantics, an empty list needs the prescribed identity, a singleton can copy its contributor and a longer list needs reduction. Weighted expressions, additional output terms, NaN/signed-zero behavior and prescribed rounding can change those routes. Establish list order when the arithmetic requires it. Fully initialize empty outputs and every consumed plan entry, and retain the plan until its last reader finishes. Rebuild value-dependent descriptors from the current call even when addresses and compiled keys are reused.

[Stable dispatch](../../examples/algorithms/stable_expert_dispatch/) provides explicit device interval counts followed by token-owned placement/copy; final positions are still accumulated by each token. [Bilinear sampling](../../examples/algorithms/bilinear_sampling/) provides a record/channel control with per-thread coordinate state. These are concrete starting points for comparing a fuller plan, not implementations of an already shared global sampling table. Use [joint address bounds](../api/vf.md#prove-joint-address-bounds-before-repeated-accesses) for plan capacity and [layout costs](vf-neighborhood.md#compare-layouts-from-actual-access-sets) for the consumer.

## Derive stable positions independently of workers

Partition input into logical intervals ordered by original position. Let `count[g,r]` be the number of valid records of category `g` in interval `r`; local rank counts only earlier records of the same category. For a valid record `i`:

```text
destination(i) = total records in earlier categories
               + same-category records in earlier logical intervals
               + same-category rank of i within this interval
```

These terms establish disjoint output intervals and stable order. Logical interval IDs follow input ranges, not worker IDs, completion order or atomic-counter acquisition order. The device computes runtime categories, valid counts and positions; Host supplies only shapes, layouts and launch parameters. Empty intervals contribute zero, adjacent offsets may be equal for empty categories, and invalid records consume no output position.

Choose count-table layout for its consumer's traversal. With category-major, interval-minor counts, one exclusive prefix over the table contains the first two terms; category boundaries come from corresponding prefix positions. The final boundary is the total valid count: save the total separately or allocate a complete boundary array rather than reading beyond the prefix's logical length. Other layouts require rederiving indices and scan axes. Budget count/rank/intermediate-map storage and scanning work; count dtype must hold the total, and oversized tables need hierarchical or streaming treatment.

One worker per category scanning the whole input is a valid simple baseline, but count its repeated `category_count × input_length` work and utilization under few or concentrated categories. More launch workers cannot split a long task already assigned to one owner. Interval counts and prefix positions allow several workers to process different input ranges of one category while preserving order; that choice is independent of payload group width.

Once positions are known, assign movement by input record, output record or contiguous payload block. Compare [SIMT metadata reuse and contiguous access](simt-payload.md), avoiding both per-element rank recomputation and serializing an entire category onto one block just to reuse metadata. Prove unique writers, disjoint intervals and producer completion before consumption separately; native-kernel stages on one Stream can express those dependencies.

Build loop bounds directly from the valid range. If only a tail needs filling, traversing the entire output with a tail predicate retains idle work; multiple owners can cover the known tail interval directly. Fully define compact outputs, inverse maps and invalid records too; correctness cannot depend on old caller values. Test empty sets, one category, interleaved categories, interval boundaries, non-divisible interval counts, multiple workers, repeated calls and guards. Performance comparisons also retain concentrated and dispersed distributions.

Runnable two-stage reference: [stable_expert_dispatch](../../examples/algorithms/stable_expert_dispatch/). It computes interval counts explicitly, then token owners accumulate earlier intervals and copy payloads. This is an inspectable correctness starting point, not an optimal count/prefix/movement schedule. Independent stable-sort tests cover empty categories, tails, inverse maps, special FP32 bit patterns, offset outputs and repeated calls.
