# PyPTO-Pro 算子产物规范

本规范负责 PyPTO-Pro 算子的 Python/JIT 源码产物组织与文档，是可关闭、可替换的默认整理策略。选择顺序为“用户明确要求 > 项目交付规则 > 默认策略”。用户或项目规则关闭整理时，保留现有产物组织；指定替代规范时，按所选规范处理目录、命名、接口包装和文档，不叠加本规范的格式要求。仅当选择本规范时，才执行下文的目录、固定命名、三份文档及标题等约定。

三种策略均不得改变算子语义、降低已有功能、精度和性能验收要求；最终公开入口仍须验证，整理影响实现、调用路径或性能时复验受影响项。已确定的精度契约和性能方案保持不变；未约定的项目才采用本规范的默认值。

CANN 离线编译、注册、安装和 ACLNN/GEIR 验收由独立的 `pypto-pro-cann-delivery` 负责，不强制先转换为本规范的源码包布局。两个 skill 按交付目标使用，安装本规范不代表必须执行整理。

## 适用范围与算子契约

算子契约应明确输入参数及默认值、计算公式、数据类型、布局与 stride、数值转换规则、输出形式，以及原地写入和别名关系。支持范围以实现和测试共同验证的结果为准；指定参考实现时，输入、计算和输出语义应与其一致。

新算子按已确认的契约组织实现、独立 golden 和测试用例。整理已有算子时，保留原入口的功能、精度和性能基线，以便验证目录与接口调整后的结果。默认命名与既有公开接口不同时，通过兼容入口或薄包装保留原调用方式、参数及默认值，不因整理破坏已有接口契约。

正式用例采用指定的验收集合；未指定时采用算子的默认性能用例，并保留其他必需验收。两者均未定义时，先依据算子契约确定覆盖适用功能与边界的非空用例集。开发试验不进入正式用例集合。代表用例按尺寸、dtype、布局、步长、边界及算法分支选择，展示子集不替代完整验收。

## 目录结构与代码职责

选择本规范时，算子目录优先采用用户指定位置，其次采用项目交付规则指定的位置；均未指定时，在用户工作目录下创建 `custom/<op_name>/`。以下目录、文件与入口命名用于本规范的源码交付，关闭整理或选择替代规范时不要求迁移到此结构。

```text
<op_name>/
├── README.md
├── DESIGN.md
├── RESULTS.md
├── op_kernel/
│   └── <op_name>.py
└── tests/
    ├── test_<op_name>.py
    └── assets/
        └── gen_golden.py
```

- **kernel 与 host 入口。** 两个入口均定义在 `op_kernel/<op_name>.py`。kernel 入口 `<op_name>_kernel` 执行设备侧计算。host 入口 `<op_name>` 是算子的公开接口，显式列出契约规定的参数及默认值，完成必要的输入检查与准备后调用 kernel。
- **独立参考计算。** `tests/assets/gen_golden.py` 负责构造输入，并依据算子契约独立计算期望输出。
- **精度校验。** 校验标准和文件位置以用户要求为准。未指定标准时，采用本规范提供的[默认精度标准](references/precision_compare.py)。未指定位置时，将所选校验实现单独放在 `tests/assets/<op_name>_precision.py`。
- **测试。** 每个用例对应一个具名 `test_<case>()` 函数。`main()` 按顺序显式调用这些函数，测试文件同时支持直接运行和 pytest。各测试可共享用例数据和 `_run_case`，通过公开 host 入口 `<op_name>` 比较全部约定输出，并按契约检查 shape、dtype、stride、返回对象关系和原地写入范围。
- **代码质量。** 函数职责清晰，保留必要的边界检查、同步和关键逻辑说明。使用可移植的导入路径，移除重复实现、无效入口和临时调试内容，遵循仓库的许可、版权、格式和日志规范。

## 功能、精度与性能验证

在最终目录及支持的 NPU 环境中，直接运行测试文件并通过 pytest 运行正式用例。逐例核对两种方式实际执行的用例标识、输入配置和结果。所有约定输出均须与独立 golden 对照，按所选精度标准校验。校验失败应使测试失败，跳过或预期失败的用例不计为通过。

性能采集和验证按用户指定的方案执行。未指定方案时，默认使用 CANN 官方 `msprof` 采集算子性能，推荐在采集前清理 L2 缓存。在 `RESULTS.md` 中记录实际采用的方法、测试条件与逐例结果。整理已有算子时，按相同口径与原有基线对照，确认性能持平或改善。

依据仓库实际规则完成 CodeCheck 检查及修正，保持测试覆盖和校验要求。正式产物仅保留必要代码与文档，原始性能采集数据、缓存、二进制和开发试验存放于产物目录之外。

## 文档结构与内容

选择本规范时，提供下列三份文档，每份保留一个算子名称一级标题，二、三级标题名称、顺序及归属严格如下；细节使用对应章节内的段落、列表或表格表达，不增删或重组标题。关闭整理时不因此补建文档；选择替代规范时仅采用所选格式。

**README.md**

```markdown
# <算子名>（PyPTO-Pro）
## 产品支持情况
## 功能说明
## 函数原型
### 参数说明
### 返回值说明
## 约束说明
## 调用示例
```

列出已验证的产品与支持范围，说明公式、数值规则和公开 host 函数 `<op_name>` 的完整原型。张量说明 shape、维度含义、dtype、布局和 stride，标量与属性说明类型、含义和取值。按契约标注单位、默认值、原地写入或返回别名。约束与实现一致，调用示例从 `op_kernel.<op_name>` 导入并调用 `<op_name>`。

**DESIGN.md**

```markdown
# <算子名> 设计说明
## 计算阶段划分
## 核间切分策略
## 核内切分策略、基本块选择与核内 Buffer 划分
## 接口选择
## 流水设计
```

说明各计算阶段、核间分工、核内基本块与尾块处理、Buffer 用途与容量及复用方式、接口选择理由，以及数据搬运、计算、写回和同步依赖。调度与依赖以最终实现为依据，涉及实际耗时或重叠的判断以对应的实测数据为依据。

**RESULTS.md**

```markdown
# <算子名> 结果说明
## 用例
## 精度标准
## 性能结果
### 绝对性能结果
### 理论评估对比
```

用例与测试一一对应，标明实际采用的精度标准。绝对性能列出逐例实测结果、单位、平台、版本和统计口径。理论评估按需选取适用指标，说明其含义和计算依据，区分实测结果、理论估算与瓶颈判断。

文档面向掌握基础算子术语的 gym 用户，说明稳定接口、使用条件、实现设计与验证结果。逐项依据源码、测试记录或官方资料核对事实与数据，解释必要术语，使用适用于目标平台的通用调用示例。

正式算子产物（含代码注释、测试及三份文档）只描述本 PyPTO-Pro 算子的契约与实现，保留必要的许可声明、实际运行与 golden 依赖，以及测量工具和数据依据。其他 kernel 框架的名称、实现描述和对比数据不进入正式产物。

## 提交说明与验收要求

本节的提交格式和三份文档要求仅在选择本规范时生效。关闭或替换整理后，仍须满足原有技术验收和仓库质量要求，不能以缺少本规范的目录、命名或标题阻止交付。

PR 说明按目的分项交代修改位置、做法和原因，覆盖最终差异，并给出算子功能、支持范围和验证结果。性能表每个 case 的完整配置写在同一行，以有语义的独立参数表示，例如 `B=4, Sq=1024, dtype=BF16, stride=...`。保留必要的输入、输出与索引 dtype、布局、stride 及属性，表前解释每个参数的意义和单位；不整体粘贴 `x_shape=(...)` 等张量 shape。README 的接口说明仍须给出完整张量形状。

明确要求参考实现对比时，PR 性能表使用四列：`用例及全部参数 | 参考实现耗时（μs） | PyPTO-Pro 本算子耗时（μs） | 性能占比`，其中 **性能占比 = 参考实现耗时 / 本算子耗时**。参考实现使用实际名称，两方数据采用一致条件和同种统计量；对比仅用于 PR 说明，不进入正式算子产物。未要求对比时列出本算子实测数据。

选择本规范时，目录、命名与引用正确，接口和计算符合契约，全部正式用例精度与最终性能达标，三份文档核验及仓库质量检查通过，方可验收。

按任务已有授权及仓库流程，使用指定身份发布并核对远端提交、文件和说明。需要 Issue 时按仓库模板创建或复用，核实正式关联。按授权发表评论或触发 CI，分别说明本地验证结果和最终提交（或其预合并提交）的 CI 状态。
