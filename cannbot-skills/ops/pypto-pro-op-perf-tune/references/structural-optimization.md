# PyPTO-Pro 结构性优化重审与可达目标取证

本页规范结构受限 kernel 的重设计：强制重审范围、可达结构取证、逐维判定与关闭要求、可达目标
推导，以及“地板/上限”结论的适用范围。调优主流程在建立 baseline 后的账本建立阶段按 §1 判定是否
命中并引入来源 `structural`，于主 Skill §3.5 闭合该来源后才进入 `bottleneck_derived`。

## 1. 强制重审范围

满足任一条件时，重审**无条件执行**，不得以“未测到触发特征”“当前设计已冻结”或“无收益”为由跳过：

- 用户给出明确数值性能目标；
- 交付 kernel 为自研实现，尚未对齐任何已验证参考的性能；
- op_summary 各 pipe 利用率均低、无 dominant bound，或活跃核显著少于物理核。

其余情形按以下诊断特征触发：

- 关键路径由同步或依赖等待主导，等待占比高于任一计算 pipe 的忙比；
- 同一算子由大量小 shape 收缩构成，固定开销（搬运发射、流水填充/排空、屏障往返）主导耗时；
- 预置来源全部闭合后，当前实现与 §4 的可达目标仍存在数量级差距。

## 2. 可达结构取证（必做）

重审前先取证，形成“最佳已知结构”，作为设计与收敛锚点：

1. 检索工作区、算子所在仓与其测试套件中的同算子/同拓扑实现、指南与样例；
2. 检索已装配的 Pro 官方样例缓存（`pro_ops/`、
   [样例索引](../../pypto-pro-material-explore/references/official_samples.md)）与
   [知识卡片库](knowledge-cards/index.md)的既有实现线索；
3. 记录候选实现的结构要点（操作数数值类型、片上驻留、工作分解、同步模型、计算图等价改写、阶段划分）与实测性能，
   注明来源与测量条件；
4. 无可复现实测性能时，按 §4 由算量 roofline 推下界。

取证结论记入性能报告。存在已验证的更快结构时，**对齐其结构为首要候选**，优先于对现有结构的
微调；未对齐前不得以“本结构已到极限”停止。

## 3. 结构维度判定与关闭

按顺序逐维度给出“当前取值 → 候选取值 → 精度/合规影响 → 预期收益”，作为账本 `structural` 条目。
候选涉及精度或 kernel 契约时，先按主 Skill §2 的**约束分栏审计**区分验收硬门与自述约束：只有验收
硬门为冻结边界；被自述约束阻断的候选须作为合同变更候选提交用户，不得据此关闭维度。

| 维度 | 判定内容 |
|---|---|
| 操作数数值类型 | cube 收缩操作数能否由 FP32 降为 bf16 或 FP16，且保持 FP32 累加（对应 `cube-09`，限定串行 matmul 链场景；Vector 侧操作数降精度当前无对应知识卡片，按 §2 取证与能力门控另行判定） |
| 片上驻留 | 循环/递推状态与跨迭代中间量能否常驻 UB 或 L1，消除 GM 往返 |
| 工作分解 | 独立工作项能否按（工作项， 头/分片）两维展平并铺满全部 AI Core |
| 计算图等价改写 | 关键路径上的逐元素或超越函数操作，能否在不改变数学结果的前提下，经数学等价改写为开销更低的单元操作（如门控加权收缩改写为 GEMM、消去重复超越函数），从而转移其工作与依赖 |

“计算图等价改写”属算法层维度，收益通常高于前四类同结构微调。采用前须核对 `SPEC` 精度门与支持
范围，分解引入的舍入为主要风险；改法、适用边界与案例见知识卡片 `algo-01`。

维度关闭只有两种合法方式：

- **实现并实测**：完成完整正确性、quick、必要时 formal compare 与机制核对；
- **可复现的能力/契约阻断**：给出最小复现（源码位置、生成物或文档依据、复现命令），证明该维度在
  当前工具链与合同下不可用。

“不适用”“收益有限”“profiler 未呈现”“能力缺口（无最小复现）”均不构成关闭依据。**机制类**维度
（尤其计算图等价改写）首次实测为负时，须迭代实现变体后再结论，不得以单次负结果关闭；放宽精度门
或目标范围属合同变更，须独立向用户确认。四类维度对应知识卡片 `cube-09`、`mem-06`、`pipe-06`、
`algo-01`，逐卡通读后按主 Skill §3.3 判定。

## 4. 可达目标推导

优先取 §2 取证得到的最佳已知实测性能为可达目标 `T_best`；无实测时按算量 roofline 推下界：

```
T_lb ≈ 总计算量 / (AI Core 数 × 单核峰值 × 目标效率)
```

- 总计算量按主 bound 单元的整量计（如 cube 的 MAC 数）；
- 目标效率取同类在目标设备的实测可达比例并注明来源；
- 乘上目标效率（<1）后的 `T_lb` 是工程估计目标而非严格数学下界；严格下界对应目标效率取 1，
  报告中引用时须注明所取效率与来源；
- `T_best`/`T_lb` 记入性能报告作为收敛锚点；不得以“Golden unavailable”免除此推导。

## 5. “地板/上限”结论的适用范围

在冻结结构上测得的耗时只界定该结构，不界定问题本身。报告“地板/上限/已到极限”时必须标注适用
范围，并给出与 `T_best`/`T_lb` 的比值。命中 §1 强制或触发条件时，冻结结构上的地板结论不成立，
须先完成 §2–§4。

## 6. 与主流程的衔接

- 来源 id：`structural`，位于主 Skill §3.5，先于 `bottleneck_derived` 闭合；
- §2 的最佳已知结构实现与 §3 的每个维度各形成一个原子项，按受控闭环执行；
- 维度候选涉及精度或契约时，按 [Design Skill](../../pypto-pro-op-design/SKILL.md) 与
  [KB 合同](../../pypto-pro-op-kb/CONTRACT.md) 同步最终事实记录。
