# 示例

以下示例用于说明编辑决策，不代表示例用词已通过规范词典认证。

## 说明原因，不重复实验历史

改写前：“采用第二版 tiling 方案后，Cube 利用率终于正常了。”

改写后：“原方案为每个小矩阵单独启动 Cube 计算。新方案将独立小矩阵合并到一个批次，减少了 Cube 的空闲周期。”

原则：删除版本和评审历史，直接说明性能根因与改动机制。

## 保留适用条件

改写前：“增大 tile 可以提高所有 shape 的性能。”

证据：测试只覆盖 K 维是 128 整数倍的 shape，且增大后的 tile 未超过 L1 容量。

改写后：“当 K 维是 128 的整数倍且 tile 未超过 L1 容量时，增大 tile 降低了实测耗时。测试未覆盖其他 shape。”

原则：将测试条件写进结论，不把局部结果推广到未测试范围。

## 保留测量范围

改写前：“算子性能提高了 30%。”

证据：msprof 只显示目标 Cube kernel 的耗时减少了 30%，未测量 wrapper 和辅助 kernel。

改写后：“在本次测试中，目标 Cube kernel 的耗时减少了 30%。测试未测量 wrapper 和辅助 kernel。”

原则：结论使用与证据相同的计时范围。

## 说明因果关系

改写前：“新的分段方案充分释放了多核并行能力。”

改写后：“每个 AI Core 先计算一个独立分段的状态摘要。系统再按时间顺序恢复各段入口状态。摘要计算可以并行，状态恢复仍有段间依赖。”

原则：写出条件、机制和结果之间的因果链。

## 保留不确定性

改写前：“更换 NPU 后解决了 kernel 运行失败。”

证据：更换 NPU 后测试通过，但现有日志不能确定原 NPU 的失败原因。

改写后：“更换 NPU 后，kernel 测试通过。现有证据不能确定原 NPU 的失败原因。”

原则：分别陈述观察结果和仍未确定的原因。
